## 0. 一句话

这份方案只回答"**怎么证明算法说的是真的**"：先证明**标注本身可信**（§1），再证明
**同一输入稳定、真实变化能看见、中断不假装连续**（§2），然后证明**门槛是事先冻结的**（§3），
最后用**负向断言**把"缺测补成实测、失败写成 0、丢样本不明说"这几类假数据挡在门外（§4）。

## 1. 标注质检：小批双人独立标注的一致性抽检

**设计原则（三条）**：
1. **独立性**：甲/乙两名标注者**各自完成、比对前互不可见**；**我不担任任何一方**（我是出判据与算一致率的一方，
   避免"既执行又验证"）；
2. **先比对、后仲裁**：分歧不靠"再聊一次"消化——进入**第三人仲裁**并留案；系统性问题**停线改规范**；
3. **零样本 ≠ 通过**：某类案件（例如菌帽未分化阶段）没有样本时，记 **`no_sample`**，
   不得写"通过"（对齐 plan §9.2"未分化不解锁帽径"）。

**抽检批次（小批）**：按 **层 × 生长阶段 × 案件类型** 分层抽样，**≥12 帧 / ≥40 袋实例 / ≥20 帽实例**
（帽实例不足则帽项记 `no_sample`）；案件类型必须覆盖：清晰、遮挡、粘连、跨袋歧义、袋顶被遮、低对比/反光。

| # | 抽检项（plan 出处） | 一致性判据（指标 + 判定规则） | 候选阈值（**待开发集冻结**，见 §3） | 不合格处置 |
| --- | --- | --- | --- | --- |
| A1 | **一袋一簇归属**（§5.5、§7.3：`bag_group_id`/`association_valid`） | 逐袋比对"袋↔簇"配对：**配对一致率**（同袋同簇）+ 歧义案件**逐案一致**；歧义率单独报 | 配对一致率 ≥ 0.90；歧义案件一致率 = 1.00（必须逐案一致） | 单案 ⇒ 第三人仲裁 + 回填；某类系统不一致 ⇒ **停线**、回改 §7.3 归属提示词（cues）与标注规范 |
| A2 | **菌簇顶部轮廓**（§5.2 一袋一实例掩码、§8.1 `t(x)`） | 掩码 **IoU**（中位 + 第 5 百分位）+ **顶部轮廓横向覆盖**；"内部背景是否填满"单列检查（plan 要求不填满） | IoU 中位 ≥ 0.85、p05 ≥ 0.70；覆盖 ≥ 0.90 的列 | 单案仲裁；若"填满内部"系统性出现 ⇒ 停线重训规范（这是量测偏差源） |
| A3 | **袋顶基线**（§5.2 折线 + `baseline_valid`、§8.3） | 折线**逐点平均偏差**（px）+ 两标注各点差 **p90** + `baseline_valid` 一致率；"不可见不猜"逐案核对 | 平均偏差 ≤ 3 px、p90 ≤ 6 px；`baseline_valid` 一致率 ≥ 0.95 | 一致率不达标 ⇒ 停线：先明确"哪一段算可见"；单案仲裁 |
| A4 | **菌帽身份与测量资格**（§5.3 `cap_state`、§9.2 资格） | `cap_state`（clear/not_clearly_formed/indeterminate）一致率 + `measurement_valid` 一致率 + 拒绝原因分布 | 两项一致率 ≥ 0.90；`not_clearly_formed`/`indeterminate` **不许混为一类**（混了即不合格） | 系统性混淆 ⇒ 停线改规范；**帽阶段零样本 ⇒ 记 `no_sample`，不通过** |

**一致率之外的必报项**：每项都要报**有效率/歧义率**（对齐 §14.1"同时报告误差与有效率"），
并按**层 / 阶段 / 质量类别**分组；只给总体一个数不算交付。

## 2. 三类必要测试的验证件设计（§14.2）

### 2.1 静态重复：不应产生虚假增长

| 项 | 内容 |
| --- | --- |
| 样本 | 现役一轮里抽 **≥6 帧**（不同层/锚点）；每帧**同输入同版本重复跑 ≥3 次**；另取"同一物理位置连续 2 个观测"组成**静态序列**（≥3 个锚点） |
| 判据 | ① **确定性**：同输入重复跑，袋级结果**逐字段相等**（掩码 IoU=1、基线与指标完全相同）；② 静态序列的 `mean_profile_height_px` 变化落在**重复性带**内（带＝同一帧 3 次运行的分位距，**冻结**）；③ **不得出现虚假持续增长**：连续 ≥3 点同向且超带 ⇒ 红 |
| 期望输出 | `repeat_report`：每帧每次运行的差异字段清单（空=一致）+ 静态序列斜率与其置信区间 + 是否越带 |
| 自证 | 人为给同一输入加随机种子/抖动 ⇒ ① 必须红；把重复性带放宽到 ∞ ⇒ ③ 必须红 |

### 2.2 真实变化：人工对照图与曲线方向一致

| 项 | 内容 |
| --- | --- |
| 样本 | **≥5 个锚点**，每个取**两个时点**（间隔 ≥1 天；**避开加湿段**；同一 `pipeline_version`/`roi_version`），共 ≥10 对 |
| 判据 | 人工先给"哪个时点更高"的**顺序**（由不参与算法的人判读，**先排序、后跑算法**，防"看着结果排序"）⇒ 曲线方向与人工顺序一致 |
| 期望输出 | `direction_table`：锚点、两时点原始帧 ID、人工序、算法序、一致/不一致、变化量与重复性带的关系 |
| 通过线 | 方向一致率 ≥ 冻结阈值（候选：10 对里 ≥9 对，允许 1 例反例但**必须逐例复核并写原因**） |
| 自证 | 把时间轴反向 ⇒ 方向应整体翻号（用例必须红）；把两个时点对调仍判"一致" ⇒ 说明比较没接上 |

### 2.3 中断事件：换包 / 缺图 / 偏移 / 模型升级**不错误连续**（§11.2）

| 事件 | 样本（每类 ≥2 例，共 ≥8 例） | 判据 | 期望输出 |
| --- | --- | --- | --- |
| 换包 | 跨 `entry_date` 的真实相邻两轮 | 序列**切段**；跨段**无速率点**；事件点有 `replacement` 标记 | 分段清单 + 段内点数 |
| 缺图 | 实际存在的轮次缺口（≥2 轮间隔） | 缺测记为 **NULL/`missing(reason)`**，**不插值**；不跨缺口算速率 | 缺口清单 + 两侧段号 |
| 偏移 | 对齐失败/被拒帧 | 该帧产 `registration` 失败原因，不进入曲线 | 失败原因分布 |
| 模型升级 | `pipeline_version` 变化 | 序列按版本**切段**；旧段不续接新段 | 版本分段清单 |

* **允许合成注入**（在时间序列里插入事件标记）但**必须标明是注入**，且与真实事件分开报。
* **自证**：把分段规则关掉 ⇒ 用例必须红；把缺测的 NULL 换成插值 ⇒ 用例必须红。

## 3. 门槛冻结流程（可执行步骤：谁冻结、记在哪、怎么防"看着测试结果调"）

| 步 | 谁 | 做什么 | 证据落地 |
| --- | --- | --- | --- |
| 1 | 算法 | **只看开发集**做分析，产出"门槛提案"（指标 + 数值 + 理由 + 开发集分布） | 提案进 `docs/patrol/growth-algo/thresholds-<date>.md`（**归算法**；我不写那份） |
| 2 | 测试（我） | **核可**：检查①提案里每个数有开发集出处；②没有任何数来自 locked test；③代码里**没有第二处**硬编码阈值（只有引用） | 我的核可记录（票/Comments） |
| 3 | Chief | **批准并冻结**：门槛文件定稿，记 **git 提交哈希 + 冻结时间戳** | 冻结提交本身即证据 |
| 4 | 算法 | **冻结之后**才运行 locked test（保管人只能是算法一人，见 §5 待裁） | locked test 运行记录（时间 > 冻结提交时间） |
| 5 | 测试（我） | 复验**时序**：`locked_test_run_time > freeze_commit_time`；代码内无第二处阈值常数 | 复验报告 |
| 6 | 全体 | locked test 结果**只报告、不回调门槛**；确有必须改 ⇒ **开新版**（新提案 → 新冻结 → 新 locked test 编号），旧结论**保留** | 版本号 + 两个冻结记录并存 |

**防"看着测试结果调"的三道闸**：① 时序（冻结提交早于 locked test 运行，可机检）；
② 单一来源（阈值只从冻结文件读，代码里不得出现第二个常数——沿用我票 13/16 的"单一尺度"做法）；
③ **改门槛必须换版本号**，且旧版本结论不撤（谁想改，都要留痕）。

## 4. 负向断言清单（每条都要"改坏了它会红"）

| # | 断言 | 正向判据 | **自证（改坏 ⇒ 红）** |

| N1 | **缺测不补成实测值**（§11.2） | 缺测点 = NULL/`missing(reason)`；序列里既有 NULL 也有真实值 | 打开插值/前值填充 ⇒ 红 |

| N3 | **输入数 = 成功数 + 失败数 + 跳过数**（§12.2） | 每个聚合层（锚点/层/整轮）平账；差值恒为 0 | 漏计一类（如跳过）⇒ 红 |
| N4 | **一袋失败不清空其他可靠袋**（§12.2） | 某袋 `invalid_pair` 时，其他袋指标与曲线仍在（panel 覆盖率下降但不清零） | 把单袋异常改成"整锚点缺失" ⇒ 红 |
| N5 | **后排不参与量测，但必须说明训练处理方式**（§7.2） | 量测侧：前排 ROI 外对象不产袋级结果；训练侧：提交"后排处理说明"（明确**忽略区** vs 负类），不得当背景无意使用 | 关掉前排过滤 ⇒ 后排进入量测 ⇒ 红；训练说明缺失 ⇒ 门禁红 |
| N6（附加） | **像素值不写进毫米列**（§12.2、§10） | 未满足 §10 的 mm 解锁条件时，mm 列恒 NULL，像素列另放 | 把 px 值写进 mm 列 ⇒ 红 |
| N7（附加） | **检测失败与尺度失败分开**（§12.2） | 两个失败原因各自计数、不合并 | 合并成一个 `failed` ⇒ 红 |

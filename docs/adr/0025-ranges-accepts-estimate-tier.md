# ADR-0025：区间表接纳「估算」档的边界

日期：2026-10-15
状态：建议（用户 2026-10-15 已裁定；待后端与算法两侧复核落地）
相关：**ADR-0024（测量标定与四量的权威口径——本 ADR 修正其"区间表只吃 verified"一句）**、
`docs/patrol/env-baseline/spec.md`、`docs/patrol/growth-algo/spec.md`、
`docs/patrol/next-plan-2026-10-15.md`

## 背景

ADR-0024 定下一条硬规则：**区间表与决策层只吃 `verified` 行**，理由是"没有真值之前，任何精确数字都是假的"。
这条规则在当时是对的，但它带来一个没人预料到的后果：**`measurements` 长期 0 行**，于是区间表长期只能出
`state=no_measurements`——**为了不放假数，连真数的位置也一起空着**，学习价值为零。

同时，口径本身早已承认第三种状态：**估算（estimate）**——有可用的帧内标尺、值可能有用、但**未经精度验证**。
也就是说，"估算"不是新概念，只是**一直没有消费者敢接它**。

而算法侧的主交付已改为**像素口径**（簇级生长趋势），`verified` 的产生路径仍然遥远
（需要模板 → 标注 → 模型 → 抽样验收四道门）。若不改这条规则，区间表还要空很久。

## 决定

1. **区间表可以纳入估算档**，但必须**整维标注「估算（未验证）」**，并用**独立状态**表达（如「仅估算」），
   **不得与正常态混写**。
2. 同一个分箱里，**估算行与已验证行不得混算**：计数与统计分开呈现。
3. **建议层永不消费估算行**。这是原铁律真正要保护的地方——调控建议不能建立在未验证的输入上。
4. 本 ADR **不改变** `verified` 的技术含义：它仍是唯一能进建议层的标记；本 ADR 只放宽"区间表"这一个消费者。
5. **估算行永久保留**：真指标落地后按版本分界**写新行、不覆盖旧行**，估算行与其证据列始终可查。

## 后果

- 区间表**立刻**可以有非零样本（含长势维），空态从"没数据"变成"有数据但标着未验证"。
- **页面必须让人一眼看出这是估算**。否则会重演"看着像真的假数"——这正是 ADR-0024 当初要防的事；
  本 ADR 用"标注 + 独立态 + 不混算 + 不进建议层"四条来替代"一律不收"。
- 读 ADR-0024 的人**必须同时读本文件**，否则会以为代码写错了。
- 建议层的输入需要一条**断言**：输入集合里不含估算行（改坏了要能红）。
- 将来 `verified` 行充足时，估算档**可以**被降权或默认隐藏，但**不删除**。

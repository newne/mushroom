# 04. 单节点放大：双刻度时间轴 + 环境带叠加

Status: implemented（2026-10-16；验收五条逐条核过，见 §4）
归属：前端（**后端一个字没改**，理由见 §4.1）
依据：[docs/patrol/growth-timeline/spec.md](spec.md)
依赖：03（同文件）

## 交付物

点总览任一格 ⇒ 进入该节点的放大视图：

1. **双刻度时间轴**：真实时间（主）＋ **生长第 N 天**（次；`day` 由本批入库日派生，端点已给）
2. **环境带**叠加：温度 / 湿度 / CO₂，以及**光照循环制度**
3. **巡检覆盖条**：该站位每轮有没有帧
4. 缺测段**断开**；悬停给出该点信息

## 验收（缺一条不算过）

- [x] x 轴按**真实时间戳**定位（换成等距下标 ⇒ 断言变红）
      —— 整张放大图只有**一套** x 比例 `mdScale(axis.t0, axis.t1)`（窗口 = 端点给的 `axis`，
      与前三张卡同源）；覆盖率点、天数边界、环境小时点、光照段起点**共用**它。两条断言钉住：
      ① 把 95 个图元（5 覆盖点 + 3 午夜边界 + 84 环境点 + 3 制度段）两两拟合到**同一个线性映射**，
      偏轴 > 0.6px 即红；② 第 6/7 天的午夜边界必须落在 `09-10 18:00 → 09-11 10:00` 之间
      **真实比例的 6/16** 处。改成"按轮次下标等距"（副本实测）⇒ **2 条红**（§4.4）
- [x] 生长天数刻度与真实时间刻度**同一条轴**且对齐正确
      —— `day` **只用端点给的值**（`rounds[].day`；入库当天 = 第 0 天），页面不自己算、也不猜；
      带的两端是**真实午夜**（`line.md-dayline[data-ts]`），带宽 = 真实时长。断言（全部对着 fixture
      手写常量，不从页面读）：4 条带 `data-day` = 6/7/8/9、`第 N 天` 逐字相等、3 条边界 =
      `09-11/12/13T00:00:00`、**带宽比** `第7天/第6天 = 24h/18h = 4/3`（按天数等分就成了 1:1 ⇒ 红）、
      `day=null` ⇒ 一条带都不画
- [x] 光照按**循环制度切段**显示，**不得**用 `Running` 积分冒充点亮时长
      —— `lampRegimeOf()` 的键**只有** `(lamp_on_m, lamp_off_m)`；`lamp_state`（设备状态：
      0=自动 1=手动 2=停止 3=关闭）**不参与切段、也不被积分**。fixture 让 `lamp_state` 逐小时在
      2/3 之间跳（**同一段制度里照样跳**），断言"段数仍是 3"——拿设备状态切段会得到 **84 段**
      （副本实测 **+5 条红**，§4.4）；层上的文案也说的是设定周期，不出现"点亮 N 分钟"
- [x] 缺测段断开；两点之间若无中间轮次**不许直连**
      —— 覆盖轨迹按"有帧的连续轮次"分段（S102 在 09-12 那一轮没有帧 ⇒ **3 点 + 2 点两段**，
      连起来 ⇒ 红）；环境三条泳道按**小时相邻**断开（`t - prevMs !== 3600000` 即断）——
      **只判"值是不是 null"不够**：断档那一小时可能整行都不在应答里（本票就是被这条抓出来的，§4.3）；
      光照段同理（缺测的小时 ⇒ 段在那里结束，不跨过去接）
- [x] 零新前端依赖
      —— 整张图是**手写内联 SVG**（`mdSvgMarkup()` 拼字符串，与前三张卡同一手法）；断言：
      页面里 `script[src]` / `link[rel=stylesheet]` 数为 0，`#nodedetail` 里没有 canvas/iframe/img

## 不做什么

- 不做跨批同期叠加（env-analysis 票 23）
- 不做按生长天数的分布（env-analysis 票 24）

## 4. 实施与证据

### 4.1 后端：一个字没改（为什么）

票 02/03 的 `/timeline` 已经给全了这一屏要的东西：`axis.t0/t1`（真实时间窗口）、
`rounds[].day`（生长天数）、`nodes[].points[i]`（逐轮 `has_frame`/`n_frames`）、`batch`、`notes`；
环境那一路复用既有的 `/api/environment`（小时行里本来就有 `lamp_on_m`/`lamp_off_m`/`lamp_state`，
见 `analysis/environment.py:FIELDS`）。所以本票**没有**把环境塞进 `/timeline`（那会把响应撑肥，
正是 spec 与票面都点名的"不要为了'一次拿回'把它撑肥"），也没有新增端点 —— `analysis/**` 一行未动
⇒ 后端套件**不跑**（票面口径：只有改了 `analysis/**` 才跑）；PG / TDengine 全程没碰。

**两个资源、不是 N+1**：

- 逐轮格点**不再请求**：点一格用的是票 03 已经**一次**拿回的**本批矩阵**（`hist.overview`）——
  "一次拿回全部站位"这个设计就是为这一刻准备的（再按站位去问就退回了 N 次请求）；
- 环境按**本批窗口一次**：`/api/environment?zone=…&granularity=hour&start=<t0>&end=<t1>`，
  幂等键 = `批次|t0|t1` —— 环境是**批次**的属性，换站不重问；
- **失败不缓存**：取不到时如实说（`⚠ 环境取不到：…`），但**不落成功 key**：用户再点一格
  （明确动作）会重试，不会被钉成永久空白；而自动刷新（换轮次 / 筛选 / 矩阵后到）**不会**反复去问
  同一个失败的窗口（`nodeEnvFailedKey`）。

### 4.2 页面（`web/console/index.html`）

- **入口**：`#overview` 里每个有站位的格子（含"本批没有记录"的灰格；空位 `vacant` 不绑）
  `onclick = openNodeDetail(id)`。点开同时把这一站变成本 tab 的**聚焦站位**（拼图 / 覆盖轨迹 /
  生长曲线说的是同一个站，不另立一套选择状态），卡片 `#mdcard` 由收起变展开并 `scrollIntoView`。
- **画法**（`MD` 常量表 + 一组纯函数）：`mdScale()`（**唯一**的 x 映射）、`mdDayBands()`（天数带）、
  `mdEnvLaneSvg()`（温/湿/CO₂ 三条泳道）、`lampRegimeOf()`/`mdLampSegments()`/`mdLampSvg()`（制度切段）、
  `mdCoverageSvg()`（帧数轨迹 + 一格一轮的覆盖条）、`mdSvgMarkup()` 装配。
- **布局**（`viewBox 920×284`，自上而下）：**生长天数带**（次刻度，落在真实午夜上）→ 三条环境泳道
  （各占一根纵轴）→ **光照制度色带** → 巡检覆盖（帧数线 + 覆盖条）→ **真实时间刻度**（主）。
- **悬停**（每条都是 `<title>`）：覆盖点（时间 + 帧数）、空心格（"无帧（不是 0 帧）"）、
  环境点（时间 + 参数 + 值 + 单位）、制度段（`OnMSet`/`OffMSet` 原值 + 起止 + 小时数）、天数带（第 N 天）。
- **环境三态分开说**：还在读 / **取不到**（不画线，也不拿 0 或空白顶替，并说明覆盖与天数刻度照画）/
  窗口内确实没有小时行（"不是 0"）。
- 图例复用页面既有的 `.legend`（只有色带那一档多一条 `.seg` 样式）；零依赖、零构建。
- 天数刻度**故意**只用端点给的 `day`：本批某天一轮都没有 ⇒ 那天的带不出现。要在"没有轮次的那天"
  也画 `第 N 天`，得拿 `batch.entry_date` 自己算日期差 —— 本票**不做**：宁可缺一条带，
  也不在页面上另立一套天数口径（与 `analysis/timeline.day_of` 的 null 同源）。

前端 35 条断言：

     6 轮只问 1 次（N+1 ⇒ 6 次）；换站不重取环境；不重取矩阵；再点同一格不重取；失败不缓存（下次重取）
10–11. 轴与覆盖条：`data-t0`/`data-t1` = 本批首末轮真实时间戳；6 轮一格一轮（5 有帧 + 1 无帧）
12–17. 双刻度：同一个 svg 里 4 条天数带 + 3 条真实午夜边界 + `第 N 天` 逐字；带宽比 4/3；
     6/16 对齐；`day=null` 一条不画；95 个图元落在同一条线性映射上
18–20. 环境带：三参数各一条线；**缺整行处断开**（84 点 / 2 段）；环境点 hover 给读数
21–26. 光照：3 段且带 `(on_m, off_m)` 原值；变制度那一刀落在真实时间上；缺测小时断开；
     `lamp_state` 不参与切段；文案是设定周期不是"点亮了多少分钟"；制度段 hover
27–30. 覆盖：3+2 两段不直连；空心格 ≠ 0 帧；`data-frames="0"` 一个都没有；三处 hover
31. 零依赖（页面无外部脚本/样式，`#nodedetail` 里没有 canvas/iframe/img）
32–35. 幂等与边界：再点不重取；换站环境与矩阵都不重取；换站后图元跟着换；
     "本批没有这个站位的记录"既不画覆盖条、也不冒充"每轮都缺帧"（且不发请求）

### 4.5 边界与交接

- **`deploy/**` 本票没动**：console BFF 的 `/api/environment` 早就有（`deploy/src/deploy/console.py:1178`），
  `/api/timeline` 的透传是票 07 的事（已合并）⇒ 上机无需再补路由。
- 段的两端：`data-to` = 段**覆盖到的最后一个整点 + 1h**（`09:00` 那一小时 ⇒ `10:00` 结束）；
  末段按窗口右端裁切；段内文字只在宽度 ≥150px 时画（否则只留 hover），免得窄段叠字。
- 补光的两档现实（秒档 `OnSSet` / 分档 `OnMSet` 并存，见 `analysis/environment.py:lamp_minutes`）：
  本票按票面口径**只用分档 `(OnMSet, OffMSet)` 做切段键**，秒档不在键里；要把它并进键，
  得先定"两侧各取自不同档"的显示口径。
- 天数刻度与真实刻度的**同轴**关系是契约（断言按"图元两两共线"钉着）：将来给放大图加新的图元层
  （如票 05 的分位数带、P1 的 growth），x 必须继续走 `mdScale()`，别另起一套比例。

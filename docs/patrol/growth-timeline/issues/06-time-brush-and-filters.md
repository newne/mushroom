# 06. 时间刷选与筛选交互

Status: implemented（2026-10-16；验收四条逐条核过，见 §4）
归属：前端（**后端一个字没改**，理由见 §4.1）
依据：[docs/patrol/growth-timeline/spec.md](spec.md)
依赖：05（同文件）

## 交付物

1. **时间刷选**：拖拽选一段时间 ⇒ 总览、放大视图、分位数带**同步聚焦**
2. **筛选**：按层 / 按列 / 按"有没有数据"筛（沿用页面既有 `data-station-filter` 手法）

实施口径（票面留白处，2026-10-16 实施时定）：

- **一份共享窗口**：窗口只有**一个**来源 `tlWindow()`（刷选生效时 = 刷选窗口，否则 = 本批首末轮）。
  总览（`ovX`）、放大视图（`mdScale`）、分位数带（`mdScale`）都从它取 t0/t1；
  **三处都不许自己再算一遍窗口**——各自算就是各自聚焦，票面明令不许。
  窗口是**自由时间**（取整到分钟），**不吸附轮次**：吸附的话"刷到没有轮次的一段"根本选不出来，
  而那正是第三条验收要钉的空态。
- **提交时机**：拖动只改选区（`brushPaint`），**松开才提交**（`applyBrush` ⇒ `redrawTimelineViews()`）
  ——一次拖拽 = 一次提交 = 三处按**同一份**窗口各重画一次。小于 1 小时（`BRUSH_MIN_MS`）算误触，
  窗口不动（点一下不该把上一段刷选弄丢）。
- **空区间**：刷到**一个轮次都没有**的一段 ⇒ 三处显示**逐字相同**的一句空态
  （`tlEmptyWindowText()`，一处写、三处用），一个图元都不画——**不画成 0**，也不画一条空轴。
- **筛选只作用于总览矩阵**（"格"只在这一张上有）：层 / 列 / 「有没有数据」三档 AND 组合；
  **「有数据 / 无数据」看的是本批有没有拍到帧**（与刷选窗口无关——窗口只决定格子里画几轮）；
  **空位（没配置站位）不算"无数据"**。
- **被筛掉的格子留在 DOM 里**（`hidden` + `data-kept="0"`），计数写在卡片上：
  `48 格 → 留下 12 格；筛掉 36 格（丢掉：有数据 1 · 无数据 0 · 空位 35）`。
- **不重取**：刷选与筛选都是把**已经拿回的那份矩阵**换一种画法 ⇒ `/api/timeline` 与环境请求
  一个都不多发（票 02–05 的"不重取"护栏原样成立）。

## 4. 实施与证据

### 4.1 后端：一个字没改（为什么）

本票要的东西**页面手里全都有**：票 03 那一次 `/api/timeline` 已经拿回「每节点 × 每轮」整段矩阵。
刷选是**窗口化**（同一份矩阵换一段 x），筛选是**换一种画法**（格子 hidden + 计数），
两件事都不需要端点知道"窗口"。真要放服务端，就多出一份必然与矩阵漂移的副本，
还多一串请求——而"不加请求"是票面硬验收。所以 `analysis/**` 未改、未跑后端套件、PG/TDengine 未碰。

### 4.2 页面（`web/console/index.html`）

- **一份共享状态**：`hist.brush = {t0, t1}`（`null` = 不刷）+ `hist.tlFilter = {layer, col, data}`。
  窗口**只有一个**来源 `tlWindow()`；`tlFullExtent()` 给本批整段（刷选条的横轴 + 未刷选时的窗口）。
  两个纯函数：`tlPointsInWindow()`（裁窗口，**三处共用**）、`tlStamp()`（毫秒 → 本地 ISO 串；
  三处与刷选条都写这个串 ⇒ "是不是同一份窗口"是**逐字节**可比的）。
- **一个入口**：`redrawTimelineViews()` = `drawOverview()`（内部连带 `drawBrush()` 与
  `drawRoomBand()`，沿用票 05"同一次渲染"）+ `refreshNodeDetail()`。改窗口只能从这里走，**零请求**。
- **刷选条**（`#brushwrap`，`viewBox 920×46`）：横轴 = 本批整段、内边距与下面三处视图**同一套**
  （`padL 66 / padR 22`，刻度因此与三处的 x 对齐，三处视图的内边距也是这套）；
  一轮一条刻度；选区 = 那份共享窗口；「清除刷选」把窗口清回整段。`brushTsAt()` 是**唯一**的
  拖拽换算（取整到分钟；量不到布局框就什么都不做——宁可不刷，也不拿错的像素比例去刷）。
- **筛选条**（`#ovfilters` + `#ovfilterinfo`）：三组按钮 + 计数行。属性名是 `data-tl-filter`
  **不是** `data-station-filter`：站位卡的 `drawList()` 会把**所有** `[data-station-filter]`
  的 onclick 收走、还会按它自己那套规则改 disabled——照抄属性名两个筛选器会互相踩
  （**手法**照旧：按钮 + `aria-pressed` + 一档「全部」）。
- **口径只有一处**：`tlCellKept()`（画格子与数计数都走它）、`tlFilterCounts()` / `tlCountText()`
  （"留下几格 / 筛掉几格 / 丢掉的都是什么"）、`tlEmptyWindowText()`（三处同一句空态）。
- **环境带**：刷选生效时只画**窗口内**的小时行（窗口外的不画，不是压在边缘上）；
  环境取数窗口仍是**本批窗口**（票 04 的护栏不动）⇒ 刷选不触发环境请求。
- **换批清窗口**：「重新读取」（`loadHistory(true)`）清 `hist.brush`；筛选**不清**
  （那是用户的看法，换批仍适用）。

### 4.5 边界与交接

- **刷选不吸附轮次**（自由时间、取整到分钟）是有意的：吸附之后"刷到没有轮次的一段"就选不出来，
  而那正是第三条验收。取整到分钟只是让窗口值可读、可写进 `data-*`，不影响任何判据。
- **筛选只筛"格"，不动库房口径**：分位数带的分母仍是本批已知站位 ∪ 矩阵站位（票 05 §4.5），
  所以按层看时它仍是"全库房整体"。要"按层看整体"是另一个需求（票面没要），别顺手塞进来。
- **空位不是"无数据"**：没配置站位在「有数据」「无数据」两档下都被筛掉，计数里单列 `空位`。
  把 45 个空位混进「无数据」，会被读成"45 个站位漏拍了"——那是另一种撒谎。
- **窗口是内存态**：换批（重新读取）清掉；页面刷新即回到整段。**不写 localStorage**：
  窗口是"这一批的这一段"，跨会话留着它没有意义（而且现场是共享终端）。
- 采样下限 `BRUSH_MIN_MS = 1 小时` 是**下限**不是标定值；真机一批 16 天，1 小时是最细的一档。
- 刷选条只有**一条**，长在「时序总览」卡里，但它管三处：**别**给放大视图或分位数带各加一条
  （那就是两份窗口，票面第一条验收当场作废）。票 07+ 要动手时，窗口仍然只能从 `tlWindow()` 取。

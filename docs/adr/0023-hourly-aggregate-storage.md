# ADR-0023：环境表只存小时聚合，原始序列按需现取

日期：2026-10-12
状态：建议（已按此实现并上机，待评审）
相关：ADR-0021、`docs/patrol/env-analysis/spec.md`

## 背景

2026-10-12 用户定调："这里只保留聚合后的指标数据落库即可，不需要保留原始分钟级数据，需要的时候通过数据接口获取即可。"

第一版实现把 TDengine 的逐分钟采样原样写进 `analysis.environment`：12 天 × 4 库房 = **69,115 行**。而界面按小时看、区间分析也按小时聚合——原始点在库里没有任何消费者。原始序列的权威本来就是 TDengine（每分钟一条，REST 可查）。

## 决定

1. `environment` 只存**小时聚合**：`ts`(整点) / `zone` / 每参数的 mean·min·max / `lamp_state`(众数) / `n`(采样点数)。
2. **原始分钟序列不落库**，按窗口现取：`GET /environment?granularity=raw`，窗口上限 **6 小时**。这类接口是排障用的，不是趋势图用的。
3. **入库每轮从当前整点重算再覆盖**（游标退到整点）：一小时的聚合必须由该小时的全部采样算出；只拉"游标之后"的增量会把当前小时的均值算小。重复拉 60 行不算成本。
4. 表结构变更**直接重建表**，不做加列迁移。敢 drop 的理由：表里全是**可再生的派生数据**，重跑一次 ingest 就回来（`migrate()` 里写明了这条）。

## 补记（2026-10-12 晚）：聚合的边界是"连续量"，不是"一切"

当天用户又指出环境分析里看不到操作员的实际操作，并给了环控平台的命令审计接口。
操作日志**逐条入库，不聚合**（`analysis.operations`）：一天几十条，事件本身就是最小
有意义的单位，聚合成"每天改了几次"之后就答不出"那天 10:10 谁把右加湿器的开启设定
改成了 5"——而那正是要学的运行经验。

所以本 ADR 的规则要读成：**每分钟一条的连续量只留聚合；稀疏的事件逐条留**。
判断依据是"聚合之后还能不能回答原来的问题"，不是"数据量大不大"。

## 后果

- 行数从 69,115 降到 **1,156**（约 60×），界面与分析要的数据一条不少；`n` 让断档仍然可审计（不足 60 就是缺）。
- 分钟级排障要多走一次实时查询（TDengine 可达才行）；反过来说，TDengine 抖动不影响趋势图与统计。
- 口径分界必须写在代码注释和文档里：`min/max` 是采样点级别的真实极值，`q25/median/q75` 是"每小时一个点"的分位数。混读会得出错误结论。
- 将来若要"按分钟回溯某一天"，走 raw 接口或直查 TDengine，**不要指望库里**。

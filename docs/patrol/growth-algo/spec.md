## Problem Statement

现场 48 个固定锚点每 3 小时采一轮，图像一直在进（本批已采十余天），但**没有一条可用的生长曲线**：`measurements` 至今 0 行，页面上的"长势"是空的。具体卡在四处：

1. **现役链路不能直接当交付。** 无模型启发式链路是**系统性过检**——袋肩门保留率中位仅 **15.1%**（218 帧里没有一帧 >50%），开门后仍有 **19% 的帧**袋级簇宽 >240 mm（比整袋还宽，物理上不可能）。直接拿来交付，等于把假数喂进区间表。
2. **口径混乱。** "菌簇高度 ≠ 平均菌杆长度""菌簇宽度 ≠ 菌帽直径"；通用预训练权重**不能**直接当现场识别结果；而毫米值没有解锁条件（方形像素不能单独证明各方向共用同一物理尺度）。
3. **旧路线已废。** 单杆完整测量（"杆长 → mm"）已被裁定退出本期主链路，但仓库里仍留着那条链路的代码与契约，容易被误当交付。
4. **时间窗在关。** 本批**第 25 天停采**，帽期样本是**时间盒**；而**原图是唯一不可再生的资产**——标注可重做、模型可重训、模板可重画，帧丢了就没了。

## Solution

- **主交付**：48 个固定锚点的**簇级像素趋势**——菌包定位、一袋一簇、菌簇**平均顶部轮廓高度**、顶部高度、宽度及时间曲线；另出**与菌包的相对尺寸**（无量纲），让不同层、不同排、不同锚点之间可以互相比较。
- **增强交付**：可辨认菌帽的实例分割、**投影卡尺直径**（px）分布与时间曲线；与主交付**解耦，互不阻塞**（帽模型不可用时不阻塞簇级曲线）。
- **方法**：真实现场图**离线标注**（一袋一簇可见掩码 + 袋顶折线 + 单帽可见掩码）→ **专用分割模型**（预训练权重只作初始化，**纯 CPU 训练**）→ 模板映射的**袋顶基线** → **逐帧对齐**（平移优先）→ **一袋一簇**关联 → **固定集合**聚合出锚点曲线 → 四层总览。
- **常设数据飞轮**：持续标注 → 增量训练 → 用新模型预标注下一轮，并配**三道防自举污染的闸**。
- **尺度延后**：实际尺寸映射（mm）不在本期门内；像素值一律不写毫米列。

## User Stories

1. 作为巡检人员，我想看到每个锚点随时间变化的簇高曲线，这样我知道这一框在长还是在停。
2. 作为巡检人员，我想看到曲线上的"缺测"标记而不是被补成实测值，这样我不会把断档读成停滞。
3. 作为巡检人员，我想在换包 / 换视角 / 换版本时看到曲线**分段**，这样我不会把两批蘑菇连成一条"增长"。
4. 作为巡检人员，我想看到每袋的簇宽与顶部高度，这样我能分辨"整体长高"和"个别袋往上冲"。

18. 作为研究者，我想每轮留 **10% 从零人标对照集**，这样我能看见"人在盖橡皮图章"。

25. 作为算法工程师，我想有一份**实测的 CPU 机时表**，这样排期不靠猜。

33. 作为运维，我想让帧**持续归档**并有覆盖率断言，这样窗口内的缺口能被发现并补拍。

## Implementation Decisions

### 3. 数据与身份契约

#### 3.1 三个逻辑键

```
AnchorKey      = (room_id, rack_id, layer_id, anchor_id)     # anchor_id = images.station_id
ObservationKey = (AnchorKey, observation_cycle_id, image_id)  # image_id = (ts, station_id, angle_profile)
ResultKey      = (image_id, pipeline_version, model_version, roi_version, calibration_version)
```

#### 3.2 与现有表达的映射（逐键给结论）

| 逻辑字段 | 现有表达 | 结论 |
| --- | --- | --- |
| `anchor_id` | `images.station_id`（`S101…S412`） | **可直接表达** |
| `room_id` / `layer_id` | `images.room_id` / `Station.layer` | **可直接表达** |
| `rack_id` | 不存在（现场单相机、一层 12 框 × 4 层） | 用常量（票 01 Q1）；**待确认是否只有一列货架** |
| `image_id` | `images` 主键 `(ts, station_id, angle_profile)` | **可直接表达** |
| `observation_cycle_id` | **不存在** | 需新表或派生键（§3.3） |
| 版本四元组 | **`measurements` 表达不了**（主键 `(ts, room_id, box_id)` 无版本维度） | 三层离线证据（§8），**DDL 另行评审** |

#### 3.3 周期（`observation_cycle_id`）的过渡口径

- **权威周期**需要农事事件源，今天没有（B4）⇒ **过渡期用派生键**：
  `(room_id, station_id, entry_date, batch_no)`，并**强制标 `cycle_id_tentative=true`**，**不得当权威周期使用**。
- 版本变更（视角/ROI/模型/标定）**不改周期**，由 `ResultKey` 四元组承担并触发**分段**。
- **换包/采收**：先用可观测信号提出**疑似**变化（袋数突变、图像变化），标 `suspected`，**不自动解释为换包**（Plan §4.3）。

#### 3.4 轮次 ≠ 周期（防混用的硬话）

`rounds`（轮次）是**采集批次**（约 3 h 一轮；`round_id` 现成）；`observation_cycle`（周期）是"同一批蘑菇的连续观察段"。**曲线按周期分段，数据划分按轮次成组**（G8）。

### 4. 指标定义（像素口径）

#### 4.1 主指标

```
H_profile = (1/|V|) · Σ_{x∈V} [ b(x) − t(x) ]        单位：原图像素 px
```

`b(x)` = 袋顶基线在该列的 y（模板折线经对齐映射）；`t(x)` = 菌簇顶部轮廓在该列的 y。

**`V` 的三条合成规则（本规格新增第 3 条，G1）**：

1. 列连续宽度 ≥ `min_col_run_px`（初值 3；先做 3×3 开运算）；
2. 该列前景最高连续段的上边界可取（段间隙 > `max_gap_px`（初值 5）⇒ 该列不可靠）；
3. **该列必须存在从 `t(x)` 向下连通到 `b(x)` 的前景竖直路径**（容差 `reach_tol_px` 初值 8）——否则是"被空隙截断"，不是"被基线截断"。

**文案**：字段名与页面一律写「菌簇平均顶部轮廓高度」，**不写"平均菌杆长度"**。

#### 4.2 辅助指标

`robust_top_height_px`（`quantile(h, 0.9)`）；`raw_top_height_px`（`max(h)`，先按 0.995 截尾）；`cluster_width_px`（与高度**同一套列有效性**）；`valid_column_count` / `valid_column_ratio`；`visible_coverage_ratio`（簇掩码面积 / `front_roi` 面积，**仅辅助**）；`baseline_valid` / `association_valid` / `measurement_valid` / `rejection_reason`（**逐袋，不许只留一个总数**）。

#### 4.3 基线的两级可用性（G2）

| 级别 | 条件 | 处置 |
| --- | --- | --- |
| 可用 | 对齐接受 ∧ 槽位匹配 ∧ 袋口偏移 ≤ `bag_shift_max_px`（初值 40）∧ 可见列数 ≥ `min_baseline_columns`（初值 8）∧ 覆盖槽宽 ≥ `min_baseline_coverage`（初值 0.2） | 出高度；不可见列由折线插值 |
| 不可用 | 上列任一不满足 | **高度缺测**；簇自身竖向跨度**另存**，但不冒名基线高度 |

#### 4.4 三态词表（与 CONTEXT.md 一致，不许混）

| 词 | 含义 | 落法 |
| --- | --- | --- |
| **可用（usable）** | 这一行/这个值可算、可比 | `cluster_height_usable`（G5 五条合成） |
| **不可测（unmeasurable）** | 现役形态下物理上量不出来 | NULL + 明确码（如帽径在未分化阶段） |
| **不可用（unusable）** | 有值但本身不可信 | NULL + 具体失效码（`no_light`/`unreliable`/…） |

**缺测 vs 0**：检测失败/不可测 ⇒ **NULL**；只有"**确认无袋/无菌帽**"（完成有效观察后）才写 **0**。

#### 4.5 取值规则初值表（**开发集后冻结，冻结后不回改**）

| 规则 | 初值 | 出处 |
| --- | --- | --- |
| `min_col_run_px` | 3 | 票 01 §3.2 |
| `max_gap_px` | 5 | 票 01 §3.2 |
| `reach_tol_px` | 8 | **本规格新增（G1）** |
| `min_valid_column_ratio` | 0.3 | 票 01 §3.2 |
| `top_quantile` / `outlier_quantile` | 0.9 / 0.995 | 票 01 §3.2 |
| `bag_shift_max_px` | 40 | 票 01 §3.2 |
| `min_baseline_columns` / `min_baseline_coverage` | 8 / 0.2 | **本规格新增（G2）** |
| `panel_coverage_min` | 0.8 | 票 01 §3.2 |

**冻结纪律**：本节数值在**开发集分析后、查看锁定测试集结果前**冻结；冻结后**不得因结果不好回改**；发现规则本身选错 ⇒ **另开一节写"算不出来 + 为什么"**，原处保留（与票 15 §13.5 同一条纪律）。

#### 4.6 相对尺寸：与菌包的比值（v1 口径，用户 2026-10-14 16:5x 裁定）

**裁定**：实际尺寸映射（mm）**延后**；v1 只要能**对比出与菌包的相对尺寸**。

```
rel_profile_height = H_profile_px / ref_px      # 无量纲
rel_top_height     = robust_top_height_px / ref_px
rel_width          = cluster_width_px / ref_px
```

`ref_px` = **同一帧、同一袋**的特征宽度（`measure/bag_ruler.BagRegion.characteristic_width_px()`：轮廓中"接近最宽"那些行的中位跨度）；每行必须**同时记下** `ref_px` 原值与 `ref_kind`（`bag_width` / `bag_height`）。

**为什么这样能消掉尺度**：同袋、同帧 ⇒ 相机内参与景深在比值里一阶抵消 ⇒ **不同层、不同排、不同锚点之间可以互相比较**——这正是原本要靠 mm 才能做的事，而现在不需要 mm。

**必须同时写出的三条限制**（不许省略）：

1. **它不是 mm**，也不代表任何物理尺寸；**不写毫米列**，不进任何以"尺寸"为名的文案。
2. **袋宽自身的测量散布会原样进入比值**：排内袋宽 CV 中位 **0.249**（p10 0.148 / p90 0.362），逐袋 mm/px 散 1.5–2.3 倍（票 15 §13.1/§12.2）⇒ 比值的不确定度**主要由分母决定**。逐帧必须报 `ref_px` 与袋宽 CV。
3. **袋本身会长、会变形**（软包装、装料量差异）⇒ 分母**不是刚性标尺**。比值的用途是**同一锚点的相对变化**与**跨锚点的粗略可比**，**不是绝对尺寸判断**。

**与将来 mm 的衔接**：真要做 mm 时，只需把 `ref_px` 换成 `ref_px × k = ref_mm`（`k` 来自标定）——**本节输出格式不变**，所以延后不动结构。

### 5. 人工资产：锚点模板与训练帧标注

#### 5.1 模板字段（在票 01 §2.1 之上补三处）

字段见票 01 §2.1；本规格补三处：

1. **`front_rows`（新增，必填）**：该锚点的"前排"是哪些 `row_id`（G9）；不写全局常数。
2. **`bag_slots[].top_line_ref` 允许 `baseline_valid=false`**：不可见不猜（Plan §8.3）；缺槽位**不删槽**，记 `panel_coverage`。
3. **`resolution_mismatch`**：参考帧必须 2880×1616，不符即记该码，不静默缩放。

#### 5.2 生成流程（半自动，B3 缓解）

**生成流程**：① 用 `find_bags()` 在参考帧出槽位候选（框 + 袋顶线）→ ② 人在复核页增删改（多边形 + 折线）→ ③ 另一人按清单复核 → ④ 发 `roi_version=v1` + `template_sha256` → ⑤ 存**离线文件**（`configs/anchor-templates/<anchor_id>.json` + 掩码 PNG），**DB 变更另行评审**。

#### 5.3 复核清单

**复核清单**（写死，防止模板自己变成误差源）：静态背景掩码不含任何生长对象；`front_roi` 不跨后排；排除区不覆盖需量测的槽位；每槽位实际有袋（或显式记空袋）；袋顶折线贴**袋口**而不是菌簇；参考帧无临时遮挡；天生不可用 ⇒ 显式 `anchor_unusable` + 原因，**不硬凑**。

#### 5.4 辅助标注方案（用户 2026-10-14 16:5x 要求）

**先摆约束**：标注在 prod 的 **X-AnyLabeling CPU 客户端**里做（票 02），客户端**不装内置模型**、走 RDP。所以辅助标注**不能依赖在线服务或 GPU**；**只能靠"预标注 + 人只复核"**。

**三条预标注来源，按「零模型的先做、模型的补后做」排**

| 来源 | 产出对象 | 成本 | 精度来自哪 |
| --- | --- | --- | --- |
| **T 模板映射（零模型）** | `bag` 槽位、`bag_top` 折线 | **≈0** | 锚点固定 + ECC 平移对齐 ⇒ 模板几何直接映射到本帧 |
| **H 启发式（零模型，已有）** | `cluster` 候选（**袋肩门后**） | **1.74 s/帧**（现役 L1–L3，票 15 §13.1） | `measure/bag_ruler` + `fruitbody` + `filter_above_bag_top` |
| **M 自训模型（模型在环）** | `bag`/`cluster`/`cap` 全类别 | 1 次/帧推理 | P2 的 v1 模型，**第 2 轮起**用它预标注下一轮数据 |

**T 是最值钱的一条**：48 个锚点是固定站位、相机只平移，模板里**已经有** `bag_slots` 与 `bag_top` 折线 ⇒ **锚点覆盖层的 48 帧，袋与袋顶几乎不用画**，人只做"删掉不对的、补上漏的"。

**两条工作流，按量分工（不是二选一）**

| 流程 | 用在哪 | 怎么做 |
| --- | --- | --- |
| **B 批处理 + 离线复核页**（主力；票 21 模式） | 量大、结构规整的帧（锚点覆盖 48 帧、扩训 500–800 帧） | 预标注脚本产 XLABEL JSON → 转复核表（`frames.csv` + `instances.csv`）→ 离线单文件页点选"确认 / 编辑 / 拒绝 / 补漏" → 回写 JSON。**人不下画笔**，只做票 21 §1.5 那四件事 |
| **C 客户端点选生成**（补充） | 困难帧、预标注明显不对的帧（估计 <15%） | 客户端里挂**本地 ONNX**（SAM-Tiny / SAM 2.1-Tiny）点选出掩码 → 人工修边界 → 存 JSON |

**A1 模板映射预标注（T）**（新增工具，算 P1-1 的一部分）：

1. 参考帧已有 `bag_slots` 与 `bag_top` 折线（模板，§5.1）；
2. 目标帧走 ECC 平移对齐（**与 P3-1 同一份实现**）得到 `T`；
3. `map_roi(slot.polygon, T)` / `map_polyline(top_line, T)` ⇒ 直接作为预标注多边形与折线；
4. 标记 `source=template`、`review_status=predicted`；
5. 人只处理**对齐残差超限**或**槽位错位**的帧；超限就整帧退回人工（不硬套）。

**A2 模型/启发式预标注（H / M）**

- **H 阶段（P1，还没有自训模型）**：用现役 L1–L3 出 `cluster` 候选。注意它的已知性格是**过检**——袋肩门保留率中位仅 **15.1%**（票 15 §13.2）⇒ 假阳少但**漏检多**，正好匹配"人补漏"这个低成本动作。候选一律 `review_status=predicted`，**必须逐个确认，不许默认采纳**。
- **M 阶段（P2 起）**：用上一轮模型预标注下一轮数据。**这是唯一能把 500–800 帧标注量压下来的路径**。
- **SAM 只在 C 流里用**，且**图像编码一次/帧**（批处理跑，CPU 可接受；点选解码很快）。若实测编码太慢 ⇒ 退回 T + H，**不阻塞**。

**A3 落到客户端的形式**：预标注 JSON 与图**同名同目录**（客户端默认），标注员 `Open Dir` 打开就已经看到画好的形状 ⇒ 客户端里只"改"，不从零"画"。类别与属性按票 01 §4.5 的三件配置文件加载。

**A4 硬规则**：预标注**不许用类别名或文件名携带来源信息**（票 01 §4.5 已禁）；来源只写在 `attributes.source` 与 `review_status` 里，**可回读、可统计**。

#### 5.5 预标注留痕与质量门

- **`source` 必填**（`template` / `heuristic` / `model` / `human_added`）。缺了它，"人只复核"事后无法回答"这条标注是谁给的"，就会退化成**人盖橡皮图章**。
- **每批固定留 10% 的帧从零人标**（不预标注）作**对照集**，同时报两个数：① 预标注**采纳率**；② 对照帧与预标注帧的**标注分歧率**。**只报采纳率会掩盖"人没看"**。
- **`review_status=rejected` 的行必须留**（票 01 §4.5.2 / 票 21 §5）：删行 = 洗白假阳，precision 就永远算不出来。
- **预标注错误率超阈值 ⇒ 停用该来源**；阈值在开发集上冻结（与 §4.5 同一套冻结纪律）。
- 试画 3 张（P0-2）**必须走一遍完整流程**（预标注 → 复核页 → 回写 → 回读四条），否则"人能只复核"只是假设。

#### 5.6 持续标注与训练：数据飞轮（用户 2026-10-14 18:2x 裁定）

**裁定**：标注与训练**不是一次性阶段**，而是**持续进行**的常设过程。⇒ P1/P2 不是"做完就过去"，而是**每轮都走一遍**。

**循环（每轮）**

```
采帧入档（§1.5-1）
  → 预标注（T 模板映射 / H 启发式 / M 上一轮模型，§5.4）
  → 人工复核（主力走 B 批处理 + 离线复核页；困难帧走 C 客户端点选）
  → 增量入训练集（记 dataset_version）
  → 训练（§6.2：imgsz=640 全量 8.7 h，排夜里）
  → 评估：**锁定测试集** + 与当前在用版本对比
  → 晋级（MLflow registry/stage；不达标**只入库、不晋级**）
  → 回到预标注（用新模型标下一轮）
```

**建议节奏（待裁，§11 Q17）**：**每周 1 轮、每轮 100–150 帧** ⇒ 稳态人工 **3.3–10 人·h/周**（§5.4 之后）+ 机时 **8.7 h/周**。

**三道闸：飞轮最大的风险是"自己教自己"**

模型预标注 → 人复核 → 再拿这批训模型 ⇒ 模型的偏差会被"复核"确认、再固化进下一轮。**只报采纳率发现不了**（采纳率天然单调上升）。所以写死三条：

1. **锁定测试集永不由"正在被评估的模型"预标注**：它必须**从零人标**，且**模型换代不得重标它**——否则基准随模型漂移，测出来的"提升"是自己给自己出的题。
2. **每轮固定留 10% 从零人标对照集**（把 §5.5 升级为**每轮必做**），并据此算**采纳率与分歧率的时间序列**——这是唯一能看见"人在盖橡皮图章"的信号。
3. **每 N 轮抽样重标**（建议 N=5、每次 20 帧，从零重标）与历史标签比对，检测**标签本身**的漂移（复核人会被模型的风格带跑）。

**训练集不能无限膨胀**：每轮新增会推高机时（600 → 1000 帧 ⇒ 机时 ×1.67）。定**上限与采样口径**（建议上限 **1500 帧**；超限后按**失败类型分层采样**，并**无条件保留**锁定测试集与对照集）。否则某天一轮训练会变成 3 天。**待裁**，§11 Q18。

**版本对应**：每轮产出记 `model_version`，训练集记 `dataset_version`，**必须能回答"这个模型是哪些帧训出来的"**；晋级走既有 MLflow registry + stage（§8），**不新造第二套治理**。

### 6. 链路分解与模块接口

每个阶段都**必须**给出输入、输出、坐标系、失败状态与单元测试；**不允许以默认值静默补齐**（Plan §13 末句）。

| 阶段 | 做什么 | 输入 → 输出 | 失败码 | 归属 |
| --- | --- | --- | --- | --- |
| **L0 质量门** | 在**目标 ROI 内**算暗/饱和比例、清晰度、截断比例、内容完整性；重复图用**图像哈希 + 采集元数据**联合判 | 原图 + 模板 → `quality` | `no_light`/`overexposed`/`blurry`/`frame_dup`/`truncated` | 算法 |
| **L1 对齐** | OpenCV ECC，**平移优先**，用**稳定背景**掩码（不用菌簇）；低分辨率估变换 → 映射 ROI → **在原图坐标量测** | 原图 + 参考帧 + 静态掩码 → `T` | `registration_failed`/`view_changed`/`registration_unreliable` | 算法 |
| **L2 定位** | 专用 seg 模型出 `bag`/`cluster` 框 + 掩码 + 置信度 | 原图 → 实例集合 | 低置信 ⇒ 逐实例标注，不整帧丢 | 算法 |
| **L3 前排过滤 + 一袋一簇** | `map_roi(front_roi, T)` 过滤；多线索 one-to-one（袋顶关系、簇下缘、横向重叠、槽位归属、最近/次近歧义） | 实例 + 模板 → `pairs` | `association_ambiguous`/`merged_multiple_bags`/`truncated` ⇒ `measurement_valid=false` | 算法 |
| **L4 基线** | 模板折线经 `T` 映射 → 逐帧验证（槽位/偏移/可见列/同一物理位置） | 模板 + `T` → `b(x)` + `baseline_valid` | `baseline_invalid` ⇒ 高度缺测 | 算法 |
| **L5 簇级量测** | 掩码轮廓 + `V` 三条规则 → §4 指标 | `cluster_mask` + `b(x)` → 逐袋指标 | `insufficient_contour` | 算法 |
| **L6 聚合与曲线** | 固定集合匹配、`panel_coverage`、分段、原始点 | 逐袋 → 锚点/层/四层 | `panel_coverage_low` ⇒ 曲线标不可比 | 算法 + 后端（消费） |
| **E1 帽支线** | 独立菌帽 seg（输入单包裁剪）→ 量测资格 → 最大投影卡尺直径 | 裁剪 → 帽级指标 | 无合格帽 ⇒ 直径 **NULL**；**只有完成有效观察且确认无帽，计数才可为 0** | 算法 |

**不要求菌簇掩码位于菌包掩码内部**；模型把多袋菌簇合并成一个实例 ⇒ 标**关联失败**，**不强行分摊尺寸**（Plan §7.3）。

#### 6.1 性能预算（写死）

| 项 | 门 | 现状/依据 |
| --- | --- | --- |
| 单帧总耗时 | ≤ **3.75 s/帧**（= 单轮增量 ≤180 s / 48 站） | 票 15 §8.1 的新门；现役 L1–L3 **中位 1.74 s/帧** |
| 单轮增量（48 锚点） | ≤ **180 s** | 同上；ECC 必须在**低分辨率**上估变换，否则整帧 ECC 会吃掉全部预算 |
| 内存/批次 | 单进程批处理，不驻留全量帧 | 现场机 4 核（票 02 §7.2） |
| 输入数守恒 | **输入数 = 成功数 + 失败数 + 跳过数** | Plan §12.2 |

#### 6.2 CPU 训练与推理预算（用户 2026-10-14 16:5x 裁定：纯 CPU）

**落点 = 开发机**（本机 WSL2 **22 核 / 15 GiB**，票 02 §7.2 实测），**不用 prod**：prod 是 4 核 + 49 个容器 + load ~1.7，训练会把巡检与推理一起拖慢（同一判断票 02 §9.3 已写过一次）。

**依赖：`uv` + 国内源**（用户 2026-10-14 16:5x / 17:3x 两条裁定）

```
# 包：国内 PyPI 镜像
uv pip install --index-url https://mirrors.aliyun.com/pypi/simple opencv-python-headless ultralytics
# torch 的 CPU 轮子：国内同样有镜像（已核可达）
uv pip install --index-url https://mirrors.aliyun.com/pytorch-wheels/cpu torch torchvision
```

- 仓库 `pyproject.toml` **已经**把 aliyun 设为默认 index（`[[tool.uv.index]] url = "https://mirrors.aliyun.com/pypi/simple"`），并另声明了 `pytorch-cpu` / `pytorch-cu129` 两个显式 index ⇒ **项目内安装本来就默认走国内源**；上面这两行是给**仓库外一次性 venv**（如 `.scratch/cpu-bench`）的等价写法。
- **别省 `--index-url`**：不带它 uv 走默认 PyPI（境外）——本机实测**一个包 9 分钟**。
- **装 `ultralytics` 时加 `--torch-backend=cpu`**（或先固定 torch），否则解析器可能去拉 CUDA / XPU 版 torch——本机实测装成过 `2.9.1+xpu`。
- **本文件不改 `pyproject.toml`**（共享文件，改前 @Chief）。

**输入分辨率：CPU 下这是第一决策，不是调参项**

- 原始帧 **2880×1616**。直接 `imgsz=640` 会把袋（宽 260–333 px）压到 ~60 px，**簇顶轮廓基本消失**。
- 因此 **训练与推理都在「锚点前排 ROI 裁剪」上做**——Plan §7.1 说"裁剪方式由开发集比较决定"，**这就是那个决定**：模板 `front_roi` 通常只占画面下部 1/2–2/3，裁剪后输入降到约 **1200×900** ⇒ 同样 `imgsz` 下有效分辨率翻倍，CPU 机时按面积下降。
- 推理保留 `crop → 预测 → 映射回原图坐标`（与 Plan §6.2「低分辨率估变换 → 原图坐标量测」同一条原则）。

**吞吐：先量，再排期**

```python
# 跑 3 个 epoch，用 results.csv 里 time 的逐 epoch 差分取稳态（第 1 个含预热，丢掉）
from ultralytics import YOLO
m = YOLO("yolo26s-seg.yaml")        # .yaml = 只建结构、不下权重；吞吐与初始化无关
m.train(data="<dataset>.yaml", imgsz=640, batch=4, epochs=3, device="cpu", workers=0)
```

机时 ≈ `s/图 × 帧数 × epochs`（用**稳态** epoch 时间，**别用"调用一次 `model.train()` 的墙钟"**——它含一次性开销）。**§6.2 已有本机实测值，不要再用拍脑袋的 it/s**；换机器或换分辨率，按同法重量一次。

**本机实测（2026-10-14，真机 YOLO26s-seg，纯 CPU）**

环境：本机 **22 核 / 15 GiB**，`ultralytics 8.4.177` + `torch 2.9.1`（CPU 执行），`workers=0`。
样本：**24 张合成帧**（1280×720、2 类多边形）——**不连生产、不读真帧**；脚本 `.scratch/cpu-bench/steady.py`。
口径：跑 3 个 epoch，取 `results.csv` 里 `time` 的**逐 epoch 差分**并丢掉第 1 个（含预热）。

| imgsz | batch | 稳态 epoch（24 帧） | **s / 图** | 600 帧 1 epoch | 50 epochs | 100 epochs |
| --- | --- | --- | --- | --- | --- | --- |
| 640 | 4 | 25.0 s | **1.04** | 10.4 min | **8.7 h** | 17.4 h |
| 960 | 2 | 56.7 s | **2.36** | 23.6 min | **19.7 h** | 39.4 h |

**结论（写进排期，别写进借口）**

- **一次全量训练 = 约 9–40 h**（600 帧 × 50–100 epochs，取决于分辨率）⇒ **必须排夜里/周末**，不是"顺手跑一下"。
- **参数搜索只在子集上做**：150 帧 × `imgsz=640` ⇒ **2.6 min/epoch**；一次 15-epoch 试验 ≈ **39 min** ⇒ **10 组就是 6.5 h**。**网格搜参在 CPU 上仍做不起**，靠先验砍到 3–5 组、小步迭代。
- **`imgsz` 是最贵的旋钮**：640 的每图成本只有 960 的 **44%** ⇒ 先用 640 定参数，最后用 960 复核。
- **别拿单次调用当 epoch 时间**：实测 640 那次 `model.train()` 墙钟 **58.6 s**，而训练循环本身只有 **25 s**——差额是建模型/建缓存/收尾/验证/保存的一次性开销。按墙钟排期会高估一倍。
- **`yolo26s-seg` 在 `ultralytics 8.4.177` 里可用**（`YOLO("yolo26s-seg.yaml")` 直接建模成功）⇒ Plan §3 的选型在**依赖层**站得住。
- 先前的**代理测量**（deeplabv3-mobilenet 11 M：1.41 / 3.00 s/图）**已被本表取代**——真机 YOLO 比它便宜约 20–35%。

**环境提示（本机实测，2026-10-14）**：**必须走国内源**（用户 17:3x 裁定）——同一台机器上，境外索引装一个包要 **9 分钟**，aliyun 镜像装 `ultralytics`+`thop` 只要 **16 秒**、23 个依赖 **1 分 34 秒**（差 **20–50 倍**）。最终装成的组合：`torch 2.9.1+xpu` / `opencv 5.0.0` / `ultralytics 8.4.177`。装 `ultralytics` 时加 `--torch-backend=cpu`，否则解析器可能去拉 CUDA/XPU 版 torch（实测就装成了 `+xpu`：CPU 上能跑，但不是我们要的轮子）。

**已知的 CPU 副作用（写进排期，不写进借口）**

1. **调参轮次是小时级** ⇒ 参数只在**小样本 + 低分辨率**上搜，选定后再跑全量。
2. **`cache=True` 先解码再缓存**：全分辨率 800 帧 ≈ **11 GB**（2880×1616×3 ≈ 14 MB/帧），15 GiB 扛不住；裁剪到 1200×900 后 ≈ **2.6 GB**，可以开。**跑之前先算一次**。
3. **Windows 上 `workers>0` 必须放在 `if __name__ == "__main__":` 保护里**，否则多进程会反复重跑训练入口。
4. **训练期不要与推理/评估并行**：同机争核会把两件事都拖长。

### 7. 时序、固定集合与四层总览

- **固定菌包集合 = 模板 `bag_slots`**；缺袋记 `panel_coverage`，**不删槽位**；样本组成明显改变 ⇒ 曲线**标不可比或分段**；"当次全部有效袋"另附、与主趋势**分开**。
- **曲线规则**：用**采集时间**不用处理时间；保留原始点；平滑仅用于展示；**缺测不补成实测值**；**不跨长缺测区间算变化速率**；不强制单调增长；换包/视角/版本变化时**分段**。
- **分段依据（事件源先留空 —— 用户 18:2x）**：v1 只按 ① **版本四元组**、② **批次边界**（`entry_date` / 台账）分段；每条曲线带 `segmentation_status=by_version_and_batch`，页面写明「**本曲线按版本与批次分段，未含换包事件**」。**疑似变化**（袋数突变、画面剧变）按 Plan §4.3 只做**图上标记**，**不得自动切段、不得自动解释为换包**。事件源补全后按新规则**重新分段**，用新 `pipeline_version` **写新行、不覆盖旧行**。
- **四层总览**：每层 12 锚点小图曲线 + 有效锚点数与缺测 + 各锚点相对自身基准变化 + 层内趋势中位数与离散 + **质量异常与形态变化分别标记**。
- **相邻锚点可能拍到同一菌包** ⇒ **未经去重不得累加为全层数量**。
- 群体指标变化只能叫**簇级形态变化**或**可测帽径分布变化**，**不得称为"同一蘑菇增长"**。

- **三层证据**：帧级（原图 ID/锚点/周期/质量/对齐/版本）、袋级（掩码/归属/基线/簇指标/有效性）、帽级（掩码/直径/资格/拒绝原因）。每个曲线点**可追溯到原图、掩码、基线与算法配置**。

| **G7** | **静态重复测试没有数据来源** | Plan §14.2-1 要"静态重复不应产生虚假增长"，但巡检 3 h 一轮、蘑菇一直在长 ⇒ **没有天然静止对** | 三种来源写死：① 同图重复推理（测确定性/随机性）；② **手动抓拍对**——console 实时模式 + ADR-0004 手动抢占可产出同站位**分钟级**重复帧，这是唯一真静止对；③ 相邻轮次弱替代（**必须标"弱"**）。票 19 §2.1 已出票，本规格只钉数据来源 |
| **G8** | **Plan 自身冲突：分组键 vs 相邻锚点拍同一袋** | Plan §5.5 的分组键是 `(observation_cycle_id, anchor_id, time_block)`，而 §11.3 明说**相邻锚点可能拍到同一菌包**。同一轮次 48 个站位时间差 <1 h ⇒ `anchor_id` 会把同一轮的相邻站位拆到两侧 ⇒ 同一物理袋一半进训练、一半进测试 ⇒ **近似泄漏、精度读数虚高** | 分组键升到 `(observation_cycle_id, round_id)`：**同一轮次全部站位必须同侧**（`round_id` 现成，ADR-0005 / CONTEXT「巡检轮次 ID」）。若确实要"未见锚点"测试，则测试锚点**连同左右相邻锚点**一起进测试侧。断言加一条 `no_adjacent_anchor_leakage()` |
| **G9** | **「前排」没有定义** | Plan §1.1/§7.2 只说"前排参与量测、后排不参与"，没说"前排"是几排、怎么划。现役 L1 实测同帧 **3–6 个深度排**，每排 **2–10 袋**（票 15 §12.1 逐排表） | 定义为「离相机最近、且**逐袋袋宽 CV ≤ 阈值**的 1–2 排」（判据取票 15 §12.2 已复核的"袋宽可分性"，**不是对比度**），并要求**逐锚点在模板里显式登记 `front_rows`**，不写全局常数 |

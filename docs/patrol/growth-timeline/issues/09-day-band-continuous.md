# 09. 天数刻度按入库日连续派生（整天无巡检时也要有带）

Status: implemented（2026-10-16；验收四条逐条核过，见 §4）
归属：前端（**后端一个字没改**，理由见 §4.1）
依据：spec 的「双刻度」决策（生长天数由 `batch.entry_date` 派生）；票 04 §4.5 记录的口径取舍
依赖：04（**同一文件 web/console/index.html**）

## 问题

票 04 的天数刻度只用端点给的 `rounds[].day` ⇒ **本批某一天一轮巡检都没有时，那一天的带不出现**。
x 轴仍是真实时间、空档看得见，所以不骗人；但**"这是第几天"这条第二刻度会缺格**——
而规格明确写的是「生长天数由 `batch.entry_date` 派生为第二刻度」，即**连续日历映射**，不是"有巡检的天才有刻度"。

票 04 当时的处理是"宁可缺一条带也不猜"，态度对；但**这里不需要猜**：入库日已知、当天日期已知，差就是天数。

## 交付物

1. 天数带按 `batch.entry_date` **连续派生**：整天没有巡检也照常出现那一天的带（带内没有数据点，如实空着）
2. 与票 04 已有的真实午夜边界保持**同一套映射**（别在页面上另立第二套天数口径）
3. 无头回归补断言

## 4. 交付记录

### 4.1 一个来源、一套映射（`web/console/index.html`）

`mdDayBands(points, entryDate, axis)` 从 "端点给了 `day` 的那些天" 改成 **按 `entry_date` 连续派生的日历映射**：
窗口里**每一天**一条带，`day = 日历日 − entry_date`（入库当天 = 第 0 天）。日期一律**只取 `YYYY-MM-DD` 前缀**
（`mdDayKey`），与端点 `analysis/timeline._as_date` / `day_of` **同一口径**——拿小时去算就成了第三套口径。

- **边界仍是真实午夜**：`startTs = 日历日 + 'T00:00:00'`，`endMs` = **次日**的本地午夜（不是 `+86400000` 硬加）；
  带宽 = 真实时长（18h / 24h 不是等分）。天数带与 `line.md-dayline` 由**同一个 `bands` 数组**生成、
  x 一律走**同一个 `mdScale(窗口)`** ⇒ 页面上只有一套比例，午夜线不可能与带宽打架。
- **空档如实空着**：带里没有数据点就不画点（不补 0 帧、不插值、不把邻点挪进去）——`null ≠ 0` 的老规矩一个字没动。
- **退化**：`entry_date` 认不出来（缺 / 格式不对 / `2026-02-31`）⇒ `mdDayBandsByEndpoint`（票 04 的老行为，
  **原样保留**）：只画端点给了 `day` 的天，`day` 也为 null 就整段不画。**不抛异常、不显示 `NaN`、不猜**。
- 覆盖面由 `mdDaySpan` 定：**窗口两端**（整批或刷选段，页面只有那一份窗口）；窗口时间戳认不出来时退回轮次自身范围。
- 画法与文案（图例 / 脚注 / 注释）同步改口径；新增 `data-date`（这条带盖住的日历日）与 `data-entry-date`（次刻度的原点）。
- **后端一个字没改**：`rounds[].day` 仍是数据事实（端点照给），只是页面不再**只**认它。

### 4.2 假后端新增（`docs/patrol/console-ui/verify-page.js`）

- `state.timeline_drop_day`：把某一天（`YYYY-MM-DD`）的轮次**整条拿掉**（明细与矩阵两条路走同一个 `covRoundsNow()`）；
  `axis` 两端**仍按全量**给 ⇒ 造的是"窗口中间整天没有巡检"，不是把窗口缩到只剩有巡检的天。
- `state.timeline_no_entry_date`：`batch.entry_date = null`（端点认不出入库日）。
两个开关**默认关**，开完即还原（末尾再读一次核对"六轮 + 四条带 + entry=2026-09-04"回来才放手）。

### 4.4 新增 8 条断言

1. **防漂移**：自己派生的天数与端点 `rounds[].day` 在两者都存在处**逐条相等**
   —— 每个轮次的 x 取覆盖条格子中心，落在哪条带里就取那条带的 `data-day` 与 fixture 的 `r.day` 比（6 轮逐条）。
   页面上有两个"第几天"的来源，这条把它们钉成一个口径（票面额外要求）。
2. 整天没有巡检的那一天，天数带**照画**（4 条带 = 6/7/8/9、每条宽 > 0、第 8 天 `data-date=2026-09-12`）
3. 空档那一天的带里**没有数据点**（5 个覆盖格都在这条带外，且没有 `data-frames="0"`）
4. 空档处的**真实午夜边界**还在（三条边界 = 09-11/12/13 三个午夜）
5. 天数带边界与真实午夜边界**逐条重合**（每条线 = 前带右端 = 后带左端，≤0.05px）
6. 空档那条带盖的就是那一天的**真实午夜区间**（x 由真实时间轴算出，不是等分摆上去）
7. `entry_date` 缺失 ⇒ 退化成票 04 老行为（6/7/9 三条带、`data-entry-date=""`、无 `NaN`）
8. 还原后再读一次：六轮 + 四条带 + 本批整段窗口都回来（假件开关不残留给后面的用例）

### 4.6 边界与交接

- **底部真实时间刻度的标签**跟着带一起变多：窗口里每个午夜一条（原来只有"有巡检的天"才有）。
  这是同一套映射的必然结果（几何一个字没改）；本批窗口 ≈ 25 天，与既有的"有巡检的天"数量同量级。
  要抽稀标签得先定"哪些标签可以省"的口径——本票不做，也不许为此另立第二套天数。
- 天数带区间取**窗口两端**：刷选到半截的一天时，那一天的带照画（被窗口裁掉的部分自然短）——
  "窗口里每一天一条带"在刷选后依然成立。
- P1 长势接入时**不要**再动这条刻度：`mdDayBands` 是第二刻度的唯一来源，新图元继续走 `mdScale()`。

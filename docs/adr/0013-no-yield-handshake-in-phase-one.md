# ADR-0013：一期不做"站间让位"，手动与定时靠时间错开

日期：2026-09-14
状态：已接受（**修订 ADR-0004 的一期范围**，其二期语义不变）

## 背景

ADR-0004 给手动与定时定了完整的互斥语义：实时模式要驱动同一台控制器，所以巡检守护必须在
**站间空程**让出控制权，该轮标记 `yielded`，退出实时模式后**从下一站位续跑**。

但代码里零实现（ticket 02 至今 `needs-info`），而且这条要求 `PatrolRound` 引入"从第 i 站开始"
的状态机——它是这堆工作里最容易做错、收益最小的一块。同时有一个被忽略的事实：

**守护进程只在"轮内"占用控制器**——`PatrolDaemon.run_cycle` 每轮连接、结束即 `close()`，
轮与轮之间控制器是空闲的。

## 决定

一期不做让位、不实现 `yielded`、不做半轮续跑。互斥改用**时间**解决：

| 情形 | 行为 |
| --- | --- |
| 轮与轮之间（占 96% 的时间） | 控制器空闲，操作者随时可在页面上接管手动控制 |
| 巡检正在跑（约 11 分钟） | 手动请求被拒，页面显示"巡检中，预计 x 分钟后可用"（不是排队、不是打断） |
| 任何时刻 | **急停可打断**，本轮作废并急停；这是安全底线，不受上面的规则限制 |

## 理由

按每 3 小时一轮、单轮约 11 分钟算，控制器有约 **94%** 的时间本就空闲。为一个不到 6% 的窗口引入
"半轮续跑"状态机，换来的复杂度与出错面（坐标系、站位游标、outbox 半截轮次）远大于收益；
而真正不能妥协的"随时能停"由急停覆盖。

## 后果

- ADR-0004 的让位部分**推迟到二期**，ADR-0004 的状态应标记为"部分实现"。
- `409 round_in_progress` 的语义简化为"巡检中，预计 x 分钟后可用"，不引入 `retry_after_s`
  排队重试。
- `rounds` 表**不引入 `yielded`**；轮次结局仍是 `ok/partial/failed/skipped`。
- 若二期要做让位，需要新增的是：让位通道（ADR-0004 默认 unix socket）、
  `PatrolRound` 的站位游标与"续跑"入口、以及 `rounds` 的 `yielded` 语义。

## 1. 意图识别

### 1.1 项目演进背景

上一阶段：离线图像处理——传统 CV + 大模型（现有 `mushroom` 项目：YOLO 按周龄分类菇体图像），已过时。
本阶段转向**库房内在线、定量、闭环**的新一代方案。

### 1.2 新系统要达成的三件事

1. **定量测量**：滑块相机在双轴导轨上运动，对库房完整巡检成像，对**每一框**蘑菇输出
   **平均菇体长度、菌盖直径**等定量参数（不再是"第几周"这类粗粒度分类）。
2. **数据分析**：生长参数时间序列 × 环境参数（温湿度、CO₂、光照等）时间序列做匹配分析，
   识别**不同生长阶段下环境参数与生长速率的对应关系**。
3. **参数寻优**：由分析结果反推**最佳控制参数区间**（分阶段的环境参数上下限），
   用于指导库房环境控制。

### 1.3 FMC4030 在系统中的角色

FMC4030 控制**滑块相机在双轴导轨上运动，从最佳拍照位逐框成像**——它是运动执行与
时序控制核心，但**不是**识别核心：

> 硬件事实（依据《FMC4030 控制器使用说明书 V2001》与《二次开发库详解》）：
> FMC4030 为 3 轴脉冲型运动控制器，无图像接口、无视觉函数；其自动运行脚本（.elo）
> 是顺序指令表（跳转/循环/IO/延时），**没有变量、没有运算、没有存储**。
> 因此图像采集与识别必然在**外部主机**完成，控制器只负责运动、IO 时序与安全。

### 1.4 交付边界

本文档交付**控制器编程设计**（运动程序 + 主机协同协议 + IO 分配），
以及识别测量、数据链路、分析方法的接口级设计。算法实现另行开发。

## 2. 系统架构

```
                    ┌─────────────────────────── 库房（高湿环境）───────────────────────────┐
                    │                                                                      │
  现有环控系统 ────▶│ 环境数据（温湿度/CO2/光照），可读取 ───┐                                │
                    │                                     ▼                                │
                    │  ┌────────────┐   ┌──────────┐   双轴导轨(X/Y) ─ 滑块：相机 + 补光灯    │
                    │  │ FMC4030    │──▶│ 工控主机  │◀──网线(拖链)── XCloud 相机             │
                    │  │ (脉冲+IO)  │   │ (Ubuntu) │                                      │
                    │  └────────────┘   └────┬─────┘                                      │
                    └────────────────────────┼────────────────────────────────────────────┘
                          ▲ TCP 8088 (DLL)   │ 识别结果/图像
                          │                  ▼
                    prod 服务器 10.77.77.39（时序库 + 分析服务 + 报表）
```

### 2.1 角色与职责

| 角色 | 职责 |
| --- | --- |
| FMC4030 | 回零、站位巡检运动（XY 插补）、到位稳定延时、IO 时序（补光灯/握手）、限位与软限位保护、（可选）脱机独立巡检脚本 |
| 工控主机（Ubuntu x86_64，Python） | 巡检任务调度、经截图服务采图、标定换算、菇体检出与测量（长度/盖径）、结果落库并同步 prod、与 FMC4030 的 SDK 通信与心跳 |
| 相机 + 补光灯 | **XCloud 网络相机**固定于滑块，网线经拖链回交换机；补光灯由控制器 OUT0 驱动；拖链走线 + 防护罩防护 |
| 截图服务（mushroom_cli / xcloudsdk_py） | 现成组件：HTTP `:7003/pool_capture` 采图（连接池复用 login/play 句柄）、直传 MinIO、MakeKeyFrame 防旧帧；巡检端只调 HTTP，不直接碰相机 SDK |
| 现有环控系统 | 温湿度/CO₂/光照数据的**来源**，可读取（接口形式在 P1 现场确认） |
| prod 服务器（10.77.77.39） | 时序库、生长-环境对齐分析、最佳参数区间计算与报表 |

### 2.2 控制器能力约束清单（设计依据）

| 项 | 规格/限制 | 设计对策 |
| --- | --- | --- |
| 轴数 | 3 轴控制器（X/Y/Z），200 kHz 脉冲 | **本机仅接 X/Y 双轴导轨，轴 2 不使用**（当前无 Z 轴） |
| IO | 4×DI（24V 低有效）、4×DO（开漏 300 mA）、6 路限位 | 见 §4.5 IO 分配表；大电流负载必须经中间继电器 |
| 通信 | 以太网 TCP（默认 192.168.0.30:8088）；**连接后 1 分钟无交互即断开** | 主机以 ≤30 s 周期轮询 `Get_Machine_Status` 兼作心跳 |
| 脚本（.elo） | 26 条指令：运动/等待/跳转/循环/IO，**无变量无运算** | 脚本只做固定位姿序列；一切动态参数由主机下发 |
| 单轴速度 | mm/s；参数掉电丢失，每次执行前需重设 | 主机每次任务前经 SDK 重设；脚本内也逐段重设 |
| 回零 | 限位开关回零（1=正限位/2=负限位），需设置脱落距离 | 脱落距离取 5 mm（避免停在限位上） |
| 软限位 | 正/负软限位，掉电保存（WorkStudio 参数页配置） | 现场标定后写入，取消则置负数 |

### 2.3 开发与部署环境

| 项 | 决定 |
| --- | --- |
| 主机系统 | Ubuntu（库房侧工控机，**x86_64**——两家厂商 .so 均只发 x86_64），**Python 开发**（沿用 `mushroom` 项目的 uv 管理习惯） |

| 相机与采图 | 相机为 **XCloud 网络相机**（登录 ip/user/pwd）；采图**复用现成截图服务** `mushroom_cli`（xcloudsdk_py：`libXCloudSDK.so` + ctypes，FastAPI `:7003`，`/pool_capture` 连接池，boto3 直传 MinIO，xvfb-run 无头运行；厂商 SDK 非线程安全 → 单 worker 串行；MakeKeyFrame+等帧防旧帧）。**巡检端不直接集成相机 SDK** |
| prod 服务器 | `ssh root@10.77.77.39`（密码见团队密码管理，不入仓库；建议改用 SSH 密钥，代码中凭据一律走环境变量） |

| 环境防护 | 相机与导轨采用**拖链走线 + 防护罩**，解决高湿腐蚀/结露主体风险 |

## 3. 运行模式设计

| 模式 | 触发方式 | 用途 |
| --- | --- | --- |
| **M0 手动调试** | 主机 Python 逐步调用（Jog/单站运动） | 装机、标定、示教站位、排障 |

## 4. 控制器程序设计（核心）

### 4.1 轴与机械参数定义

| 轴 | 机械 | 用途 | 回零方向 |
| --- | --- | --- | --- |
| 轴 0 (X) | 双轴导轨纵向 | 沿菇架通道定位 | 正限位（远离电机端） |
| 轴 1 (Y) | 双轴导轨横向 | 沿菇架层数/框位定位 | 正限位 |

轴 2 不接线（当前系统只有 X/Y 两轴）；"多角度"由固定双档相机支架实现（§4.4）。

速度/加减速分层参数（示例值，现场整定）：

| 档位 | 速度 mm/s | 加/减速 mm/s² | 用途 |
| --- | --- | --- | --- |
| 巡检 (travel) | 150 | 500 | 站位间空行程 |
| 接近 (approach) | 30 | 200 | 距目标站位 5 mm 段，降低过冲 |
| 回零 (home) | 20 | 200 | |
| 点动 (jog) | 10 | 100 | 手动调试 |

### 4.2 巡检主流程（M1，主机调度，伪代码）

```
connect(ip, 8088)                       # FMC4030_Open_Device
loop 每 30s: Get_Machine_Status          # 心跳 + 状态监视
for axis in [0, 1]: Home_Single_Axis(axis, 20, 200, 脱落5, 方向1)
等待 Check_Axis_Is_Stop == 1 (X、Y)      # 回零完成
for station in station_list:             # 站位表见 4.4
    Line_2Axis(id, 0x03, X_approach, Y_approach, 30, 200, 200)   # 接近段
    等待轴停
    Line_2Axis(id, 0x03, X, Y, 150, 500, 500)                    # 巡检段
    等待轴停
    delay(400 ms)                        # 机械振动衰减（现场整定 300–800 ms）
    Set_Output(OUT0=1)                   # 补光灯亮（曝光窗口开始）
    delay(150 ms)                        # 灯光稳定
    GET :7003/pool_capture               # 截图服务采图：MakeKeyFrame→等帧→抓图，
                                         # 典型 1–5 s，storage=cloud 直传 MinIO
    Set_Output(OUT0=0)                   # 采图返回（success 判定）后灭灯
    记录 (station_id, box_id, XY位置, 时间戳, 图像对象名) → 元数据
return_home()                            # 回原位，待机
```

时序注意：截图服务在连接池命中时单次采图约 1–5 s（含强制关键帧与等帧），补光灯窗口按
此量级预留；失败重试一次再记告警。巡检端与服务均为串行调用，天然匹配其单 worker 约束。

错误处理约定：任何 SDK 返回值 < 0（-1 连接失败 / -5 发送失败 / -7 接收错误 / -8 空指针）→
中止当前站位，记录告警，尝试重连（Close → Open → 重新回零一次），连续 3 次失败转人工。

### 4.3 M2 脱机脚本（.elo）示例

按《FMC4030 自动控制指令表》编写（指令名=WorkStudio 下拉项，坐标为 mm）：

```
行 1: 设置单轴运动参数 | 0 | 20 | 200 | 200      // X 回零参数
行 2: 启动单轴回零运动 | 0 | 5                   // X 回零, 脱离 5mm
行 3: 设置单轴运动参数 | 1 | 20 | 200 | 200
行 4: 启动单轴回零运动 | 1 | 5
行 5: 等待回零完成     | 0 | 1 | 0 | 0          // 等 X、Y
行 6: 延时等待         | 2000
行 7: 设置直线插补参数 | 30 | 200 | 200          // 接近段插补参数
行 8: 启动两轴直线插补 | 3 | X1接近 | Y1接近
行 9: 等待轴运行完成   | 0 | 1 | 0
行10: 设置直线插补参数 | 100 | 500 | 500         // 巡检段
行11: 启动两轴直线插补 | 3 | X1 | Y1             // 站位1 拍照位
行12: 等待轴运行完成   | 0 | 1 | 0
行13: 延时等待         | 400
行14: 本地输出口操作   | 0 | 1                   // OUT0 补光灯亮（相机侧计划快照窗口）
行15: 延时等待         | 1000
行16: 本地输出口操作   | 0 | 0
行17: 延时等待         | 500
行18: …（站位 2…N 同构；N 框 = N 组 行7–17）
行N+1: 启动两轴直线插补 | 3 | 0 | 0              // 回原位
行N+2: 等待轴运行完成   | 0 | 1 | 0
行N+3: 循环           | 1 | 999999              // 循环回行1, 近似长期自动
```

说明：
- 脚本内写死站位坐标，由标定/示教阶段生成（WorkStudio 编辑 → 编译 → `FMC4030_Download_File(type=2)` 下发 → `Start_Auto_Run`，亦可全流程由主机 Python 完成）。
- M2 模式下主机侧截图服务不可用，采图依赖相机自身计划快照（SD 卡）——**选型时确认 XCloud 相机支持**，否则 M2 只保运动、数据链路降级。
- 可选握手增强：在行 14 前插入 `长等待` + `本地输入跳转 | 0 | 1 | 行14`（IN0 下降沿=主机采图完成再关灯）。**边沿等待语义需现场向厂商验证**，故默认版本用固定延时。

### 4.4 站位表与"最佳角度"

站位表由主机侧配置文件管理（控制器脚本只是它的只读快照）。字段与
`patrol.stations.Station` 一致（`load_stations` 直接 `Station(**item)`，因此 **x/y 是两个
独立字段**，不是 `xy` 数组）：

```yaml
stations:
  - id: S01
    box_id: B01            # 对应库房第X架第Y框
    x: 1200.0
    y: 350.0
    angle_profile: top45   # top0（量盖径）| top45（量菇长）
    camera_ip: 192.168.x.x # 相机在交换机上的地址（截图服务按 ip 采图）
    camera_user: admin
    camera_pwd: ""
    exposure_note: manual  # 手动对焦/固定曝光（标定时锁定）
  - id: S02 ...
```

"最佳角度"的确定（本期方案，无 Z 轴）：
1. **安装固定双档角**：相机支架设计为"顶拍 0°（量菌盖直径）+ 侧斜 45°（量菇体长度）"两个档位，不做电动变角。
2. **示教标定**：M0 手动模式下逐框微调位置 → 对两档角做图像质量评分（清晰度/反光/遮挡）→ 择优存入站位表。
3. 控制器不参与"选角"决策，只执行坐标——保持控制器程序简单可靠。

### 4.5 IO 分配表

| 端口 | 信号 | 方向 | 说明 |
| --- | --- | --- | --- |
| IN0 | 采图完成握手 | 输入 | 主机采图完成拉低（M2 握手用，M1 可不用） |
| IN1 | 急停/门磁串联 | 输入 | 触发即跳转到安全停止段 |
| IN2 | 相机故障反馈（可选） | 输入 | |
| IN3 | 备用 | | |
| OUT0 | 补光灯 | 输出 | 经继电器驱动 LED 常亮/频闪 |
| OUT1 | 备用 | 输出 | XCloud 相机走 SDK 软触发，不使用硬触发 |
| OUT2 | 系统状态灯（绿=巡检/红=故障） | 输出 | |
| OUT3 | 备用（预留环境控制，如风机/加湿继电器） | 输出 | |

安全链：软限位（参数页写入现场标定值）→ 限位开关（每轴 ±）→ IN1 急停 → 主机看门狗
（连续 N 次心跳失败即 `Stop_Run`）。

### 4.6 主机侧 SDK 调用封装（Python + ctypes + Linux .so）

```python
class Fmc4030:
    def __init__(self, ip="192.168.0.30", port=8088): ...
        # cdll.LoadLibrary("libFMC4030_2009_1.so") + FMC4030_Open_Device
        # 返回值<0 抛 FmcError
    def heartbeat(self): ...          # Get_Machine_Status → dataclass(位置/IO/轴状态), ≤30s 周期
    def home_all(self): ...           # 逐轴 Home_Single_Axis + Check_Axis_Is_Stop（仅 X/Y）
    def goto(self, x, y, speed): ...  # Line_2Axis(0x03) 两段速(接近+巡检)
    def lamp(self, on: bool): ...     # Set_Output(0, on)
    def capture_at(self, station): ...# goto → delay → lamp → HTTP :7003/pool_capture → lamp off
    def close(self): ...              # 退出必须 Close_Device，否则重连失败
```

阻塞/非阻塞两套库并存：主机用**非阻塞版** + `Check_Axis_Is_Stop` 轮询，避免 TCP 阻塞卡死调度线程。

## 5. 识别与标定设计（主机侧接口级）

### 5.1 标定

- 每个站位固定 → **一次棋盘格标定**得到该站位 mm/px 与畸变系数；导轨重复定位精度保证标定长期有效（建议每季度复核）。
- 顶拍档测菌盖直径（圆拟合），45° 斜拍档测菇体长度（菇柄两端点投影 + 角度补偿）。
- IP 相机侧须锁定成像参数：**手动对焦、固定曝光/白平衡、固定分辨率**（自动模式漂移会破坏 mm/px 标定）；灯窗内拍摄保证照度一致。截图服务抓实时流帧，分辨率以相机主码流设置为准。

### 5.2 测量算法（替换旧"周龄分类"）

- 检出：分割/检测模型（可在现有 YOLO 数据基础上重标为实例分割），输出每朵菇的柄轴向与盖轮廓。
- 度量：标定换算为 mm；按框聚合：均值、P10/P90、样本数。
- 质量门控：模糊/过曝/遮挡帧标记 `quality_flags`，不入统计。

### 5.3 图像与元数据规范

```
图片对象名（MinIO / 本地）: {date}/{box_id}_{station_id}_{angle}_{HHMMSS}.jpg
   由巡检端生成 filename 参数传给 /pool_capture（服务端会自动补 .jpg 并校验路径）
元数据 JSON: {ts, box_id, station_id, xy, angle_profile, camera_ip, minio_url, file}
```

M2 脱机模式下采图依赖相机 SD 卡计划快照（选型确认），事后按时间戳对齐。

## 6. 数据链路与参数寻优（接口级）

```sql
measurements(ts, box_id, n, mean_len_mm, mean_cap_mm, p10_len, p90_len, quality)
environment (ts, zone, temp_c, rh_pct, co2_ppm, light_lux)   -- 从现有环控系统读取入库
```

环境数据接入：温湿度/光照/CO₂ 从**库房现有系统**读取——prod 可直接访问则由 prod 定时拉取；
仅库房局域网可达则由工控主机代读并随测量结果上报。接口形式（HTTP API / Modbus / 数据库直读）
在 P1 现场确认，分析层只依赖上面的 `environment` 表结构。

分析流程（每日批处理，跑在 prod 服务器上）：
1. 按框重采样为小时级生长曲线，差分得生长速率（Δlen/Δt、Δcap/Δt）。
2. 环境参数按同窗口聚合（均值/极差），与生长速率按生长阶段（按长度分段）分层。
3. 分箱对比/分位数回归：各参数区间内的平均生长速率 → 得出"速率最高且稳定"的区间，
   即**最佳控制参数区间表**：`(阶段 × 参数: 下限, 上限, 置信度, 样本量)`。
4. 输出为报表+API；本期**只建议不闭环**，环境执行器若后续接入 OUT3/现有环控系统，再扩展控制回路。

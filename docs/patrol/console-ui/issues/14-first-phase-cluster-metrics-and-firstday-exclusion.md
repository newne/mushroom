# 14 · 一期交付量的显示（菌簇长度/直径）+ 环境首日剔除的显式标记

**Status:** proposed（**只出票，未实现**——Chief 2026-10-14 明说"等契约落地后再动手"）
**归属（实现）：** `web/console/index.html` + `docs/patrol/console-ui/verify-page.js`（界面师）
**归属（我等的契约）：** ① **不确定度列**（测量侧 → analysis，归属待 Chief 指：测量师/环境官）；
② **首日剔除的显式标记**（环境官，`/api/environment` 及 summary/batches）。
**提出：** Chief 2026-10-14 转用户裁定。

## 1. 用户裁定（原话，不动一个字）

> 1) 一期交付量改成**菌簇平均长度与直径**（菌杆估算 / 菌帽预测降为探索项）——页面优先把这两项做清楚，
> 带量纲与不确定度，与实测值的视觉区分照旧。
> 2) 环境侧要**剔除入库首日**的温湿度：被剔除的那段在图上必须**显式标记**（如"首日剔除"），
> 不许静默消失——照你们"没有记录 ≠ 干净"的既有原则办。
> 3) 顺带：如果页面上还显示菌杆/菌帽的推算值，标清"探索项"，别让它看起来像交付量。

## 3. 我需要的契约（写清楚，别让我猜）

### 3.1 菌簇长度/直径 = **现有列就够**（票 18 §0 已定，不需要新增列）

票 18 写明：一期交付的"菌簇长度与直径"由**现有列**承载 ——
`mean_projected_d_mm`（投影径）/ `mean_cluster_w_mm` / `mean_cluster_h_mm` / `mean_area_mm2`。
页面要做的是**把它们显示出来并用对名字**，不是等新列。
**唯一要测量侧确认的是**："长度 / 直径"分别对应现有哪一列（`mean_cluster_w_mm`=长？`mean_cluster_h_mm`=高/直径？）——
**这层映射以测量侧定义为准，我不替它定名**（票 18 §1.2 也是这个态度：同一事实不许两个名字）。

### 3.2 不确定度：**没有新列**，页面只能显示"已有的区间"，不许自造

票 18 明确"一期**不需要新增列**"，而全库**没有** `±SD` / 置信区间列。
所以用户要的"带不确定度"，今天只能用已有字段**诚实地**表达：
- `p10_len` / `p90_len`（契约里已有）⇒ 显示成「**P10–P90 12.1–28.4 mm**」这样的**分位数区间**，
  **措辞必须写"P10–P90"**，不许写成「±8.2」——分位数区间与标准差是两种东西；
- `n`（已有）⇒ 标出样本量；**`n` 很小时弱提示**（阈值等测量师口径）；
- **字段缺失/NULL ⇒ 不显示任何区间数字**，按现有三种"空"的话术说清原因；
- **要真 ±SD/CI 就得新增列** —— 由 Chief/测量师定；在它落地之前，我不发明、不估算。

### 3.3 探索项：按**字段级标记**判，不写死列名（票 18 §2）

票 18 给了字段级标记：`estimated_fields`（`+` 分隔列名）+ 行级 `quality` 里的 `estimate`，
外加 `scale_source` / `mm_per_px` / `no_scale` / `unreliable`。页面的「探索项」标签**照这些字段判**：
某列在 `estimated_fields` 里、或该行 `quality` 含 `estimate` ⇒ 该值标「**探索项**」。
**不写死一张"哪些列是估算"的表** —— 那会与票 18 的标记机制漂开，也会在测量师改口径时静默变错。

### 3.4 环境首日剔除：等 `first_day` 标记（票 19 §2）

票 19 的实现提案：`first_day` **不落库**，读时按批次窗口派生（响应里**每行**带 `first_day: true/false`），
端点是新增的 `GET /environment/batch-series?room_id=&entry_date=&granularity=hour|day`。
⇒ 页面按**每行**的 `first_day` 画显式区间/底纹 + 「首日剔除」文字。
**拿到标记之前**：页面照原样画（宁可不剔，也不静默丢）。
票 19 §2 还留一个待裁项（(a) 入库时刻起算 24h vs **(b) 自然日**），**不影响页面**：
不管哪条，页面只消费 `first_day`。

## 4. 页面将怎么做（等契约落地后实施，先写下来免得走样）

1. **一期交付量放到最前**：环境/历史两处的测量块把"菌簇平均长度 / 平均直径"排在首位，
   **每格都必须带量纲**（`mm`，沿用 `unitLabel()`）；
2. **不确定度**：只显示**已有的 `p10_len`–`p90_len` 分位数区间** + `n`，措辞写「P10–P90」；
   字段缺失或 NULL ⇒ **不显示数字**，按现有三种"空"的话术说清"为什么没有"；
   **不写 `±`**（除非将来真有 SD/CI 列）；
3. **实测 vs 探索项**：实测值用正常字重；`estimated_fields`/`estimate` 指到的值 ⇒ 弱化样式 +
   「探索项」角标，并且**不进长势曲线的主线**（两种量纲绝不画进一条线）；
4. **首日剔除**：按每行 `first_day` 在曲线上画显式区间/底纹 + 「首日剔除」文字，并在图例里说明；
   拿不到标记时**照原样画**（宁可不剔，也不静默丢）——与"没有记录 ≠ 干净"同一条原则；
5. 「探索项」「首日剔除」两个词要进 `CONTEXT.md` 词表（Chief 归一后我按它写，不自造词）。

## 5. 可扫描断言（实现时必须逐条有）

1. **量纲跟数字走**：任何显示出来的菌簇量都带 `mm`；
2. **区间**：`p10_len`/`p90_len` 在场 ⇒ 文案含「P10–P90」且**不含 `±`**；
   字段缺失/NULL ⇒ **两种都不出现**；
3. **探索项**：`estimated_fields` 指到的列在场 ⇒ 文案含「探索项」，且**不出现在**长势曲线的主数据里；
   没被指到 ⇒ **不出现「探索项」**（防"一律标探索项"变成噪音）；
4. **首日剔除**：行上 `first_day: true` ⇒ 图上出现「首日剔除」且区间与标记一致；
   **没有这个标记 ⇒ 不出现这四个字**（防"假装标了"）；
5. **契约三件套照旧**：新字段进 `CONTRACT` 与 `PAGE_CONSUMES`；值可 NULL 的列**不进 `required`**；
6. **负向钉子**：页面不许把 NULL 渲染成 `0` 或空串，也不许自己编区间/不确定度。

## 6. 不做什么

- **不改数据**：不做服务端剔除、不改 `analysis` 的过滤逻辑（那是环境官的活）；
- **不静默丢行**：页面不为了"好看"过滤任何数据；
- **不把估算量当交付量**：不把探索项与实测值混排、不给它同等的视觉权重；
- **不自造不确定度**：没有 SD/CI 列就不写 `±`，只显示已有的分位数区间并写明是 P10–P90；
- **不动别的领地**：本票只改 `web/console/index.html` 与 `verify-page.js`（+ 本票）。

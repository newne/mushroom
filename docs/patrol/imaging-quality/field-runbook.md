> 这是 [field-checklist.md](field-checklist.md) 的**命令级配套**：清单说"做什么"，这份说"怎么敲、按什么判、先做哪一步"。

## 0. 前置顺序

非巡检窗口（**轮内 `goto`/`jog` 会被 409 拒**）→ ① **修灯 / 对焦（成像）** → ② 量 θ → ③ 逐层定相位 → ④ 把 Δz 写进档表、出镜像 → ⑤ `reanchor` 预演 / 落盘 → ⑥ 跑一轮 + 联系表复核。

**禁止用"改坐标"去修成像问题**（"全场发灰"已证是加湿水汽，不是锚点）。

## 1. 接管与命令骨架（console 实时模式）

建议用 `goto` **绝对坐标**，**不用 `jog`**（`jog` 的 `mm` 带方向符号，容易搞反）：

```
POST   /api/session                                            # 接管；TTL 300s，轮询 session_active 续期
POST   /api/cmd  {"kind":"goto","args":{"y":<站位 y>,"z":<候选 z>}}
GET    /api/cmd                                                # 轮询到 inflight:null = 到位
POST   /api/cmd  {"kind":"capture","args":{}}                  # 判据帧（抓图链路）
POST   /api/cmd  {"kind":"capture","args":{"no_lamp":true}}    # 对照帧：只差"灯亮/灯灭"
GET    /api/preview/frame.jpg                                  # 只看方向，**不作判据**
POST   /api/cmd  {"kind":"home"}  →  DELETE /api/session
```

**预览与抓拍不能逐像素互推** ⇒ **定档一律以 `capture` 帧为准**，预览只用来快速找方向。

## 2. θ 判定（放最前，约 10 分钟；它决定走哪条分支）

摆一根 **100 mm 竖直标尺**，与目标**同排同深度**，`capture` 一张。用该排**袋宽像素** + 已知物理宽（**240 mm**；若现场确认是另一朝向则用 **140 mm**）求该排局部 mm/px：

```
cosθ = 投影长(px) × 局部 mm/px ÷ 100mm
```

判据（2026-10-14 按测量师裁定更新，**三档 + 一道门**）：
- **θ ≤ 18°**：平行基本满足（投影项 ≤5%，低于分割噪声 7–8%）⇒ **走 §3**；
- **18–30°**：**相对趋势仍可用**，但**绝对 mm 必须带 `cosθ` 项**；
- **> 30°**：投影项 >13%（45° 时 29%）且遮挡/重叠加剧 ⇒ **只有要绝对值 / 跨站位比较时才进 §5 支架作业**。

**门（比 θ 更根本）**：**动不动支架不由 θ 单独决定**——相对长势里 θ 是恒定项（同站位同档），比值自动抵消 ⇒ **一期交付量（相对长势）不需要动支架**；真正需要"平行"的是**绝对 mm**与**跨站位比较**（不同站位 θ 不同）。所以量完 θ 之后要回答的是：**要不要绝对值 / 跨站位比较**。

两条配套：
- **不必改偏航**："按排局部标尺 + 远排弃测"够用——判据是"每个被测实例能找到**同排**菌包、且该排 `row_width_cv ≤ 10%`"；**CV > 10% 的排标 `unreliable`**。只有要"整帧一个数 / 跨排汇总"才需要缩深度跨度（那才动机械）。
- **换档必须重测**（至少重验一次投影比）：Δz 会改每个像元的俯角 ⇒ `cosθ` 与局部标尺按新档重建；**同档内不重测**，且同档内只比"**同排同档**"的量。

两种朝向假设**各算一遍**；若结论跨档 ⇒ **先确认卧放 / 立放**。测量师那份 θ≈25–29° 是**纹理透视反演**、残差大，**只作量级校验**，取值以现场竖直标尺为准。

## 3. 分支 A：只落观察高度档（逐层 5 mm 步距）

候选 z = 该层锚点 ± {0, 5, 10, 15, 20, 25} mm（**L4 向下只到 −212，即最多 −17 mm**）。

逐层循环：`goto 候选 z` → `capture` → 记（站位 / 候选 z / 帧名）。

**新鲜判据：画面主体是菇体侧影**——杆基到杆顶都在画面内、基部不被袋沿或前排遮挡；**不是**袋面相位、货架横梁/立柱、失焦近景、上一层货架底面。每层挑 1 个候选 z（**宁可稍微偏，也不要停在失焦/横梁相位**）。

产数：4 个 z ⇒ **Δz = z − 现锚点（−40 / −90 / −145 / −195）**；**|Δz| ≤ 25 mm**，超了该层就是超窗 ⇒ 转 §5。

⚠️ **这一步的产物是"4 个数"，不是"直接改配置"**：档表当前**只有默认档 `surface`（全 0）**，所以此刻 `--view-stage pin` 会**明确报错"未定义的观察高度档"**——那是设计，不是故障。把这 4 个 Δz 发给巡检手 → 写进档表（档名在 `surface / pin / stipe / cluster` 里挑最贴的）→ 发版官出镜像 → 才进 §4。

## 4. `reanchor` 预演 diff（判据逐条对）

```bash
BASE=/home/sysadmin/algorithm      # REG / TAG 见 z-frame-cutover.md §2
cp $BASE/mushroom_patrol/configs/stations.yaml $BASE/mushroom_patrol/configs/stations.yaml.bak-$(date +%Y%m%d)
docker run --rm -v $BASE/mushroom_patrol/configs:/app/configs $REG/mushroom_patrol:$TAG \
  patrol-migrate reanchor --stations /app/configs/stations.yaml --view-stage <档名> --dry-run
```

必须逐条对上：
1. 第一行打印"表里声明 `surface` / 本次指定 `<档>` ⇒ 生效 `<档>`"，且**已定义档名里有它**；
2. 每层"重锚前/后"：**只有该动的层 z 变**（= 锚点 + Δz）、**y 一个都不许动**；
3. 若有站点被列为"z 与该档锚点不一致（含现场示教值）"⇒ 正常，确认是自己教的；
4. 末行"落盘会有 N 个站位有改动"，N = 预期（需要动的层 × 12 框）；
5. **原文件未改动**。

落盘（去掉 `--dry-run`）后会备份并打印"观察高度档 `<档>` 已写回表"＋"**要重启 `mushroom_patrol`**"（console / 手动抓拍的"最近格点"归属是**启动快照**）。

## 5. 分支 B：θ ≥ 30° ⇒ 支架作业（顺序不能反）

① 停巡检、接管 → ② 支架作业（改**俯仰**＝真平行；或改**偏航**＝正对某排 ⇒ **y 锚点全部作废**）→ ③ **抓图链路重扫 z**（逐层 5 mm 步距，判据同 §3）→ ④ 落盘 `stations.yaml`（先备份、同盘 `cp+mv` 原子替换），坐标走 `reanchor` → ⑤ **物理角真变了之后**才改 `GRID_ANGLES` 标签并重出镜像（**反序＝照片顶着新标签、实际旧视角**）→ ⑥ 锁焦 / 固定曝光、建 `imaging_profile` 快照（含 `view_stage` + `observation_z`）→ ⑦ 重启 `mushroom_patrol` → ⑧ 跑一轮 + 联系表。**口径分界从生效日算。**

## 6. 联系表复核口径

```bash
python round-sheet.py --out <目录> [--since <日期>] --rotate 0 --thumb 400
```

逐层看：**每格主体必须是菇体（杆 / 盖 / 簇）**；出现袋面相位、货架横梁 / 立柱、失焦近景、上一层底面 ⇒ **该层不合格**。48/48 无失败格；失败格按标注原因处理，**不看"平均"**。

## 7. 成像 vs 取景（不许混）

- 补光灯照不到视野、半数帧失焦、曝光 / 白平衡未锁 ＝**成像**（改灯 / 对焦 / 锁参；判据看亮度 / 对比度 / σ / 清晰度）。
- **主体不是菇体 ＝取景**（改坐标）。

## 8. 对照帧到位后由巡检手与测量师定两条

① **投影比 ≈ 1**（θ ≤ 18° ⇒ cosθ ≥ 0.95）与**局部标尺口径**；
② **深度跨度**（近 / 远表观尺度差 ≥2 倍、远排对比度 ≈ 近排 1/4–1/5）是否还需"正对某排"——若"**按排局部标尺 + 远排弃测**"够用，就**不动偏航**。

## 1. 目标

给现场操作者一个界面，回答两个问题：

1. **实时模式**：我要把相机挪到某个位置拍一张——现在在哪儿、能不能过去、过去以后拍成什么样。
2. **历史模式**：这个位置以前拍过什么——它长什么样、这几轮有没有长大。

不做的事：不做连续视频预览（ADR 未立项，`capture` 只有单次抓帧）；不做巡检流程编排
（那是 M1 守护进程的职责）；不做图像分析与测量（那是 `measure` / `analysis` 的职责）。

## 2. 轴模型与运动参数（单源，ADR-0007）

本机是 **Y/Z 双轴**（**不接 X 轴**），虚拟坐标只有 `(y, z)` 两维，顺序恒为 Y 在前、Z 在后，
与 `Line_2Axis` 的 `endX`/`endY` 槽位对应。现场实测几何（`patrol.motion_profile` 单源）：

| 轴 | 轴号 | 行程 mm | 正方向 | 原点 | 目标速度 | 目标加减速 | 回零方向 | 回零速度 | 回零加减速 | 脱落距离 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| Y | 1 | 0 … 4492 | 向右 | 左端 | **150** | **1500** | 负限位（向左 / 反向，`homeDir=2`） | **90** | **900** | 5 |
| Z | 2 | -212 … 0 | 向上 | 顶端 | 20 | 200 | 正限位（向上，`homeDir=1`） | 20 | 200 | 5 |

（**2026-09-13 更正**：原表 Y 目标速度 50/500、Y 回零 150/1500、Z 回零 50/500 均为早期
整定值；现值为 `patrol.motion_profile` 的唯一真源，且有回归测试钉住。Y 回零速度 90 还有
一条下界约束：`≤ 4492 / (0.5 × homeTime 100s)`——回零太慢会在控制器自己的 100s 超时前
走不完全程。）

- **原点** = 「Y 反向（负限位）回零、Z 向上（正限位）回零」的落点，两轴都等于 `0.0`。
  行程都从原点单侧展开，于是坐标符号自带方向语义：**Y 增大 = 向右，Z 减小 = 向下**。
- **软限位包络 = 机械行程**（`Y 0–4492 / Z -212–0`）。越界目标在浏览器侧即拦下，
  下发控制器前还会被 `Fmc4030.check_travel` 二次拒绝。
- **两轴插补速度是合成量**（`Line_2Axis` 语义），按方向余弦折算
  `v_comp = min_i(v_i / |cos θ_i|)`，保证任一轴都不越自身上限——不让短行程的 Z 把
  长行程的 Y 拖慢。
- 接近段与点动无现场整定值，按目标速度/加减速 × 0.2 派生——**例外是 Y 点动**：它是
  显式覆盖的 `jog_ratio = 10/150`（10 mm/s、acc 100），因为"肉眼跟得上"是现场整定目标，
  按 0.2 派生会得到 30 mm/s。Z 点动走默认比例（4 mm/s）。
- **到位判据不是"控制器说到了"**：`goto` 分两段（先全速到接近点，再 30 mm/s 走最后
  5mm），然后**等停稳**（速度 < 1 mm/s 持续 0.2s）再读位置，偏差超过 `ARRIVAL_TOL_MM=0.5`
  抛 `TravelShortfallError`。控制器无位置反馈，"它报的位置"只是脉冲计数——所以
  **短停（计数器说走了、机构没走完）是一类独立的失败**，界面必须能把它和"相机失败"
  分开显示（见 §10.2 第 3 条）。
- 控制器侧另有一层整定参数（导程/细分/**软限位**/回零超时）不属于本文件管：出厂默认软限位
  仅 ±200mm，未整定时控制器会把 Y 目标**自行截断到 200mm 且返回成功**。`PatrolDaemon`
  **每轮连接后**都会 `check_soft_limits()`（ADR-0008），不过就断开、本轮判失败、一条运动
  指令都不发；M0 调试台有 `para` 命令可读回核对。这条状态要在界面上持续可见——它一旦
  不满足，机器看起来"完全正常"却什么都不做。

### 2.1 现场布局：12 框 × 5 层（`patrol.stations`）

| 维度 | 常量 | 取值 | 沿轴分布 |
| --- | --- | --- | --- |
| 横向 | `GRID_COLS` | **12** 框 | Y 0…4492 均分，框距 374.33mm，框心 `col_y(c) = (c−0.5) × 374.33` |
| 竖向 | `GRID_LAYERS` | **5** 层 | Z −212…0 均分，层距 42.4mm，层心 `layer_z(L) = −(L−0.5) × 42.4` |
| 角度 | `GRID_ANGLES` | `("top45",)` | 每框 1 个站位 → 共 **60** 个 |

- **层号自顶向下**：第 1 层贴近 Z 原点（z = −21.2），第 5 层在最下（z = −190.8）。
- **站位 id / 框 id 编码网格位置**：`S{层}{框:02d}` / `B{层}{框:02d}`（如 `S105` / `B105`
  = 第 1 层第 5 框）。列表、平面图、图像对象名三处看到的是同一个编号。
- 坐标**由行程推导**，不逐点手写 YAML——现场"框数随时会调"，改 `GRID_COLS` 一个常量即可，
  不用重标 60 行。`grid_geometry()` 把几何交给前端，避免两处各推一套。
- **蛇形遍历**：层内单方向走完、相邻层反向。不是美观问题——按层号顺序直走的话每换一层都要
  从最右端折回最左端（11 × 374 ≈ 4.1m 空程），5 层多跑约 16m；折返走法把这段空程降到 0
  （换层只动 Z 的 42.4mm）。这是**每轮都省**。

## 3. 部署形态

```
现场平板/笔记本  ──HTTP──▶  console（与 patrol 同机）
                              ├─ 静态页面 + 控制/查询 API（本规格 §6）
                              ├─ 进程内 → Fmc4030（ctypes，TCP 192.168.1.239:8088）
                              ├─ 回环   → capture :7003/pool_capture
                              ├─ 回环   → patrol 守护（让位握手，形态待定 §9）
                              ├─ 本地   → 图像索引 SQLite + outbox
                              └─ 出网   → prod :8000（已同步索引与测量值）
```

浏览器只认一个 origin（ADR-0003）；MinIO 不出现在浏览器可见的任何配置里。

## 4. 页面信息架构

单页 + 顶栏模式开关（现场操作员不该记两个网址）。

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ 蘑菇房巡检台   库房 A · 货架 12 框 × 5 层   [ 实时模式 | 历史模式 ]   状态药丸  │ 52px
├───────────────┬─────────────────────────────────────────┬────────────────────┤
│ 导轨平面图     │  主视区                                  │ 操作区              │
│ 12 框 × 5 层   │  实时：最新静帧 + 位姿读出 + 运动进度      │ 实时：急停/会话      │
│ (格线 = 货架)  │                                          │   坐标/点动/单轴/灯   │
├───────────────┤  历史：大图 + 缩放 + 时间轴 + 生长曲线     │                    │
│ 站位          │                                          │ 历史：日期/轮次/角度  │
│ (按层分组)     │                                          │   显示选项           │
│  第 1 层 12 框 │                                          │                    │
│  S101 … S112  │                                          │                    │
├───────────────┴─────────────────────────────────────────┴────────────────────┤
│ 事件与指令日志（等宽，自动滚到底，含 MinIO 对象名）                             │ 138px
└──────────────────────────────────────────────────────────────────────────────┘
```

- 左栏 **320px** / 右栏 320px / 中栏自适应；目标设备 1280×800 及以上，触控优先（按钮 ≥ 44px）。
  左栏从最初的 236px 加宽，是因为平面图要画 12 列 × 5 行，窄栏里点会挤成一排。
- 左栏是**固定头 + 滚动列表**两段：导轨平面图常驻（约 229px 高，不随列表滚走），
  站位列表独立滚动——因为"点位在哪"和"点哪个点位"是同一个决策的两个输入。
- 站位列表**按层分组**（5 组 × 12 框）。按框分组会得到 60 个单行分组，等于没分组；
  按层分组才与货架结构和平面图的行列一一对应。每行给站位 id 与坐标；
  单角度档时行内改显**相机 IP**（比重复 60 次"斜拍 45°"信息量大）。
- **急停常驻在右栏顶部，不随滚动隐藏**（ADR-0004）。
- 顶栏状态药丸文字取自 §6.1 的 `machine.state`：`待机（SCHEDULED）/ 让位中 / 手动（MANUAL）/ 已急停`。

## 5. 交互

### 5.1 导轨平面图（Y–Z，两模式常驻）

左栏顶部的 Y–Z 平面视图，画的**就是货架网格本身**：横向 Y 归一化到 0–4492mm 分 12 列，
竖向 Z 归一化到 −212–0mm 分 5 层，**第 1 层在最上**，每个格心一个站位点。
归一化而非按毫米真比例（`GET /api/status` 的 `envelope`）——Y 行程 4492mm 而 Z 只有 212mm，
按真比例画会退化成一条线。**Y 向右、Z 向上**。

- 静态层：隔层浅色带 + 11 条竖格线 + 4 条横格线 + 外框；底部标框号 1…12，左侧标层号 1…5。
  层带是为了让"5 层"一眼可数——只有格线的话容易看成一片均匀网点。
  格心与 `col_y` / `layer_z` 用的是同一套归一化公式，所以点必然落在画出来的格子里。
- 静态层：**蛇形遍历路径**（虚线折线）按 `build_grid` 的顺序连接 60 个格心，把"层内单向、
  换层同侧"的走法直接画出来。它是可断言的不变量：相邻两点要么同行、要么同列，
  **不允许出现斜向段**（斜向 = 横向空程）。
- 站位点是**唯一入口**：单击 = 选中该站位，与左栏列表双向联动（选中态、坐标栏同时更新）。
- 配色：蓝 = `top0`（顶拍 0°）、紫 = `top45`（斜拍 45°）；有失败帧的站位描红圈
  （与列表 `.warn` 同源，`<title>` 里说明是哪一层哪一框）。悬停显示
  `station_id / box / 第几层第几框 / 角度 / Y,Z mm / 帧数`。
  图例只列**数据里真实存在的**角度档——一期每框 1 档，就不摆注定筛出空结果的选项。
- **实时模式**叠加动态层：红色十字 = 滑块当前位置，虚线 = 当前位置到选中站位的余程连线，
  随 `job` 进度实时移动——这正是"我要把相机挪过去"的直观反馈。
  **历史模式**隐藏动态层（那里没有"现在"）。
- 图中标记只跟随**选中站位**，不跟随坐标栏的临时输入：图是"站位导航"，不是坐标编辑器。

### 5.2 实时模式

**进入**：点"实时模式" → `POST /api/session`。

- 成功 → 状态 `MANUAL`，**会话有效期 300s**，倒计时显示在操作区，任何一条运动命令都续期；
  到期或浏览器断开自动 `DELETE /api/session` 退回 `SCHEDULED`。
- 若守护正在巡检 → `409 round_in_progress`：界面进入 `让位中`，按 `retry_after_s` 自动重试
  （最长 30s），超时提示"轮次采图中，请稍候"。让位成功后日志记录"巡检已让位，本轮标记 yielded"。

**运动**（仅在 `MANUAL` 下可用）：

| 操作 | 命令 | 确认 |
| --- | --- | --- |
| 点站位列表 | 填坐标栏，不动作 | 无 |
| 移动到该点 | `POST /api/goto` | **二次确认**（显示目标与直线距离） |
| 点动 | `POST /api/jog`（步长 0.5/1/5/10 mm；Y 轴左右、Z 轴上下） | 无 |
| 单轴绝对 | `POST /api/abs`（轴选 Y 或 Z） | 无 |
| 回零 | `POST /api/home` | **二次确认** |
| 补光灯 | `POST /api/lamp` | 无 |
| 抓拍 | `POST /api/capture` | 无 |
| 急停 | `POST /api/stop` | **无（永远可点）** |

- 坐标栏实时做**软限位校验**（包络来自 §2 的机械行程）；越界立即标红并禁用提交——
  错误发生在浏览器，不下发到控制器。
- 运动期间右栏出现进度条与"运动中…"；`esc` 或急停可中断。
- **退出**：`DELETE /api/session`，退出流程固定为"先 `home` 再放开"（ADR-0004）。

### 5.3 历史模式

- 左栏选站位 → 中栏加载该站位的**倒序时间轴**（缩略图条）+ 大图查看器 + 该 `box_id` 的
  生长曲线（`mean_len_mm` / `mean_cap_mm` 叠在时间轴上）。
- 时间轴以日期分隔，缩略图角标显示 `HHMMSS` 与角度档；采图失败的那一帧画灰并标"失败"。
- 大图查看器：点击 / 滚轮缩放（1× / 2× / 4×），放大后拖拽平移，`适应`复位。
- 筛选：日期范围、角度档、轮次（`rounds` 表作刻度）；显示选项：叠加测量数值。
- 图像来源标注：`本地待同步` / `prod`（ADR-0006 双源合并）；对象缺失时显示"图像已不可用"
  并保留该行（ADR-0005 后果）。

## 6. HTTP 接口契约（console 侧，前缀 `/api`）

### 6.1 `GET /api/status` — 唯一的状态轮询口（1s）

```json
{
  "ts": "2026-09-10T16:32:07+08:00",
  "machine": {
    "state": "MANUAL",
    "connected": true, "ip": "192.168.1.239", "port": 8088,
    "real_pos": [1684.5, -21.2], "real_speed": [0.0, 0.0], "run_mode": "M0",
    "inputs":  {"IN0": 0, "IN1": 0},
    "outputs": {"OUT0": 1}
  },
  "session": {"id": "s-8f2a", "expires_in_s": 287, "operator": "现场"},
  "job": {
    "id": "j-19", "kind": "goto", "state": "running", "progress": 0.42,
    "target": [1684.5, -21.2], "elapsed_ms": 1830, "error": null
  },
  "patrol": {"active": false, "last_round_ts": "2026-09-10T09:15:00+08:00",
             "last_round_status": "yielded"},
  "envelope": {"y": [0.0, 4492.0], "z": [-212.0, 0.0]},
  "events": [
    {"ts": "2026-09-10T16:31:58+08:00", "level": "info",
     "text": "采图成功 S105 → 20260910/B105_S105_top45_163158.jpg"}
  ]
}
```

`job.state ∈ {queued, running, done, failed, cancelled}`；`events` 为最近 50 条，驱动底栏日志。
`real_pos` / `target` 的元素顺序恒为 `[y, z]`，与 §2 的轴顺序一致。
`envelope` 即 §2 的机械行程，前端据此做浏览器侧越界拦截。

### 6.2 命令端点

| 方法 | 路径 | 请求体 | 成功 | 失败 |
| --- | --- | --- | --- | --- |
| POST | `/api/session` | `{"password": "可选"}` | `202` | `409 round_in_progress` / `401` |
| DELETE | `/api/session` | — | `202`（内含 home） | `409` |
| POST | `/api/goto` | `{"y":1684.5,"z":-21.2,"speed":"travel"}` | `202 {job}` | `400` 越界 / `403` 无会话 / `409` 忙 |
| POST | `/api/jog` | `{"axis":"Y","dist":5.0}` | `202` | 同上 |
| POST | `/api/abs` | `{"axis":"Z","pos":-190.8}` | `202` | 同上 |
| POST | `/api/home` | `{"axes":["Y","Z"]}` | `202` | 同上 |
| POST | `/api/lamp` | `{"on":true}` | `200` | 同上 |
| POST | `/api/capture` | `{"station_id":"S105"}` | `202 {job}` | `503` 相机不可用 |
| POST | `/api/stop` | — | `200`（幂等） | 无 |

约定：**参数同步校验、执行异步**（ADR-0006）。`400` 只在参数非法时出现；机械时长不确定，
一律进 `202 + job`，进度由 §6.1 轮询获取。命令动词集与 `patrol-debug` 一一对应
（`status/home/jog/abs/goto/lamp/stop/para`），实时模式不新造控制协议。
`para` 是只读的整定参数核对（ADR-0008），实时模式不暴露写入口——改软限位只能在控制器参数页。

## 7. 图像索引（ADR-0005 落地形态）

patrol 本地 SQLite，采图成功/失败**立即**写一行；随 outbox（`kind:"image_index"`）→ prod
`/ingest` 同步，prod 侧同构表 + `INSERT OR REPLACE`（ADR-0001）。

```sql
-- 实现见 analysis/db.py（与 2026-09-10 那版草稿的差别：主键换成 (ts, station_id,
-- angle_profile)，去掉了 round_ts，补上了 camera_ip/cloud_url/坐标 与**库房三列**）
CREATE TABLE images (
  ts            TEXT NOT NULL,   -- 采图时刻（ISO8601）
  station_id    TEXT,
  box_id        TEXT,
  angle_profile TEXT,
  camera_ip     TEXT,
  y             REAL,            -- 拍下这张图时的**实际**位置（含 trim 与微调位移）
  z             REAL,
  object_name   TEXT,            -- MinIO 对象名；失败行为 NULL
  cloud_url     TEXT,
  ok            INTEGER,
  error         TEXT,
  room_id       TEXT,            -- 库房维度：多库房/多批次部署时必须能按行读出来
  entry_date    TEXT,
  batch_no      TEXT,
  PRIMARY KEY (ts, station_id, angle_profile)
);
```

**为什么没有 `round_ts`**：失败帧没有 `object_name`，用含 NULL 的列做主键会让幂等语义
含糊；而"这一轮"能从 `rounds` 表的时间刻度推出来。原型的轮次筛选要改成**按时间区间**
（或后端补一列 `round_ts`，那就要连带改主键——不建议）。

**库房三列是硬要求**（2026-09-13 修）：`patrol.daemon` 一直给每行盖 `room_id/entry_date/
batch_no`，但表里原先没有这三列，写入时被**静默丢弃**——照片在 MinIO 里、索引在库里，
却说不清属于哪间库房。老库靠 `analysis.db.migrate()` 就地补列（补出来是 NULL，
不编默认值）。

`object_name` 由 `patrol.stations.image_object_name` 生成——索引只是把它**记下来**，不改命名。
手动抓拍（实时模式）同样落索引（无轮次归属），这样"刚拍的那张"能立刻出现在历史里。

## 8. 前端技术选型

- **零构建**：一个 `.html` + 原生 JS 模块，无 node 工具链（仓库是纯 Python；工控机现场离线）。
- 依赖**必须 vendor 进仓库**（`console/static/vendor/`），不走 CDN：图表用 ECharts 或
  Chart.js，图片缩放自写（约 40 行，避免再引一个库）。
- 状态轮询是唯一的数据源，不做前端状态库；`api` 收敛成一个薄适配层，mock/真实实现可切换
  （原型里就是这个结构）。

### 10.4 手动控制的执行侧（2026-09-14 落地，ADR-0016）

页面上的每个动作，实际走的是这条链：

```
页面 → console（写 data/cmd） → patrol-serve（唯一持有控制器） → FMC4030 → 写回 result.json → 页面
```

几条与页面直接相关的语义（细节见 `docs/adr/0016-manual-control-execution.md`）：

* **巡检进行中**：除急停外一律 409，并带上"预计 x 分钟后可用"（`console.round_eta_s`）；
* **急停**：独立标志文件，不走指令队列，**能打断正在跑的那一轮**（等待原语被中止）；
  急停是**闩锁**——置位期间只有"关灯"和"再停一次"被放行，必须显式复位；
* **指令有新鲜度**：提交后 60 秒才被领走的指令不执行（手动操作是"此时此地"的动作）；
* **`capture` 不移动机构**：拍的是当前位置，站位号是操作者给的归属，记录里存实际坐标。

### 10.5 页面已落地的手动面（2026-09-14）

`web/console/index.html` 的右栏：急停（sticky，永远可点）· 接管/放开 + 会话倒计时 ·
坐标与定位（二次确认）· 回零（二次确认）· 点动（0.5/1/5/10）· 补光灯 · 抓拍（绑定选中站位）。
与 §5.2 的差异（**以代码为准**）：

| spec §5.2 写的 | 实际做法 | 为什么 |
| --- | --- | --- |
| 进入实时模式即 `POST /api/session`，到期自动 `DELETE` | **显式**「接管 / 放开」两个按钮，不会自动接管，也不会自动放开 | 自动接管 = 一次误入页面就拿到了动机构的能力；自动放开则要处理"页面关掉了"的判定，一期不做 |
| 让位握手（409 `round_in_progress` → 自动重试 ≤30s，"巡检已让位"） | **不让位**：巡检中直接拒绝并给出预计时间（ADR-0013） | 一期的巡检轮不可中断（除急停），"让位"是二期的事 |
| `job.progress` 进度条 | 只有"执行中…"+ 结果；进度条留给中栏的巡检进度 | 指令是异步文件通道，后端不知道运动百分比 |
| `POST /api/abs`（单轴绝对） | 不做 | 两个坐标框 + `goto` 已覆盖现场需要；少一条动机构的路径 |
| `esc` 可中断运动 | `esc` **只在有指令在飞时**发急停 | 空闲时误按会把急停闩上，之后每一轮巡检都失败——代价太大 |

## 11. 图像微调（第二步定位）：页面怎么呈现

**一句话**：走到推导坐标只是**第一步**（把目标送进视野），"目标真的居中"要靠**拍到的
图像**说话（第二步）。实现见 `patrol.framing`（闭环与安全边界）、
`measure.framing`（亮区质心），部署接线见 `deploy.framing_wire`。

### 11.1 闭环做了什么（页面要能解释它）

```
走到「站位坐标 + trim」→ 拍一张 → 量目标偏离画面中心多少 px
   → 在容差内？ 是 → 收工（就用这张）
                否 → 挪一小步（≤15mm）→ 再拍 → 最多 max_taps 次
   → 任何一步"没变好" ⇒ 退回**最好**的那个位置，用那张图
```

三条现场必须知道的约束：

* **找不到目标就一步不挪**（检测器说不确定、或置信度低）。宁可交一张"没居中但真实"的
  图，也不要基于猜测去挪 4.5 米的导轨。
* **不进步就回退**。方向配错（`sign_y/sign_z`）的表现就是"越挪越偏"，这条把它挡住。
* **trim 会累积写回站位表**：学过一次之后，下一轮直接从好位置起步，常规轮次**零额外耗时**
  （每多拍一张 = 每站多 5.2 s，60 站就是每轮多 5 分钟）。

### 11.2 页面增量

| 位置 | 内容 |
| --- | --- |
| 站位列表行 | 有 trim 的站位加一个小标记（如 `⇥2.5`），悬停显示 `trim_y/trim_z`、学到的时间、`trim_note` |
| 实时模式操作区 | 「微调这一站」按钮：在该站位跑一次闭环（需要 `MANUAL` 会话）。跑的时候显示每步的 `tap / 偏移 px / 步长 mm`，随时可急停 |
| 中栏主视区 | 微调过程中显示**当前这一步**的帧（不是最后一张），让人看清它在往哪挪 |
| 底栏日志 | 每次闭环一行：`S506 微调 2 步 → trim (8.5, -3.2) 已居中` 或 `S506 微调放弃：这一帧没找到目标（亮区只占 1.2%）` |
| 历史模式 | 每张图旁标出**拍摄位置**（`y/z`，含 trim 与微调位移）——同一站位不同位置拍的图不该被当成同一视角 |

### 11.3 接口

## 12. 生长判断（与上一时间点比）：页面怎么呈现

**一句话**：`measure` 给的是一次测量的数，`analysis.growth` 给的是**判词**——
"这一框跟上一个时间点比，长了没有"。

### 12.1 判词（页面直接用，不要自己拼文案）

| 判词 | 文案 | 触发条件 |
| --- | --- | --- |
| `growing` | 在长 | 速率 ≥ 0.1 mm/h |
| `stalled` | 基本没长 | 速率在 ±0.1 mm/h 内，**且**间隔 ≥ 30 分钟 |
| `shrinking` | 比上一时间点更短（看图核对） | 速率 ≤ −0.1 mm/h。菇不会变短 ⇒ 多半是口径变了（换角度档、镜头脏、被遮） |
| `interval_too_short` | 距上一时间点太近，看不出趋势 | 间隔 < 30 分钟——**不下"停滞"结论**，否则半夜误报 |
| `not_comparable` | 两次测量不可比 | 任一端检出朵数 < 2，或没测到长度，或时间戳不可解析 |
| `no_prev` | 没有上一个时间点 | 该框只有这一个点 |

阈值都在 `analysis.growth` 的参数里（`stall_mm_per_h` / `min_span_h` / `min_n`），
要改就改那一处，别在页面上再写一套。

### 12.2 页面增量

| 位置 | 内容 |
| --- | --- |
| 历史模式·生长曲线 | 每个测量点旁标判词色块；`shrinking` 与 `not_comparable` 用**警示色**而不是"持平色" |
| 历史模式·点选某点 | 显示"距上一个时间点：+6.0 mm / 12.0 h / 0.50 mm·h⁻¹（在长）"，以及**上一时间点那张图**做左右对照 |
| 首页/顶栏（库房级） | 「本库房今日：N 框在长 · M 框基本没长 · K 框异常」——`/growth/room` 的 `counts` 直接给 |
| 左栏站位列表 | 按判词排序/筛选（"只看没长的"），这是每天真正要巡的东西 |

### 12.3 接口

```
GET /api/growth?box_id=B101&limit=50   → {box_id, points:[每次对比一行], latest}
GET /api/growth/room?room_id=611       → {n_boxes, counts, boxes:{B101:{…判词…}}}
GET /api/growth/room?boxes=B101,B102   → 显式指定框清单
```

`/growth/room` 在给了 `room_id` 时会从**图像索引**里取该库房的 `distinct box_id`：
"拍了但还没测量值"的框也会以 `no_prev` 出现在列表里——现场最怕列表里**少**几个框，
那分不清是"没长"还是"没拍"。

### 12.4 还没接的一环（先说清楚）

`measurements` 目前是空的：`PatrolDaemon(measure_fn=None)` ⇒ 只落 round 行与图像元数据。
真正的检出（`measure.Detector` 的模型实现，票 05）到位后，把 `measure_fn` 接上即可——
从 `round` 报告取帧 → Detector → 按框 `aggregate_box` → `MeasurementRecord.from_box_stats`
→ 随 outbox 进 `/ingest` → 本节的判词立刻就有数据。**页面可以先按本节实现**（空数据时
全部显示"没有上一个时间点"，这是诚实的结果）。

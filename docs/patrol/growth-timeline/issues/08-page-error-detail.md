# 08. 页面错误态：显示上游 4xx 的原因（别把参数错误说成"不可达"）

Status: ready-for-agent
归属：前端
依据：票 07 §已知边界 3；票 02 交付的页面取数路径
依赖：03（**同一文件 web/console/index.html**）

## 问题

页面取数用 `jget`：**见非 2xx 就抛，不读 body**。于是上游（analysis）回的 400 到了页面上只剩：

> 查不到覆盖轨迹 ⚠ 覆盖轨迹接口**不可达**：… HTTP 400

状态码是如实的，但**把"客户端请求有问题"说成了"连通性错误"**，而且真正的原因（`detail`/`notes`）被丢掉了。
票 07 已经保证**状态码与信封原样透传**（400 就是 400、错误体一字不改）——所以原因就在手里，是页面没读。

## 交付物

1. `jget` 在非 2xx 时**读 body**，把其中的原因（`detail` / `notes` / `error`）显示出来
2. 文案区分两类：**请求有问题（4xx）** vs **连不上 / 服务异常（5xx 与网络故障）**——现在两种都叫"不可达"
3. 无头回归补断言

## 验收（缺一条不算过）

- [ ] 上游 **400** 时页面显示**上游给的原因**，不是笼统的"接口不可达"
- [ ] **4xx 与 5xx/网络故障的文案分得开**（把 4xx 也说成"不可达" ⇒ 断言变红）
- [ ] body 为空或非 JSON 时退化成现有文案，**不抛异常、不显示 `undefined`**
- [ ] 零新前端依赖

## 不做什么

- 不改 BFF（票 07 已交付原样透传）
- 不改 `/timeline` 的契约

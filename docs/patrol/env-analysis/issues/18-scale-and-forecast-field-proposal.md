# 18 — 字段提案：菌杆平均长度 / 簇长势 / 菌帽后续长度（预测）+ 尺度基线

**Spec:** ../spec.md §2.2、§2.7、§5；票 11（measurements 契约）、票 16（长势量口径）

**状态：定稿（待测量师对齐）。** Chief 2026-10-14 已裁定 §6 的 4–9 条；用户原始定义回来后
如与暂定口径冲突，只改被改到的那几处并标注日期。**不动 DDL、不改代码。**

**任务来源（用户 2026-10-14）：** 测量侧新增三个量 —— 菌杆平均长度、簇长势、
菌帽后续长度（预测）；尺度基线 = "**用菌包直径做帧内标尺反推 mm/px**"。

## 0. 一句话结论

三样里**只有"簇长势"是测量量**；"菌杆平均长度"在平视单档下是**估算**（票 11 §9 判过它缺测），
"菌帽后续长度"是**预测**。本票的核心不是加几列，而是**把"测量 / 估算 / 预测"在字段层分开**，
让任何下游（区间表、建议层、页面）都不可能把后两者读成第一种。

## 1. 三个量

### 1.1 菌杆平均长度（估算）

| 项 | 值 |
| --- | --- |
| 列名 | **复用 `mean_len_mm`**（不造 `stem_len_mean_mm` —— 同一事实不许第二个名字） |
| 单位 | mm |
| 性质 | **估算**：必须带 §2 的标记（`estimate` / `estimated_fields` / `scale_source`） |
| NULL 语义 | 没算出、没有标尺、或被判 `unreliable` ⇒ **NULL，不写 0** |

与票 11 §9 的关系：§9 说"平视下杆长明确缺测、禁止用平视近似**冒充**测量"。本票给它开的是
**合法出口**：① 显式标注来源是标尺反推；② 下游不吃它。**缺任一条就是 §9 要禁止的那件事。**

### 1.2 簇长势 v1 = **菌簇占地范围**（provisional，Chief 2026-10-14）

| 角色 | 量 | 列 | 单位 | 缺什么会算不出来 |
| --- | --- | --- | --- | --- |
| **主动量** | 分割实例**外接框面积** | `mean_bbox_area_mm2`（**提案新列**） | mm² | 无 `mm_per_px` ⇒ **NULL**（裁定 6：**不许**退化成像素量）；远排/低置信 ⇒ NULL + `unreliable` |
| **辅量** | 实例数 | `n`（已有） | 个 | 整簇不可分（如整帧回退）⇒ `n=0`，**不可信** |
| **派生** | 相对上一轮变化率 | 不进 `measurements`（`growth`/`ranges` 算） | mm²/轮 或 %/轮 | 上一轮缺测、或两次量不同 ⇒ 算不出 |

- **`mean_bbox_area_mm2` 是否真的要新列，取决于测量师**：如果他的 `mean_area_mm2` 本来就是
  外接框面积（而不是掩膜面积），那就**不新增列、只补语义**（列注释写明是 bbox 面积）。
  **这条写进对齐清单**（§6.7）——同一事实不许两个名字，也不许同一个名字指两种面积。
- **`unreliable`（新 quality flag）**：远排 / 低置信导致该量不可信 ⇒ 值写 **NULL** +
  `quality` 带 `unreliable`。处置 = **不可用**（与 `no_light` 同级），**不是降权**。
- 变化率沿用票 16 的老规矩：**两点同时有值、同一 `metric` 才比**；异量或单侧缺测 ⇒ 不给速率。

### 1.3 菌帽后续长度（预测，provisional）

**固定目标时点**：未来 **3 天**、未来 **5 天**（这两条照排）；**"到采收日"那条不排期** ——
2026-10-14 实测 `mushroom_batch_yield.harvest_time` 填充率 **0/27** 且没有任何写入路径
（证据见 §6.3），**待有填充来源后再排**。放在**单独一张表**（§3），不混进 `measurements`。

## 2. "估算 / 预测"的表达（**绝不与 `verified` 混**）

| 列（`measurements`） | 类型/单位 | NULL 语义 | 说明 |
| --- | --- | --- | --- |
| `scale_source` | TEXT 枚举 | NULL = 没记 | `bag_diameter`（菌包直径做帧内标尺）/ `calibration_target`（已知尺寸靶标）/ `none` |
| `mm_per_px` | REAL，**mm/px** | NULL = 未知 | **实际用的比例**。有它，任何 mm 值都能复算/复核；没有它只能是估算 |
| `scale_ref_mm` / `scale_ref_px` | REAL | NULL = 没记 | 参考物真实尺寸与帧内像素尺寸（如菌包直径）；`mm_per_px ≈ scale_ref_mm / scale_ref_px`，可交叉验算 |
| `estimated_fields` | TEXT，`+` 分隔列名 | NULL/空 = 无估算值 | **字段级**：如 `mean_len_mm`、`mean_len_mm+mean_bbox_area_mm2` |

**过滤规则（写给所有下游）：**

> 引用 `measurements` 的字段 X，必须同时满足 **`quality` 含 `verified`** **且**
> **X ∉ `estimated_fields`**。不满足的值只能**展示/探索**，
> **不得**进区间表、建议层或任何统计。

**行级 fail-safe flag `estimate`（进 `quality` 串）：** 只要 `estimated_fields` 非空，
`quality` **必须**含 `estimate`。这样只看 `quality` 的消费者（现有的和将来的）也不会
把估算读成测量。**`estimate` 与 `verified` 正交**（像 `no_angle_profile`）：它不否定整行，
但 `estimate` 单独出现**绝不算可用**。

**本票引入的三个 `quality` flag（行级；与 `estimated_fields` 配合）：**

| flag | 何时出现 | 处置 |
| --- | --- | --- |
| `estimate` | 该行有**任何**估算值（`estimated_fields` 非空） | **正交**：不否定整行；被 `estimated_fields` 指到的字段**不可用**（不进统计/建议） |
| `no_scale` | **缺标尺**（`scale_source='none'` / `mm_per_px IS NULL`，Chief 2026-10-14 口径） | 所有 mm 量写 **NULL**（裁定 6：不许退化成像素量）；该行只可能承载实例数等无标尺量 |
| `unreliable` | 远排 / 低置信（判据由测量师定） | 涉及的量写 **NULL**、**不可用**（与 `no_light` 同级，不是降权） |

命名对齐：**列里放描述值（`scale_source='none'`），`quality` 里放行级 flag（`no_scale`）** ——
与 `no_angle_profile`（列是 `angle_profile`）同一模式：只看 `quality` 的消费者不会漏判。

**为什么不做"整行拉黑"**：平视下杆长恒为估算，整行拉黑等于清空区间表 —— 和删数据没区别
（票 11 §3 的同一教训）。

## 3. 预测：菌帽后续长度 —— 单独一张 `forecasts`（提案）

| 列 | 类型/单位 | NULL 语义 | 说明 |
| --- | --- | --- | --- |
| `predict_at` | TEXT ISO8601 | 必填 | **预测时点**：做出这次预测的时刻（= 输入数据截至时刻） |
| `target_at` | TEXT ISO8601 | 必填 | **目标时点**：预测指向的未来时刻（3 天 / 5 天 / 采收日） |
| `room_id` / `box_id` | TEXT | 必填 | 与 measurements 同口径 |
| `metric` | TEXT | 必填 | 预测哪个量（如 `mean_cap_mm`） |
| `value` | REAL | 必填 | 预测值（单位随 `metric`） |
| `model_version` | TEXT | 必填 | **模型版本**（含版本号/训练批次） |
| `inputs_from` / `inputs_to` | TEXT | 可空 | 输入数据起止（便于回放） |
| `note` | TEXT | 可空 | 备注 |

- **幂等键 = `(room_id, box_id, metric, target_at, model_version)`**：同模型同目标重复预测 ⇒ 覆盖；
  不同模型/不同目标 ⇒ **并存**（预测本来就有多条）。
- **隔离铁律**：预测值**永远不进** `measurements`、**永远不进** `verified` 统计；
  任何读 `mean_*_mm` 的路径都**不许回退**到 `value`。分表就是为了让"只吃 verified"那层
  过滤不被预测污染。
- 展示必须**三个一起**：值 + `target_at` + `model_version`（缺一个都会被误读成测量）。

## 4. 幂等与兼容

- `measurements` 主键不变 `(ts, room_id, box_id)`；新增列随行覆盖写。
- 加列走 `ADDED_COLUMNS` 就地迁移，老行 NULL = "那时还没记"。
- **顺序照旧：先落列 → 测量师发字段 → 下游启用过滤**（票 11/17 的既有纪律）。
- **落列时机（Chief 2026-10-14）**：等测量师的 **L1–L3 代码**出来再定 —— 他那边已获准开工，
  **不训练模型**，**缺标尺时写 NULL + `no_scale`**。所以在 L1–L3 定型前，本票只作为契约待命，
  **不落 DDL**（避免列名/口径先落地、后被他的设计改一遍）。

## 5. 与其它票的关系

- 票 11 §9（平视缺测）：本票是它的**合法出口**，不推翻它。
- 票 16（长势判定）：变化率的"两点同时有值、异量不相减"照旧；`metric`/`unit` 必显示。
- 票 17（内容完整性）：被排除的轮/帧照旧不进统计；估算标记与它是两个正交维度。

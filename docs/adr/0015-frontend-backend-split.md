# ADR-0015：巡检台前后端分离——页面是独立产物，后端只做 API 与代理

日期：2026-09-14
状态：已接受
背景：ADR-0003 把 console 定为一个部署单元，由它同时提供静态页面与控制/查询 API。落地后页面
被塞进 `deploy/src/deploy/static/index.html`，再由 Python 进程读文件返回。这带来三个问题：

1. **控制面接口与前端代码混在一个发布物里**。改一行 HTML 要重建后端镜像；页面回归与后端回归
   绑在一起，无法分别部署、分别回滚。
2. 后端承担了它不该承担的职责：静态文件分发（缓存、MIME、压缩）用 Python 做，既没人做得比
   nginx 好，也把"API 进程"这个安全边界撑大了。
3. 前端产物在 Python 包里，构建期要额外 `COPY static` 进镜像、再配 `PATROL_STATIC` 环境变量，
   是为打包而打包。

## 决定

- **前端是独立产物**：页面、样式、脚本放仓库根的 `web/console/`，由 nginx 服务，**不经过 Python**。
- **后端只提供 `/api/*` 与 `/healthz`**：`mushroom_console`（`deploy.console`）不再有 `/` 路由、
  不再有 `static_dir`、镜像里不再有静态文件。
- **单一 origin 用反向代理接回来**：nginx 把 `/api/` 代理到 `mushroom_console:8001`，浏览器仍然
  只看到一个 origin（ADR-0003 的约束不变，实现方式从"Python 返回页面"换成"nginx 同源代理"）。
- 前端是被服务方，**不持有任何巡检控制逻辑**：命令一律 `POST /api/cmd`，前端不知道控制器、
  SDK、库房主机路径的存在。

## 决定理由

- 拆分后两侧可独立演进：调页面不必重建后端镜像，改 API 不必碰页面；现场排障时"页面空"与
  "接口 500"能一眼分开。
- 反向代理把 CORS、缓存、压缩这类问题交给 nginx，后端保持纯粹的 JSON 边界。
- 控制面收敛在唯一一处后端，是本项目反复强调的边界（ADR-0011：`patrol` 不发网络调用；
  控制只能经由部署侧），前端不应成为第二条通往控制器的路。

## 后果

- 部署多一个容器 `mushroom_console_web`（nginx:alpine，只挂 `web/console/` 只读），端口 8002；
  上位机访问 `http://<服务器IP>:8002/`。
- `web/console/` 的页面用相对路径 `api/...` 取数，因此换端口、换主机名都不需要改前端。
- 后端 API 的契约测试不再覆盖页面；页面正确性由 `docs/patrol/console-ui/verify.js`（jsdom 回归）
  与现场验收负责。
- 只暴露一个 origin 的结论仍成立，但**"console 是唯一对外服务"这条要更正**：对外的是前端
  容器，后端 8001 只应被前端容器与调度侧访问。

## 实测数据（2026-10-13 15:0x，生产 10.77.77.39）

`mushroom_preview`：镜像 tag `registry.cn-beijing.aliyuncs.com/ncgnewne/mushroom_patrol:station-calibration-20261008-l3z132-l4z155-c08y40`，
容器 2026-10-08 17:59 起，`restarts=53`、`uptime_s≈421084`（≈4.87 天）。

**先排掉一个误读**：53 次重启**不是**均匀分布——**52 次挤在 2026-10-09 一天**：

| 日期 | `启动转码`（含首启） | `转码退出` |
| --- | --- | --- |
| 2026-10-08 | 1（首启） | 0 |
| 2026-10-09 | 52 | 52 |
| 2026-10-12/13 | 1 | 1 |
| 合计 | 54 | 53 |

### 事件 A：2026-10-09 17:11:59 → 18:32:23（≈80 分钟）链路中断，自动恢复

该窗口 52 条 `转码退出` 的原因分布：

| 原因 | 条数 |
| --- | --- |
| `Error opening input files: No route to host` | 45 |
| `画面停滞 10 秒（ffmpeg 进程还在、但没有新帧…）` | 4 |
| `Error opening input files: Connection refused` | 2 |
| `Error opening input file rtsp://admin:***@192.168.1.238:554/Streaming/Channels/101` | 1 |

- 起点 17:11:54 第一声 `画面停滞`（1253164 帧后不再出帧）→ 17:11:59 第 1 次退出。
- 之后转为 `No route to host` ⇒ **EHOSTUNREACH**（网络层到不了相机 192.168.1.238）。
- 退避 1→2→…→10 s 全程生效；第 52 次退出在 18:32:23，18:32:33 重启成功。
- **关键旁证（反证"相机整体挂了"）**：同一时段巡检轮次 **18:20:02 → 18:27:34，48/48、0 失败**
  （`data/runs/20261009-182002-1.jsonl`）。⇒ 预览容器到相机**这条路**当时不通，而宿主侧的采图
  服务同一时刻拍得成。不是 DVR 整体不可达，是 (预览容器 → 相机 RTSP) 这条路径/会话的问题。
- 恢复是自动的，代价是**这 80 分钟没有实时画面，且没有任何告警**（现场当时没人看着，所以没人报）。

### 事件 B：2026-10-13 03:05:28 静默停滞——看门狗首次实战，≈20 秒自愈

```
03:05:28 ! 画面停滞 10 秒（ffmpeg 进程还在、但没有新帧：5665775 帧后就没有了），换掉这个 ffmpeg
03:05:33 转码退出（第 53 次），10 秒后重试：…
（随后 启动转码 成功）
```

这正是 ADR-0017 补记/§17 那一类（对端不关连接、ffmpeg 挂在一次读上：0 CPU、无输出、无错误），
也验证了 `_watchdog` 修复有效：**从卡死到画面恢复 ≈20 秒**。同类故障在 2026-09-29 曾让预览
黑了 5 天 6 小时（当时 `restarts=0`）。

## 要做的事

- [ ] **事件 A 的 RCA**：解释"预览容器 EHOSTUNREACH 而宿主采图同时成功"。入手点：容器在 bridge
      网络经宿主 `eno1` 出网，与宿主进程的网络路径不同（NAT / conntrack / RTSP 长连接）；查
      10-09 17:12–18:32 的 DVR 侧会话/连接数限制、宿主 ARP 与 conntrack 记录、同时段是否有别的
      消费方占满相机会话。
- [ ] **要不要"更早的探针"**：现在只有 ffmpeg 退出或停滞才发声，画面断了 80 分钟没有任何告警
      （2026-09-29 那次同理）。判据用什么（帧龄阈值 / 连续 N 次退出 / 别的）由你定。
- [ ] **要不要给 RTSP 加读超时**（ADR-0017 补记三的 `-timeout <微秒>`）。当时不采用是那个时点的
      取舍；事件 A 之后值得重新评估。上机前先按补记三的一次性容器命令验一遍。
- [ ] **`-loglevel` 是否提到 `info`**：现在 `warning`，静默类故障不留痕（事件 B 是靠看门狗才留痕的）。
- [ ] 若判定需要改代码：改动落在 `deploy/src/deploy/preview.py`；发版动作（重建 `mushroom_preview`，
      `--force-recreate --no-deps`）由发版官执行，动手前走发布确认。现役预览参数已核：容器内
      `PREVIEW_SCALE=1280` / `PREVIEW_FPS=15`，真实命令 `-vf scale=1280:-2 -r 15 -q:v 7`。

## 不做的事

- 不为本票做任何现场动作（含"顺手重启一下预览"）。
- 不把 53 次读成"每天都会重启十几次"——52 次属于同一次中断。

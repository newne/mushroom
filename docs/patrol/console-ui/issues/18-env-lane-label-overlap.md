# 18. 环境模式泳道标签字体重叠修复

Status: implemented（2026-10-15；验收三条逐条实测，见 §4）
归属：前端
依据：只读侦察（2026-10-15）定位到唯一确定性成因
依赖：—

## 1. 交付物

1. 泳道内两个标签的纵向偏移改为**从车道高度派生**，不再硬编码（车道高度被压缩后两者基线只剩 4px ⇒ 必然叠字）

## 2. 验收（缺一条不算过）

- [x] 两个标签的基线间距 ≥ **14px**（车道 54 时 14.04 用户单位；行距下限 14px 兜底）
- [x] 在 **1366×768** 真机截图里不重叠（Chrome headless 1366×768 实测，见 §4）
- [x] 车道高度再次变化时**不会复发**（44/54/64/76/96 都 ≥14px，且偏移随高度走）

## 3. 不做什么

- **不**顺手改另两处疑似溢出（缺真机截图，凭推断改会把没坏的地方改坏）——另出票

越界自查：车道高度 54 与 viewBox `0 0 920 204` **都没动**（既有断言「曲线高度收窄」照旧绿），
另两处疑似溢出一个字没碰。

## 4. 实现与验证（2026-10-15）

**实现**（`web/console/index.html`）：车道内的纵向落点全部由 `envLaneRows(laneH)` 派生——
车道名 `0.18H`、行距 `max(14, 0.26H)`、绘图区顶 `名 + 行距/2`、上限值行 `名 + 行距`、
基线（横轴 + 下限值）`名 + 行距×2`。比例取自 **76px 时代的手调结果**（`envLaneRows(76)` =
13.68 / 19.76 / 23.56 / 33.44 / 53.2，对上当时的 14 / 20 / 32 / 50）；行距下限 **14px 就是本票的
验收线**，所以车道再压也不会让两行贴上。

原写法是 `yTop+14` / `yTop+32` / `yBase = yTop + laneH - 26`：车道 76→54 之后
`32` 与 `28` 只差 4px，而且**次序也反了**（上限值跑到下限值下面）。

**无头回归**（`docs/patrol/console-ui/verify-page.js`，新增 4 条断言）

```
NODE_PATH=<jsdom 那棵 node_modules> node docs/patrol/console-ui/verify-page.js <页面绝对路径>
改前：390/403，新增的 4 条全红（相邻两行只差 4px / 次序反 / 没有 envLaneRows / 偏移不随高度走）
改后：394/403 通过，运行期错误：无
       失败 9 条与 HEAD 逐条相同（地图点击与站位那一组，与本票无关）
```

**1366×768 真机渲染**（Chrome `--headless=new --window-size=1366,768 --force-device-scale-factor=1`，
页面接假后端渲出真实数据；几何是**从浏览器读回来的**，不是推算）：

- 车道内相邻两行**基线间距 14.04 用户单位 = 19.84 渲染 px**（三根车道一致，≥14）；
- **字形墨迹间距 2.04–5.04 用户单位**（最紧的是 `CO₂ ppm` 那行，带下标/降部）⇒ **无墨迹重叠**；
- 该视口下 SVG 渲染宽 1300px（viewBox 920 ⇒ 缩放 1.413），字号与间距**同倍缩放** ⇒
  "不叠"与视口缩放无关。（浏览器给 SVG 文本的 `getBoundingClientRect` 是**含行距的排版盒**，
  在这里会报 0.16px 的假重叠；判定用的是字形墨迹盒。）

**护栏自证**（各自只打红对应用例，都是实跑出来的）

# ADR-0008：控制器整定参数纳入单源（软限位必须与行程一致）

日期：2026-09-12
状态：已接受
背景：按《FMC4030 控制器使用说明书 V2001》与《指令说明表》逐条核对现有驱动与 `.elo`
生成器，发现**控制器侧**还有一层本程序完全看不见的状态——一旦不符，故障现象是
"指令下发成功但机构只走一小段"，没有任何错误码：

1. **控制器自带软限位，出厂默认正负各 200mm**（说明书 §三.4「参数」页）。本机 Y 行程是
   0…4492mm。未整定时控制器把 Y 的目标位置**自行截断到 200mm 并返回成功**。
2. **回零可能被控制器自行终止**：若在设备参数 `homeTime`（ms）内没等到限位开关，控制器
   中止回零并置位「轴回零超时」（`FMC4030.h` `MACHINE_HOME_OVERTIME`）。此时点位**不是**
   原点，继续下发绝对坐标会整体偏移。
3. **`Stop_Single_Axis` 不能停止插补**：说明书明确其"只能用于启动单轴运行后停止"。急停若
   只逐轴下发，`Line_2Axis` 的插补运动会继续跑。
4. **60s 无数据交互即断连**：状态轮询本身就是保活，不能把轮询当成纯粹的可选优化。
5. `.elo` 的「等待轴运行完成 / 等待回零完成」按**轴槽位**取值，控制器的槽位是固定 3 个；
   原生成器填 `0,1`（X、Y），而本机接线是 Y、Z（1、2）——M2 脚本会在未接线的 X 上等待，
   等于没等。

## 决定

- **控制器整定参数建模为一等公民**：`patrol.fmc.device_para` 给出与厂商
  `struct machine_device_para` 逐字段对齐的 ctypes 布局（导程 / 细分 / 软限位 /
  回零超时），提供 `get_device_para` / `set_device_para`（整体 read-modify-write——控制器
  没有局部写）。字段偏移有断言测试守护，改结构体会立刻红。
- **软限位一致性可校验**：`Fmc4030.soft_limit_issues()` 返回控制器软限位**窄于**机械行程
  的轴；`check_soft_limits()` 在巡检/自动运行启动前抛 `SoftLimitMismatchError`。M0 调试台
  连接后调 `warn_soft_limits()` 只警告不阻断（它本就是排障入口），并新增 `para` 命令随时复查。
- **软限位的符号约定显式写下并待现场证伪**：说明书既称默认"正限位 200、负限位 200"，又称
  "把任一软限位设成负数即取消"——两者在"`softLimitMin` 存有符号边界"的解读下自相矛盾。
  故按**「负极限字段存幅值」**实现：生效区间 `= [-softLimitMin, +softLimitMax]`，任一字段为负
  即视为取消（交由本程序的 `check_travel` 兜底）。这个假设写在 `DevicePara.effective_limits`
  的 docstring 里，现场一次读回即可证实或推翻。
- **回零默认阻塞且区分两种失败**：`home_all(wait=True)`；`wait_home()` 一旦读到
  `MACHINE_HOME_OVERTIME` 立即抛 `HomeTimeoutError`（原点不可信），主机侧等满 `home_timeout`
  则抛 `MotionTimeoutError`。**回零未完成时的当前位置不是有效原点**，绝不能静默返回。
- **急停顺序**：先 `Stop_Run`（停插补）再逐轴 `Stop_Single_Axis(immediate)`；
  `stop_everything()` **收集**失败动作名而非抛出——急停链路要把每条指令都尽量送出去。
  返回非空 = 调用方必须告警（CLI/console 上报，并提示人工确认/断电）。
- **`.elo` 等待指令改为按接线轴循环填充 3 个固定槽位**（本机得 `(1,2,1)`），不再硬编码 `0,1`。

## 后果

- **现场投产前置条件**：必须先在控制器「参数」页把 Y 的软限位上限提到 ≥4492、下限 ≤0
  （或按上述约定取消软限位），否则长行程轴只能走 200mm。这是**部署检查项**，不是可选项。
- 主机侧 `home_timeout`（120s）应大于控制器的 `homeTime`；两层超时都保留，一层防机构卡死、
  一层防控制器自行放弃。
- `motion_profile.py` 仍只管运动参数；控制器整定参数是**另一处**现场入口，两者都要整定，
  文档里明确区分（改这个文件改不动控制器里的软限位）。
- 巡检启动路径新增一次 `check_soft_limits()` 读回；读设备参数会占用一次网络往返，只在启动时做。

## 现场核实（2026-09-12 21:1x，prod `10.77.77.39`，只读）

`Get_Device_Para` 实读回（结构体 `sizeof = 92`，与厂商头文件一致）：

```
div          = (5000,   100000, 100000)
lead         = (10,     95,     95)      mm/转
softLimitMax = (200,    4495,   -1)
softLimitMin = (200,    0,      220)
homeTime     = (10000,  100000, 100000)  ms
```

1. **符号约定假设被证实。** Y 轴原始 `(min=0, max=4495)` → 生效 `[0, 4495]`；Z 轴
   `max = -1` 为负 → 判为取消。与本文档按「负极限字段存幅值、任一字段为负即取消」
   的实现完全一致。`DevicePara.effective_limits` 的 docstring 相应从"待现场证伪"
   改为"已实测证实"。
2. **Y 轴软限位已在现场整定**（`[0, 4495]`，与 4492mm 行程一致），本文档"后果"里那条
   投产前置条件**已在现场解决**，长行程被静默截断的风险消除。
3. **Z 轴软限位是取消状态**——Z 没有控制器侧过行程保护，只能靠本程序的 `check_travel`
   兜底。且 Z 行程上端恰为 0（原点），若控制器其实按 `[-220, -1]` 解读（而非取消），
   命令 Z 到 0 会被静默截断 1mm。**首次上机应先以 `-50` 之类中间目标验证方向与到位**。
4. **`homeTime` = 100 s**（Y/Z），主机侧 `home_timeout = 120 s` 的两层超时关系成立。
5. **细化 div/lead**：Y/Z 均 `div=100000 / lead=95` → 1052.632 脉冲/mm，mm 换算有据
   （换算发生在控制器内部，本程序按 mm 下发）。
6. ⚠️ **`FMC4030.h` 的状态位命名陷阱**：`MACHINE_LIMIT_N_NONE` 等后缀 `_NONE` 的厂商
   注释是"**未触发**"（`MACHINE_HOME_NONE` 是"**未回零**"），**不是**"没有这个开关"。
   本轮曾误读，已在 `patrol/fmc/status.py` 逐条抄录厂商原文注释并在 `AxisStatus`
   docstring 点名，防止再次踩坑。

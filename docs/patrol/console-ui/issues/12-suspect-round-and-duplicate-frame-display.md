## 1. 事故与背景（为什么这条重要）

2026-10-09 那一轮：48 帧里 **35 帧是同一张陈旧近黑帧**，轮行却标 `ok=1`，

## 2. 字段与语义（环境官给的原文，别自己解释）

| 端点 | 字段 | 类型 | 语义 |
| --- | --- | --- | --- |
| `/rounds` | `suspect_duplicate` | 0/1/NULL | 该轮被判可疑重复 |
| | `dup_groups` | list[str] / NULL | sha12 分组；**NULL 或 `[]` 都表示"无重复组"** |
| | `content_check_error` | TEXT / NULL | **非空 = 没查成 ≠ 没重复** |
| | `n_duplicate` | 张 / NULL | 重复帧数 |
| | `n_frames_recorded` | 张 / NULL | 记录到的帧数 |
| `/images` | `frame_dup` | 0/1 / NULL | 这一帧与别人同一份字节 |
| | `dup_group` | sha12 / NULL | 所属重复组 |
| | `content_sha256` | 64 位 hex / NULL | 帧内容指纹（可追溯） |
| | `same_as_previous` | 0/1 / NULL | 与上一帧同一份字节 |
| | `duplicate_streak` | 张 / NULL | 连续重复长度 |
| | `elapsed_s` | 秒 / NULL | 这一帧耗时 |

**NULL 语义（本次的关键）**：`suspect_duplicate` / `n_duplicate` / `n_frames_recorded` /
`same_as_previous` / `duplicate_streak` 为 **NULL = 那时还没查/没记，不是"确认无重复"**。

**判据（与环境官聚合侧同口径，票 17）**
- 一轮不可信 = `suspect_duplicate=1` **或** `n_duplicate>0` **或** `content_check_error` 非空；
- 一帧不可信 = `frame_dup=1` **或** `duplicate_streak>0`。

## 3. 显示设计（提案）

### 3.1 四种状态、四种文案——**"没查成"和"查了、干净"必须分开**

| 状态 | 判据 | 显示 |
| --- | --- | --- |
| **正常** | 字段有值且全 0/空 | **零痕迹**：不加角标、不改色、不改文案、不动 `N 帧` 那句话 |
| **可疑** | `suspect_duplicate=1` 或 `n_duplicate>0` | 中性角标「重复 35/48」（数字来自字段，不写死）；tooltip 给 `dup_groups` |
| **没查成** | `content_check_error` 非空 | 「**未核查**（核查失败：<原因>）」——**不是"可疑"、更不是干净** |
| **那时还没查** | 字段缺失或 NULL | 「**未核查**（那时没有内容核查）」——旧数据/旧镜像走这条 |

- 用中性色（warn/灰）而**不是告警红**：红是"失败"语义，重复帧是"拍到了但不可信"。
  现场最怕的是"天天报警"，那会把真报警淹掉（与 `stale`/`band_source` 同一原则）。
- 可疑轮的说明只放在**该卡上**，不往页头塞（页头是全局状态，噪音会摊到每一屏）。

### 3.2 `n_results` 与 `n_frames_recorded` 并列时怎么防误读

现状 `#roundnavinfo` 里的「N 帧」用的是 `n_results`＝**成功站数**，容易被读成"48 张都拍到了"。
- 正常轮：**保持现状**（零痕迹），不动那句话；
- 可疑/未核查轮：改成双数并列 ——「记录 48 张 · 成功 47 站」，并在 tooltip 里说清两个数各自的含义。
  现场要的是"到底有多少张能看"，两个数分开写才不会被合成一个错结论。

### 3.3 拼图格：`frame_dup` 要与"欠曝/过曝"区分开

- `frame_dup=1` ⇒ 角标「**重复帧**」（并在 tooltip 里给 `dup_group` 前 12 位）：
  视觉上用**虚线边 + 中性色**，**不用红**；
- `duplicate_streak>0` ⇒ 角标「连续重复 N 张」（N 来自字段）；
- **区分原则**：欠曝/过曝是**帧质量**（`quality` 里的 `no_light`/`overexposed`，属"这帧拍坏了"），
  重复帧是**内容相同**（属"这帧没换地方/没换时间"）——两者**文案、颜色、位置都不同**，
  混用会让人以为是同一件事。当前拼图格不显示质量标记（质量在测量行的表里），
  若将来要在格子上一并显示，本票要求两者必须能被一眼区分（并各配断言）。

### 3.4 详情区（点开某一帧时）

只在该帧**不可信**时显示一行可追溯信息：`content_sha256` 前 12 位 + `same_as_previous` /
`duplicate_streak`；**正常帧不显示任何行**（零痕迹）。`content_sha256` 只显示前 12 位，
完整值放 `title`（现场核对时够用，又不会把卡片撑爆）。

## 4. 可扫描断言（实现时必须逐条有）

1. **正常轮 fixture**（`suspect_duplicate=0`、`n_duplicate=0`、`content_check_error=''`、
   `dup_groups=[]`）：断言轮次卡 / 拼图格 / 详情区**零痕迹**——文案里不出现
   「重复」「可疑」「未核查」，且 `N 帧` 那句话与现状一致。
2. **事故轮 fixture**（复刻 10-09：`suspect_duplicate=1`、`n_duplicate=35`、`n_frames_recorded=48`）：
   断言标出来**且能数出 35**（文案含 35，且数字来自 fixture 而非写死）；断言用的是中性样式，
   不是 red/bad 类。
3. **没查成 fixture**（`content_check_error='sha 读取失败'`）：断言文案是「未核查（核查失败…）」，
   **不含**「重复」「可疑」，也**不含**"干净/正常"这类词。
4. **那时还没查 fixture**（字段整列缺失或为 NULL）：断言显示「未核查（那时没有内容核查）」，
   **且绝不出现**"无重复/正常/已核查"。
5. **帧级**：`frame_dup=1` 的格子断言出现「重复帧」角标且**不等于**欠曝/过曝的文案；
   `duplicate_streak=5` 断言出现「连续重复 5 张」。
6. **契约表**：把 `/rounds`、`/images` 的新字段加进 `verify-page.js` 的 `CONTRACT`
   （键必须存在；**值可以为 NULL 的字段不能写进 `required` 的"必须有值"语义**——
   契约只保证键存在，不保证非空），并进 `PAGE_CONSUMES`。

## 5. 边界与不做的事

- **只显示，不替人做决定**：不自动删帧/屏蔽帧/改 `ok`；不改采集侧；不动别人的文件。
- 改动落在我领地：`web/console/index.html` + `docs/patrol/console-ui/verify-page.js`。
  若需要 console 侧**聚合**新字段（例如按轮统计可疑帧数），那是 `console.py` 的活，
  **另开小票**再动（本票不默认包含）。
- `analysis` 侧**没有** `station_summary`：轮次聚合在 console 这边自己算（不要为这事去加 prod 依赖）。
- **部署后才能观测**：字段没上生产之前，页面一律显示「未核查」（第 3.1 的第四行），
  这正是 10-09 那条"看不出异常"的根治方式——**不知道就说不知道**。

## 7. 契约更正（`8d52a60` 之后的修订；实现提交 `c6f1b12`，2026-10-13）

§2 那张字段表是**环境官按聚合侧口径**给的，其中两处形状与**生产者落地形态**不一致；
巡检手在 `6a232e4` 给了原文（`patrol/daemon.py:259` / `:344`）。这两处都属于
**"页面照设想写、真机上渲染错/漏判"**的同一族问题（票 10 的兄弟），所以按实改：

| 项 | §2 原写法 | 实际（以生产者为准） | 页面原来会怎样 |
| --- | --- | --- | --- |
| `suspect_duplicate` | 0/1 | **布尔** `True/False`（进 SQLite 成 1/0，接口上两种都可能） | 判 `=== 1` ⇒ **真机布尔标记全部漏判**，可疑轮显示成正常轮 |
| `dup_groups` 元素 | `list[str]`（sha12） | **对象** `{sha256_12, n, stations}` | 按字符串拼 ⇒ tooltip 显示 `重复组：[object Object]` |
| `frame_dup` / `same_as_previous` | 0/1 | 布尔（同上） | 判 `=== 1` ⇒ 重复帧角标不出现 |

**改法**
1. 新增 `isFlag(v)`：`true`/`1`/`'1'` 都认（与 `analysis/integrity.py` 的 `_truthy` 同口径）——
   轮级 `suspect_duplicate`、帧级 `frame_dup`、`same_as_previous` 三处都走它；
2. 新增 `dupGroupsText(groups)`：**对象优先**（`sha256_12` + `n 帧` + `stations`），
   同时兼容旧的字符串形态（旧契约的数据不该让页面崩），缺字段给 `?`，**任何情况都不出现 `[object Object]`**；
3. `n_duplicate` 为 NULL 时（轮已判可疑、但张数没记）文案是
   「**可疑重复（张数未记录）**」——不写 0、不省略，因为 NULL 的语义是"那时没记"。

**新增断言（共 7 条）**
- 重复组按对象渲染：tooltip 含 `41685c091234`、`35 帧`、`S102`、`S211`；
- 兜底钉子："**屏幕上任何一处都不出现 `[object Object]`**"（只看渲染元素——`<script>` 的
  `textContent` 是源码本身，第一版没排除，红的是我自己的注释）；
- **隔离用例 ×2**：`suspect_duplicate` 的布尔形态与整数形态各来一次，
  每次都把 `n_duplicate` 置 NULL，让 `suspect_duplicate` 成为**唯一信号**；
- 帧级同样隔离：`duplicate_streak` 置 NULL，只留布尔 `frame_dup`；
- 兼容性：`dup_groups` 退回字符串形态（旧契约）仍能渲染、不崩。

**为什么必须做隔离用例（自证时抓到的覆盖漏洞）**：
第一版隔离用例里，那一轮 `n_duplicate=35>0` 也成立，于是把 `isFlag()` 退回 `=== 1`
跑一遍——**居然全绿**。也就是说"布尔这条路"从来没被单独测到，写下的断言看着对、
其实测的是 `n_duplicate`。这与票 09 那条"`waitFor` 判据撞过渡态"是同一类坑：
**断言写了 ≠ 断言有用**，只有真的把实现改坏、看它红，才算验过。

**验证（`c6f1b12`）**：jsdom **354/363**，连跑 3 次同结果，运行期错误：无；
失败 **9 条与 HEAD 逐条相同**（`Compare-Object` 比过清单，逐字一致，非本批引入）。

**护栏自证（5 条，各自只打红对应断言；实测结果）**

## 9. 真机形状到了：`8d52a60` 的"干净"判据**过松**（已修）

巡检手 2026-10-14 给了 21:27 那轮的实测值（票 06 §J.1），这条直接推翻了我的 fixture 假设：

| 列 | 我 fixture 写的（正常轮） | **真机实际**（21:27 那轮） |
| --- | --- | --- |
| `suspect_duplicate` | `0` | **`null`** —— 生产者在**没有重复时根本不发这个键** |
| `dup_groups` | `[]` | **`null`** |
| `content_check_error` | `''` | **`null`** |
| `n_duplicate` | `0` | `0`（int） |
| `n_frames_recorded` | `48` | `48`（int） |

**旧实现的洞**：`allAbsent`（四列全缺或全 NULL）之外一律返回 `ok`（零痕迹）。
真机上正常轮的三列都是 NULL，只有 `n_duplicate=0` 是正面证据 —— 而"只要不是全缺就算干净"
等于把"**没记**"读成了"**查了、干净**"，正好撞上 Chief 附条件 2
（「键不存在」和「值为 NULL」都要落到「未核查」，一个都不许显示成干净）。

**改法（正面证据原则）**：
- **干净** = 有正面证据：`n_duplicate` 是**数字 0**（明确记了"0 张重复"），
  或 `suspect_duplicate` 明确为假（`0`/`false`/`'0'`）；
- **否则**一律「未核查」，且**两种未核查分开**：
  - 四列全缺/全 NULL（旧数据、旧镜像）⇒「未核查（**那时没有**内容核查）」；
  - 有帧数但没有"查过重复"的正面记录 ⇒「未核查（**没有内容核查记录**）」。
    两句不能混：前者是"那时压根没有这项核查"，后者是"那时有核查、但没留下记录"——
    写成同一句，事后回查会得出相反的结论。

**新增 2 条断言**（fixture 搬运真值，不改 fixture 结构，避免副作用）：
1. 生产形状的正常轮（三键 NULL + `n_duplicate=0`）⇒ **仍必须零痕迹**；
2. 把唯一的正面证据（`n_duplicate`）也拿掉 ⇒ **必须**落「未核查（没有内容核查记录）」，
   且文案里不许出现"无重复/正常/干净/已核查"。

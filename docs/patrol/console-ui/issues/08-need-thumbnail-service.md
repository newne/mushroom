**提出人：** 界面师（`web/console/**` 与 `deploy/src/deploy/console.py` 的唯一写者）

**触发：** 用户裁定当前重点是「优化巡检过程、清晰拍到各阶段长势，为后续测量和决策积累数据基础」，
历史模式最值钱的视图变成「同一站位跨轮次/跨天对比」。

## 为什么卡住

| 事实 | 出处 |
|---|---|
| 巡检帧 1080×648、约 750–766 KB/帧 | `docs/patrol/prod-deploy/container-cutover.md:596,677` |
| 48 格拼图一屏 = 30+ MB，是"历史页一屏几 MB"的已知欠账 | `docs/patrol/console-ui/spec.md:475,623`（标"待做"） |
| 现在**没有**服务端缩略图、也没有服务端拼图；`.mosaic` 是前端按 `layer×col` 摆的格子，缩略图就是原图 | `web/console/index.html:2224-2268`、`spec.md:193-197` |
| 换轮次/跨天翻图每次都是整车原图，翻 5 天 = 180+ MB | 本票据测算 |

跨天对比要「一眼看出这几天怎么长的」，就得同时摆 N 天的图。**N × 750 KB 是硬墙**：
没有缩略图，这个视图要么慢到没人用，要么必须靠"只取 2–3 天"打折，达不到用户要的"一眼"。

## 请求的契约（前端侧的硬要求，不改契约就别指望前端配合）

1. **仍在单一 origin 下**：`console` 是唯一 origin（ADR-0003/0015 + `web/console/nginx.conf:39-51`）。
   缩略图必须由 `/api/*` 提供，**不能**给前端一个 MinIO/控制网地址——
   2026-09-17「历史图全黑」就是 `cloud_url` 上了前端（`console.py:509-513`）。
2. **单张**：`GET /api/thumbnail?object_name=<名>&w=<宽>`
   - `object_name` 走**现有** `safe_object_name()` 校验（`console.py:80,875`），不新增取值面；
   - `w` 限定 {320, 480, 640}，非法值钳到最近档（避免任意尺寸打崩缓存）；
   - 返回原图字节流，`404` 表示对象不存在（**不要**回 HTML/JSON 让 `<img>` 当图片渲染）；
   - 对象不存在/取图失败要与 `/api/image` 一样有可区分的话术（`console.py:864-885`）。
3. **批量（可选，能显著降请求数）**：`GET /api/thumbnails?...` 一次多张；
   前端可先用单张版跑通，批量是优化项不是前置项。
4. **可缓存**：对象名与内容一一对应（不可变），期望 `Cache-Control: public, max-age=31536000, immutable`
   或等价的 nginx `proxy_cache`，把重复翻页的 CPU 省在服务端。**这是"翻得快"的关键之一**，
   不只是字节数；nginx 现在页面本身是 `no-store`（`nginx.conf:22-24`），缩略图不要跟它一样。
5. **不落盘改原图**：缩略图不得覆盖或替换 MinIO 里的原始对象（原始帧是测量与决策的证据）。

## 验收标准（可量的）

- 同屏 48 格**首次**加载传输量从 ≥30 MB 降到 ≤2 MB（按 320px、JPEG q≈80 或 WebP 估）。
- 局域网内单张缩略图 P95 ≤ 200 ms（含取原图 + 缩放），缓存命中后 ≤ 20 ms。
- 缩略图与 `/api/image` 的对象名口径完全一致：给定同一 `object_name`，两者都必须 200 或都必须 404。
- 不改变现有 `/api/image` 行为（回归：`deploy/tests/test_console.py`，由归属方跑）。

## 不做什么（明确的非目标）

- 前端**不**用 canvas 自造缩略图：等于把 750 KB 先下完再缩，带宽一点没省。
- 不在本票据里做服务端拼图（`spec.md:193-197` 已把拼图定义为前端布局）。
- 不新增控制网地址、不引入浏览器直连 MinIO、不新增第二个 origin。

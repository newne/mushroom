# 实测环境的主视图是「按生长天数的日分布」，不是小时序列

Status: accepted (2026-10-21)

## 背景

环境模式原来的中栏是一张 72 小时的三泳道小时曲线（温/湿/CO₂ 各一根纵轴）。它回答的是"这几个小时怎么走的"，答不了运维真正在问的那句："**这一批到了第几天，温湿度散不散、有没有冲出去**"。一根均值线把日内波动压平，日与日之间的离散程度在图上根本不存在。

2026-10-21 与用户确认的口径：实测环境**按天显示本批次全部数据**，用箱线图表达日参数分布，曲线连接中位数。

## 决定

1. 环境模式中栏的**主图**改为：横轴 = 生长天数（本批全量，缺天不补），每天一个箱线，箱线之间用中位数折线相连。
2. **小时级均值曲线不另起一张卡，而是叠在同一张图里、共用一根纵轴**——箱体里的样本就是这些小时点，观者能直接看出箱体是怎么长出来的。
3. **不画双纵轴**。同一个量用两根轴是读图作弊（与 `index.html` 环境页既有态度同源："两个单位共用一根轴是在骗人"）；箱体被压扁是留白问题，不是轴的问题。
4. 箱体走**小时口径**（一天 24 个小时均值的 q1/中位/q3），采样点级 `*_min`/`*_max` 另画一条淡色范围带。两者视觉通道分开，图注写清各是哪一档粒度（`env-analysis/spec.md` §2.3 明令不得混读）。
5. **只画本批**。放弃原 D14「本批 vs 最近 1 批」双箱线。行键仍是 `(zone, day)`，每行带 `entry_date` / `batch_no` / `growth_day`（`growth_day_prod` 一并给出）。**没有** `batch_key` 这一列——要做跨批对比得先加"批次"这个键，本期不做（`grep batch_key` 在 `analysis/src` 下零命中）。
6. 光照**不做箱线**：它的主口径是「补光循环制度」（ADR-0021 修订 / D13），改为同一横轴下的一条按设定变化点切段的制度带。
7. 五数在**后端**算，由每日任务落库（`environment_daily`），页面直接取数——沿用 `ranges` 的既有形态，不在页面里重复一套统计。

## Considered Options

- **照 D16 留跨批对比**：3 个历史批次分属 12 月 / 3 月 / 8 月，"两批的差异"和"季节的差异"分不开，叠上去只会被读成规律。放弃。
- **双纵轴（箱线左轴、小时均值右轴）**：同量纲双轴，图会自己骗人。放弃。
- **页面从 `/api/environment` 现算五数**：本批约 500 行，前端完全算得动，且零后端改动。但用户明确要求"定时任务落库、前端直接取数"——一份口径算一次，避免页面与算法侧各算一套。放弃。

## Consequences

- 72 小时小时曲线作为独立视图消失；小时级信息改由图内的小时均值曲线承载。夜间短时超调在日视图上**看不出来**——这是本决定接受的信息损失，需要看小时细节时走历史模式的节点放大（那里有另一条环境带）。
- `environment_daily` 成为派生表：口径一变就要重算，重算必须写新值而不是留旧值（与 `ranges` 的封版策略不同）。
- **没有"封版"**：`refresh` 每晚把全部日行重算一遍、按库房整删整写。台账窗口只保证"某一天归到哪一批"稳定，**不保证**已结束批次的数值不再变——补采或迟到的小时行仍会改写旧批次的日行。真要封版得给批次加状态字段，本期不做。
- 页面仍然零前端依赖（手写内联 SVG）。

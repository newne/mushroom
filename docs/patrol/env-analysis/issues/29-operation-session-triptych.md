# 29. 操作 × 长势：操作会话与相邻轮次三联图像

Status: implemented（2026-10-21；后端会话与三联 + console 反代 + 前端对照卡；1366×768 未上机核过，见 §3）
归属：后端（analysis）+ 前端（web/console）
依据：`docs/patrol/env-analysis/spec.md` §3.1、**ADR-0028**
依赖：无。`rounds` / `images` / `operations` 都已在库里；**`measurements` 的 `round_id`（票 11 / G3）不是前置**——本票只给图不给数值。

## 1. 为什么

环境模式的「操作记录」是逐条审计，回答"把哪个点改成了什么"，答不了
"**在什么长势下调的这一下，调完之后长势怎么变**"。要答后者，必须把调节动作、
调节前后的库房图像、生长天数三件事对上同一个时间锚。

## 2. 交付物

1. **操作会话**（`analysis/src/analysis/ops_session.py::sessions`，纯计算）：
   同库房内相邻审计记录间隔 ≤ `window_min`（默认 10）并入一次调节，`n=1` 也成立。
   会话内逐条保留（设备 / 点位 / 值 / 操作人 / 动作来源）。
2. **三联选取**（同模块 `pick_rounds` + `pick_frame` + `attach_frames`，纯计算）：
   同一观察框 × 最近 3 个巡检轮次，**强制跨越**会话时刻（≥1 帧在会话前、≥1 帧在会话后）。
   凑不齐跨越 ⇒ `side` 标注缺失，`note` 写明原因，**不拿调节前的帧充数**。
3. **接口 `GET /operations/sessions`**：只读，不建表；返回会话 + 每会话的三联
   （含 `object_name`，页面复用 `imageUrlFor`）。
4. **前端「操作 × 长势」卡**：左列会话时间线，右列选中会话的三联对照（图 + 轮次时刻 + 与调节的时差）。

## 3. 验收（缺一条不算过）

- [x] 间隔 ≤10 分钟的记录并成一会话；>10 分钟切开；边界值（正好 10 分钟）算同一会话
- [x] 三联**同框**——3 帧的 `box_id` 必须相同
- [x] 三联**强制跨越**；无法跨越时如实标缺，**不顶替**
- [x] 走 `ok` 帧：失败帧（`ok=0` 或无 `object_name`）不入选
- [x] 轮次按 `round_id` 关联，**不按时间戳猜轮次**
- [x] 空态：无操作 / 无巡检轮次 / 该框该轮无帧，三种各自具名
- [x] 只读：本票不产生任何写操作
- [ ] **1366×768 上三联可读**——未上机核过（本机没有可跑的 console 环境）

## 4. 不做什么

- 不做数值长势关联（等 `measurements.round_id`）
- 不做多框并排（观察框可换，但一次只画一个框）
- 不做图像相似度排序（"top-3" 指**时间邻近**，不是视觉相似）
- 不在分析侧缓存图像

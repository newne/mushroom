# ADR-0019：Z 回零**向上**、原点在**顶端**、第 1 层为**最上面那层**

日期：2026-10-10
状态：已接受（用户现场："导轨平面图和方向键控制是对的，**z 轴回零方向是反的**"，并要求
第 1 层对应**最上面那层**）
取代：**ADR-0018**（"回零向上、原点在顶端"这一半被本次采用；其"向下为正 / 行程 `0…212`"
与本次不同）。
修订：ADR-0007 的 Z 行、ADR-0008 的 Z 软限位、`console-ui/spec.md` 的轴表与地图说明、
`station-retarget.md` §8.2 的 Z 方向注记、`CONTEXT.md` 的"层"定义。

## 背景

Z 的方向在本仓库里翻过三次，每次都推翻上一次（ADR-0018 → 2026-10-09 `7169156` →
2026-10-10 `3537d00` / `40c8434`）。根因是**同一个事实有三处副本**（`motion_profile`
的 `positive_towards`、页面文案、`framing.sign_z`），且现场结论互相打架——`container-cutover.md`
§20 的教训写得很清楚：**"撞到哪个限位"证明不了"哪端是原点"，得看轴往哪走**。

2026-10-10 用户在机器旁给出**决定性观察**：

- 方向键 / 平面图现有的约定（`Z+ = 向上`）是**对的**——保持不动；
- 但按「回零」时 Z 往**下**跑（去到底部）、把底部当成了坐标 0——**这是反的**，要改成向上回零。

于是目标框架 = "**回零向上、`Z=0` 落在顶端、`+Z` 仍向上**"：原点在顶端、向下为负、行程 `−212…0`。

## 决定

1. **回零方向**：`_Z.home_dir` 由 `HOME_DIR_NEGATIVE`(2) 改为 **`HOME_DIR_POSITIVE`**(1)。
   说明书 §三.2 定死"**正限位 = 远离电机端**"，Z 的电机在**底端**，故正限位在**顶端**
   ⇒ 找正限位就是**往上**到顶端。Y 不变（电机在左端、原点在左端，仍 `HOME_DIR_NEGATIVE`）。
2. **坐标框架**：回零到哪一端，`Z=0` 就落在哪一端——**控制器没有方向反转参数**，所以
   "回零向上"与"原点在顶端"是同一件事、绕不开。`+Z` 向上由**接线**定死（2026-10-09 现场
   SDK 实测：从旧回零位向 +Z 走到行程尽头触发的是**正限位**），与回零方向无关。于是行程由
   `0…212` 改为 **`−212 … 0`**、`home_position = 0`（顶端）。
3. **两轴不再同构**：Y 的原点在**靠近电机**的一端（左端），Z 的原点在**远离电机**的一端
   （顶端）。这是现场要求，不是笔误。回零方向与坐标框架由此**绑定**：`home_dir` 一变，
   `layer_z` 必须还能算出落在行程内的层心（代码里有越界断言）。
4. **第 1 层 = 最上面那层**：层号**自顶向下**（第 1 层贴近顶端 Z 原点），层心到原点的距离
   为 **57 / 80 / 152 / 202 mm**（沿用 2026-10-08 的实拍标定，**物理货架不变**，只把"第 1 层"
   重新定义成最上层）。新层 z = `[−57, −80, −152, −202]`。
5. **站位数据迁移**：按**层号**逐站重算 z（**不是** `z → −z`）：`z_new = layer_z(station.layer)`，
   `trim` 原样保留。工具 `patrol-migrate z-frame --stations <p> [--dry-run]`，落盘前自动备份；
   已经是新框架（全部 `z ≤ 0`）、或旧 z 超出 `0…212` 时**拒绝执行**。
6. **控制器 Z 软限位**改为 `−212…0`（ADR-0008）。巡检启动前的 `check_soft_limits()` 会
   **fail-closed** 拦住"控制器还是旧框架"。
7. **页面**：平面图**第 1 层画在最上**、Z 原点在顶端（z 越大越靠上）；点动按钮与方向键
   **保持**（`↑ = Z+（上）`、`↓ = Z−（下）`）；坐标范围文案由 `/api/grid` 派生（自动变成
   `−212…0`）。
8. **`positive_towards` 保持 `"up"`**，故 `framing.default_sign_z()` 仍为 **−1**（本次不动）。

## 为什么不能只改回零方向

与 ADR-0018 §"为什么不能只改一个方向"同源：只把 `home_dir` 改成 1 而不动行程，会让原点
落在顶端、而代码仍以为 `−212` 在下 → 每个绝对目标都跑反。**回零方向、行程、站位表、
控制器软限位**是同一套框架的四份表达，必须一起改。

## 后果

- **上机必须重做一次回零**（`homeDir` 变了）+ 重写 Z 的软限位；在此之前**不许下发任何
  绝对坐标**（点动也算，点动按当前坐标算落点）。清单见
  `docs/patrol/prod-deploy/z-frame-cutover.md`。
- 站位表迁移是**幂等保护**的（第二次执行会报错）；历史图像按 `station_id` 关联、物理站位
  没变，不受影响。
- **教训**（承接 §20）：方向只能由"用户在机器旁看**轴命令符号**（`jog Z +N` 让机构往哪走）"
  定论，不能从"撞到哪个限位"反推原点；而这三处副本（`positive_towards` / 页面 / `sign_z`）
  要**同源派生**，别各写各的。

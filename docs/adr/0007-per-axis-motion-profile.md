# ADR-0007：运动参数按轴拆分（本机 Y/Z 双轴几何单源）

日期：2026-09-11
状态：已接受
背景：`motion_profile` 原先只有一组全局标量（`travel_speed` / `travel_acc` /
`home_speed` …）和虚拟坐标 `Point = (x, y)`——那是按"X+Y 双水平轴、行程各约 2.4m/0.14m"
的假想机器写的，且当时三轴的行程并未实测。2026-09-11 现场实测给出真实几何：

| 轴 | 控制器轴号 | 行程 mm | 运动正方向 | 原点位置 | 回零方向 |
| --- | --- | --- | --- | --- | --- |
| Y | 1 | 0 … 4492 | 向右 | 左端 | 负限位（`homeDir=2`） |
| Z | 2 | -212 … 0 | 向上 | 顶端 | 正限位（`homeDir=1`） |

本机**不接 X 轴**，虚拟坐标系只有 `(y, z)` 两维。两轴的行程、速度、加减速、回零方向
**各不相同**（当时 Y 50 mm/s vs Z 20 mm/s，相差 2.5 倍；Y 的 50 是这一轮按"假想机器"
推的值，2026-09-12 已重新整定为 150 —— 见文末补充），旧的单组标量无法表达。

## 决定

- 运动参数**按轴**建模：`AxisProfile`（行程、目标速度/加减速、回零方向/速度/加减速/脱落距离、
  接近段与点动比例）取代全局标量；`MotionProfile` 持有 `y` / `z` 两个 `AxisProfile`。
  单源原则（ADR-0002）不变——M1 与 M2 仍 import 同一份 `M1`/`M2`。
- 虚拟坐标 `Point = (y, z)`，顺序**恒为 Y 在前、Z 在后**，与 `Line_2Axis(axis_mask,…)`
  的 `endX`/`endY` 形参槽位一一对应；`MotionProfile.axes` 即该顺序的定义处。
- **控制器轴号与两轴组合号由参数派生**，不写字面量：`axis_mask = Σ(1 << index)`，
  本机得 `0x06`（Y+Z）。接线变化时无需逐处改常量。
- 原点不变式：`AxisProfile.home_position`（正限位→`travel_max`，负限位→`travel_min`）
  必须等于 0。两轴行程都从原点单侧展开，于是坐标符号自带方向语义——
  **Y 增大 = 向右，Z 减小 = 向下**。该不变式有断言测试守护。
- 行程兼作**软限位包络**：越界目标在下发控制器前即被 `Fmc4030.check_travel` 拒
  （`TravelLimitError`），不再由"站位 min/max ± 50mm"推断。
- 两轴插补的速度/加减速是**合成量**（`Line_2Axis` 的语义），由
  `fmc.geometry.composite_limits` 按方向余弦折算：`v_comp = min_i(v_i / |cos θ_i|)`，
  保证任一轴都不越自身上限——避免短行程慢轴（Z）把长行程快轴（Y）拖慢。
- 接近段与点动没有现场整定值，按目标速度/加减速的固定比例派生
  （`approach_ratio` / `jog_ratio = 0.2`，沿用改造前的整定值），需要时按轴覆盖。

## 后果

- 现场整定仍然只改 `motion_profile.py`；改轴接线要同步核对 `index` 与行程符号。
- `.elo` 生成器同步升级：回零必须用「设置回零运动参数」（带 `homeDir`）而非
  「设置单轴运动参数」；轴号用 `spec.index`（1/2）而非 0/1；插补组合号用
  `profile.axis_mask`（`0x06`）而非硬编码 `3`。这三处是改造前潜伏的 bug（原样生成
  的 M2 脚本回零方向与轴号都是错的）。
- `current_xy()` 更名为 `current_yz()`；`Station` 字段 `x,y` → `y,z`；前端巡检台原型
  的假想 X-Y 包络 `350–2850 / 250–390` 随之换成实测 `Y 0–4492 / Z -212–0`。
- 控制器地址随实测更新为 `192.168.1.239:8088`（出厂默认 `192.168.0.30`）。

## 补充（2026-09-12）：回零速度有下界

现场原整定 `home_speed` **Y 150 / Z 50 mm/s**，**高于巡检速度**（Y 50 / Z 20）2.5–3 倍——
与"回零是找硬限位、应当更慢"的常规做法相反。经授权下调为 **Y 90 / Z 20**。

下调中定下一条**不变式**。回零是"从行程内任意位置出发、向固定的限位开关找开关"，
最坏起点在行程另一端，所以**寻零距离按全行程估**；而控制器 `homeTime`（Y/Z = 100 s，
2026-09-12 实测）一到就中止回零并置位 `MACHINE_HOME_OVERTIME`——后果是**原点不可信**
（`fmc.errors.HomeTimeoutError`），不是"慢一点"。因此：

```
home_speed ≥ travel_span × 余量系数 / controller_home_time
```

- **Y**：取 2 倍余量时 `4492 × 2 / 100 = 89.8 mm/s`，**90 就是贴着这条线取的值**——
  即"在 2 倍余量下，Y 已经不能再慢了"。最坏寻零 ≈ 50 s。
- **Z**：212 mm 行程无压力（最坏 11 s），直接取巡检整定值 20 mm/s。

取舍写在这里以免后人误改：**想让 Y 更慢，就必须抬高控制器 `homeTime`**，而那会把
"限位开关坏了"时的硬顶时间从 100 s 变成 200 s——用机构损伤换速度，**不建议**。

该不变式由 `test_home_speed_keeps_margin_under_controller_home_timeout` 守护：
测试中硬编码了实测的 `homeTime`，任何把速度调慢的改动都会直接失败，
而不是等到现场出现"回零随机超时"。

## 补充（2026-09-12 晚）：巡检档整定，以及**两段速段序写反**的修复

两项一起做，因为量级差一个数量级——**先修段序，再谈速度**。

### 一、两段速的段序写反了（bug，与速度无关）

`Fmc4030.goto` 与 `elo.generate` 都把两段的限值喂给了错的那一段。判据是
`approach_point(prev, target, offset)` 的语义：它返回「距 target 沿来向退 offset mm」的点，
所以 `prev → mid` 是**空程**（该全速），`mid → target` 才是最后 ≤offset mm（该降速防过冲）。
代码给反了，于是：

- 站间空程按**接近档**（0.2×）爬行 → 一轮纯运动 2106 s（35 min）而不是 452 s；
- 最后 5 mm 反而按**巡检档**全速冲到位 → "接近段降速防过冲"的设计目的同时失效。

修正：有接近段时空程用巡检档、最后 ≤offset mm 用接近档；**没有接近段**（`offset=0`，
或来向距离 ≤ offset）时整段就是空程，按巡检档走——接近档只服务于"最后几毫米"。
M1 与 M2 共用同一段序（单源原则），段序由断言钉住：
`test_goto_two_phase_motion`、`test_goto_short_move_single_segment`、
`test_station_block_and_approach_chain`。

### 二、整轮时长的口径错了 5 倍

`motor-command-review.md` §2.5 原先写"一轮时长下界 ≈ 86 s"，那是**只算了一层**的横向空程
（4118 mm）。蛇形遍历 5 层，每层都要横着走满一遍：真实 Y 空程 = 5 × 4118 = **20.8 m**。
口径错 5 倍会把"提速值不值得"的结论直接带偏，所以模型固化成可重跑的脚本
`.scratch/prod-deploy/speed-tune.py`，而不是文档里一行字。

### 三、巡检档 50 → 150（Y）

| 依据 | 值 |
| --- | --- |
| 控制器脉冲上界（**与机械无关**的硬上界） | 200 kHz ÷ 1052.632 脉冲·mm⁻¹ = **190 mm/s** |
| 现场依据 | Y 的**回零**档现场给的就是 150/1500（同为 `acc = 10 × speed`） |
| 原先的 50 | 双轴改造时按"假想机器"推的，**2026-09-12 已确认没定过** |

取 **150 mm/s = 158 kHz = 上界的 79%**，acc 1500（升速时间恒 0.1 s，与现场比例一致）。

- **点动档不能跟着放大**：`jog_ratio` 默认 0.2 会把 Y 点动推到 30 mm/s（示教时肉眼跟不上），
  故显式取 `10/150` ⇒ 点动 10/100，恰好等于改造前现场值。
- **Z 巡检档不动**（20/200）：一轮只有 4 次换层动作、合计 191 mm，提速收益 < 5 s/轮，
  不值得为它去动竖直轴（重力负载 + 无编码器）。
- 守护测试：`test_travel_speed_stays_under_controller_pulse_ceiling`（≤ 0.85 × 上界）、
  `test_derived_ladder_matches_the_pre_migration_tuning`（150 / 30 / 10 阶梯）。

效果（60 站位，含单站 1.75 s 固定开销，采图按 1 s 估）：

| 版本 | 一轮 |
| --- | --- |
| 改造前（段序反 + Y 50） | 36.8 min |
| 只修段序（Y 50） | 9.5 min |
| 修段序 + Y 150 | **4.6 min** |

✅ **现场验收通过（2026-09-13）**：用户在产线上实跑确认 **150 mm/s 可用、速度可接受**。
原先唯一的残留风险是「驱动器 FMDD50D40NOM 无手册、最大输入频率未知」，此项由现场验收关闭。
理论侧佐证：现场给的 Y **回零**档本来就是 150/1500，说明这条轴在本机历史上跑过 150。

⚠️ **一条技术注记**（不阻碍启用，但别把它当成"已做丢步判定"）：150 mm/s 下的丢步是**静默**的——
控制器位置计数器只数**发出去的脉冲**，丢步时 `real_pos` 照样报"到位"，表现为**采图偏位**而非报错。
所以"速度可接受"这一验收结论**不蕴含**"没有丢步"。定量判据只有一个：**限位基准法**
（用硬限位当物理基准，阈值 0.2 mm，见 `motor-command-review.md` §2.2.1 第 2 步），
建议在首轮全量巡检后顺手补做一次。脚本保留：`.scratch/prod-deploy/travel-speed-check.py`。

## 四、回零约定的现场实证（2026-09-13）

**约定**（用户 2026-09-12 定稿）：**Z 轴向上回零后为 0 点；Y 轴反向回零后为原点。**
即本文件 `_Y.home_dir = HOME_DIR_NEGATIVE`、`_Z.home_dir = HOME_DIR_POSITIVE`，
两轴 `home_position` 均为 **0**——代码与约定一致，无需改动。

在 prod 上完整跑了一遍回零周期并逐帧记录状态字（50 Hz，Y 轴从 +499.999 mm 出发）：

| t | `axisStatus` | 位含义 | `realPos[Y]` |
| --- | --- | --- | --- |
| 0.001 s | `0x0648` | HOME_DONE（**上一轮的残值**） | 499.999 |
| 0.022 s | `0x0681` | **HOMING** + RUNNING（`home_done` 被清零） | 499.858 |
| 5.650 s | `0x0491` | HOMING + **LIMIT_N** | −3.522（撞负限位） |
| 6.028 s | `0x0681` | HOMING | +0.800（脱落回退） |
| 7.605 s | `0x0491` | HOMING + LIMIT_N | −1.995（**二次精碰**） |
| 7.901 s | `0x0648` | HOME_DONE | **0.000** |

四条结论，都直接支撑上面的整定：

1. **方向确为负限位**：回零过程中触发的是 `LIMIT_N`（负限位），与 `home_dir=2` 一致。
   Z 轴同样以 `homeDir=1`、耗时 4.82 s 从 −40 mm 回到 0.000。
   交叉验证（更省事的判据）：从已知位置出发回零，**耗时是否只够走"离开的那点距离"**——
   Y 从 +100 出发用 3.62 s（若方向反了要走 4392 mm ≈ 49 s，差一个数量级）。
2. **落点精确等于 0**，两轴都如此。这关闭了「`home_release` 脱落距离会不会让静止点变成
   ±5 mm」这个悬置问题：控制器是**先脱落回退、再置零**，所以静止点就是坐标系原点。
   本文件 `travel_*` 的区间端点因此可以直接取 0（Y 的 `travel_min`、Z 的 `travel_max`）。
3. **回零是两段式**（找开关 → 脱落 → 再精碰 → 置零），所以耗时不是"路程 / `home_speed`"。
   Y 从 +100 出发的理论寻零时间只有 1.1 s，实测 3.62 s——差额就是脱落与二次精碰。
   §4.1 的 `homeTime` 下界推导用的是**纯路程**，因此是保守的（偏严），无需修正。
4. **`home_done` 不会被普通运动作废**：Y 点动到 100 mm 后它依然为 True。它的语义是
   "坐标系已建立"，不是"现在位于原点"。这一条是 ADR-0010 那个竞态的根源。

现场流程与逐阶段输出见 `.scratch/prod-deploy/m0-commission.py`（默认只读，`--go` 才动作）。

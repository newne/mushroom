## 真实差集（核出来的，可直接收）

### 缺口 A（功能性，实锤）：下拉直接选轮次会留下过期状态
`#roundSel.onchange`（`:3039`）是 `loadRoundImages($('#roundSel').value)`，**绕过了 `syncRoundOptions()`**，
而按钮路径 `switchRound()` 最后会调它（`:2547`）。后果，当 `rounds.length > 1` 且新选的不是列表首个时：
1. `hist.roundIndex` / `hist.roundCount` 停在上一个值 → `#roundnavinfo` 仍显示旧轮次、"第 N / M 轮"错位（`updateRoundNav()` 只由 `syncRoundOptions()` 调，`:2524`）；
2. `#prevround`/`#nextround` 的置灰状态是上一轮算的（`:2503-2504`）——到边界时按钮亮着、点了才弹"已经是最早一轮"；
3. 不清 `hist.focusedStationId` → 违反"换轮次先看整体"（`:2543` 只写在 `switchRound()` 里）。

### 缺口 B（可视缺陷，实锤）：窗口缩放后拼图格子不重算
格子宽只算一次（`:2260-2268`，`tl.clientWidth`），**全文件没有任何 `resize`/`ResizeObserver`**：
`grep` 命中的窗口级监听只有 `window.addEventListener('blur', …)`（`:1941`）、
`window.addEventListener('mousemove'/'mouseup', …)`（拖拽，`:3115-3119`）。
窗口变宽/变窄后格子保持旧尺寸直到下一次 `renderHistory()`。这正是另一写者自己承认的遗留。

### 风险 1（注释/契约过期，不是行为缺陷，但会误导下一个改这页的人）
`web/console/index.html:560-561` 还写着"完整图像就在它**旁边**"、"不要单独的预览大图卡，
点格位在旁边看整张就行"——这是**第二轮**口径；第四轮已改"大图放预览上面、吃满整栏"
（`:113-118`、`:143-150`），`issues/06-…md:61-68` 也记了。按注释改回去就会把第四轮弄坏。

### 风险 2（口径脆弱）：④ 靠"整卡滚到顶"实现，靠注释而不是靠结构保证
"换轮次默认看到拼接图"= 滚到 `#mosaiccard` 的 top（`:2551-2555`）。若以后在拼图卡顶部再加内容
（筛选条、对比条），第一眼就不再是拼图。要保住口径应该把"拼图可见"写成断言，而不是靠滚动副作用。

### 并集事实（不是缺口）：跨轮次/跨天对比目前只能靠"换轮次看大图"
要点一下才知道换的是哪一株，没有"同一位置 N 天并排"的视图。**这是新方向下的真缺口，见下。**

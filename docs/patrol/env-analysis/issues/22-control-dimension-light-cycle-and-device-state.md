## 0. 前提（2026-10-15 实测 —— 它直接改变了本票的范围）

- `OnMSet`/`OffMSet`/`OnSSet`/`OffSSet`/`Running` **已经采集**：环境接口的日行已经出 `lamp_state`/`lamp_on_m`/`lamp_off_m`/`lamp_on_s`/`lamp_off_s`/`lamp_on_min`。
- TDengine 的补光灯表**已经有** `OnOff1..4`（分路开关）与 `Choose1..4`（白 / 蓝），但采集侧只取五列 ⇒ **本票是「扩列」，不是「从零落库」**。
- `Running` 是**设备状态**（0=自动 / 1=手动 / 2=停止 / 3=关闭），**不是"灯亮没亮"**；`lamp_on_min` 由设定周期**推导**，是**设定值不是实测值**（代码注释已写明这件事）。

## 1. 交付物

1. **扩列**：把 TDengine 里已有但未采的 `OnOff1..4`、`Choose1..4`、`Model` 纳入采集与小时聚合。
2. **设备状态维**：确认空调 / 加湿 / 冷风机的 `Model`/`Running` **有没有数据源**；有则同法纳入，没有则**显式登记"无数据源"**。
3. **制度序列**：按**设定变化点切段**，给出"这个生长阶段的补光循环是什么、改过几次"（不是逐小时重复同一行）。
4. **卡片消费**：环境模式「补光」卡片显示循环制度；「实际占空比」只在有实测依据时才出。

## 2. 验收（缺一条不算过）

- [ ] 制度序列可按生长阶段切片，**改过几次**可数（例：09-17 是 2 分钟亮 / 30 分钟灭，其后改为不补光）
- [ ] "设了没开"看得出来（设定与实际不一致时可见）
- [ ] 无数据源的维度显式标"无数据源"，**不显示成 0**
- [ ] **对 TDengine 只有读**：本票任何代码路径都不含对 TDengine 的写或 DDL
- [ ] 落点全部在 PostgreSQL（业务数据），必要时 Redis 做缓存

## 3. 不做什么

- **严禁修改或写入 TDengine**（它是源历史数据的权威存储）
- 不把 `lamp_on_min` 当实测值
- **不用 `Running` 积分冒充"点亮分钟"**
- 不改既有列语义、不删旧字段

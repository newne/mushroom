# ADR-0016：手动控制的执行侧——唯一执行者、急停是闩锁、指令有新鲜度

日期：2026-09-14
状态：已接受
背景：巡检台的手动面（接管会话 / 指令 / 急停）在 ADR-0013 里定了"谁来收"和"什么时候
不许动"，但没有回答执行侧的问题：**谁去碰控制器、被打断时怎么办、十分钟前点的指令还算
不算数、放手时机器停在哪**。这几条都直接关系到一台会自己走 4.5 米导轨的机器的安全，
必须在写代码时定下来，而不是留给现场临场判断。

现状：console（`deploy.console`）没有厂商 SDK、也不许连控制器（单会话设备，第二个连接
会把正在跑的那一轮踢掉）；`patrol-serve` 是唯一持有控制器的进程，且单实例。两者之间
只有文件（`data/trigger/`、`data/cmd/`）。

## 决定

1. **执行者唯一**：只有 `patrol-serve`（`deploy.manual_exec.ManualExecutor`）执行手动
   指令。console 只写"想做什么"，永远不碰控制器，也不碰厂商库。
2. **急停是闩锁，且能打断正在跑的那一轮**。急停写成一个独立标志文件（不进指令队列）；
   等待原语（`wait_stop` / `wait_home` / `goto` / `move_axis` / `home_all`）新增
   `abort` 回调，每轮询一次；为真即抛 `MotionAborted`——**下发之前先拦，运动中随时停**。
   置位期间只有"关灯"与"再停一次"被放行，其余一律拒绝；复位是独立动作，不随指令自动清掉。
   这条判断只有一处实现（`deploy.manual.estop_allows`），console 用它给出**当场**的话、
   执行方用它做**最终**把关；而且它**优先于其他一切拒绝理由**——"急停还按着"比"上一条
   没结束"重要得多，说错了会让人以为再等等就能动。
3. **指令有新鲜度**：提交后超过 60 秒才被领走的指令**不执行**，结果里注明"已过期"。
   手动操作是"此时此地"的动作；反过来说，正常路径上执行方的轮询是 0.5 秒，只有"中间
   隔着 11 分钟的一轮"才可能过期——而那正是我们希望它别执行的情形。
4. **轮内拒绝在 console 当场做**：巡检进行中（`patrol_state().active`）提交指令直接
   409，并带上"预计 x 分钟后可用"（按已完成站数外推）。执行方的过期判定只是兜底。
5. **放开会话 = 回零 + 撤权**。手动点动之后，坐标系与实际位置的关系只有操作者知道；
   本机无编码器，两端硬限位是唯一的物理基准，只有回零能把两者重新对齐。排不上回零
   （轮内 / 通道忙）时接口**明说没排上**，不静默跳过。
6. **手动抓拍不移动机构**：拍当前位置，站位号是操作者给的归属，记录里存**实际坐标**
   （`yz`），并标 `manual: true`（prod 的 `images` 表只取约定列，多余字段被忽略）。

## 决定理由

- 与 ADR-0011 的边界一致：`patrol` 库内不发网络、不读标志文件；它只接受 `abort()` 回调，
  由部署侧（`deploy.m1.make_estop_check`）把"标志文件在不在"接上去。库因此仍然可测、
  可逐行审计。
- 急停必须能打断**正在跑的那一轮**：否则"急停永远可用"（ADR-0013）就只是句空话——现场
  看到的是"按了急停，机器又走了一站"。等待原语是最小、最可靠的切入点（每一步运动都要
  经过它）。
- 闩锁而不是一次性动作：急停的语义是"停下来别动"，自动复位（例如被下一条指令顺带清掉）
  会让"我按了急停但它又动了"重新出现。
- 新鲜度上限而不是无限排队：队列里的手动指令是**危险**的——它会在没人看着的时候动机构。

## 后果

- 手动指令是**异步**的：页面提交后轮询 `GET /api/cmd` 拿结果。这一点在页面设计时就接受
  了（ADR-0006 的 REST + 轮询）。
- 急停延迟 = 执行方的轮询周期（0.5 s）+ 等待原语的检查周期（0.1–0.2 s），约 1 秒量级；
  它是**软件急停**，不替代硬件急停回路。
- 巡检与手动共用一份站位表 / outbox / 入库日期（`patrol-serve --cmd-dir` 透传给
  `deploy.m1`）：参数分叉会造出"手动用的表和巡检不是同一份"这种事。
- 轮内提交的指令若在轮末 60 秒内，仍会执行；更早的一律过期。等位交接（yield 握手）仍然
  不做（ADR-0013）。

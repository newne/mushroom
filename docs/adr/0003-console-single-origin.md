# ADR-0003：巡检台作为独立部署单元，浏览器只与单一 origin 通信

日期：2026-09-10
状态：已接受
背景：需要新增前端界面（实时控制 + 历史回溯）。当前全仓库没有任何前端代码，也没有任何
对外的运动控制接口：`Fmc4030`（FMC4030 私有 SDK，ctypes）只在 patrol 进程内被调用，且
`patrol.links` 明确"库内不发起网络调用"，真实传输由部署侧注入。现成可直连的只有
`capture`（:7003 采图）与 prod 的 `analysis`（:8000 查询）。同时现场是菇房内网，
浏览器很可能既到不了 prod（10.77.77.39）也到不了 MinIO endpoint。

## 决定

- **console** 是一个**新增部署单元**，与 patrol 同机（库房主机）运行，由它提供静态页面与
  控制/查询 API。
- **浏览器只与 console 这一个 origin 通信**：导轨控制、站位表、历史图像与测量数据全部经
  console 转发或代理，页面不直连 `capture`、prod 或 MinIO。
- 图像交付方式（MinIO 预签名 URL 还是后端流式转发）为 console 内部实现细节，**MinIO 凭据
  与对象名不出现在浏览器可见的配置里**。

## 决定理由

- 菇房现场通常只有内网；单一 origin 同时解决可达性与 CORS，不需要给 prod/MinIO 开公网口。
- 控制面必须与运动进程同机（FMC4030 是进程内 ctypes 调用，且控制器为单一 TCP 会话），
  把 UI 放在 prod 侧会强行引入一条"公网 → 库房主机"的运动指令通道。

## 后果

- console 是本系统**唯一**需要暴露到现场局域网的服务；`capture` 与 FMC4030 均可继续只监听
  回环/内网。
- 所有页面数据契约在 console 边界内收敛，prod 侧只需按 ADR-0001 的 ingest 语义扩展查询端点。
- 若未来要做多库房（多台 patrol），console 需要引入库房选择器与多 origin 管理；本 ADR 只
  覆盖单库房。

# ADR-0004：手动控制与自动巡检互斥，实时模式须先让位

日期：2026-09-10
状态：已接受
背景：FMC4030 是**单一 TCP 会话**的控制器（出厂 `192.168.0.30:8088`，1 分钟无交互即断开，
需 ≤30s 心跳），而 M1 巡检守护进程常驻占用它并驱动导轨。巡检台要提供的"实时模式"意味着
操作者直接指挥同一台控制器。两者不可能同时驱动导轨——这不是 UI 问题，是硬件约束。

## 决定

- 巡检台存在**两个显式状态**：`SCHEDULED`（巡检守护运行时）与 `MANUAL`（实时模式会话
  持有导轨）。二者**互斥**，不存在共存的第三种状态。
- 进入实时模式：先 `stop_all()`，再请求守护进程让位（停在安全位、不中断当前轮次数据）；
  退出实时模式后守护进程可恢复。
- 实时模式**仅在 M0 语义下**接受运动命令（`home / jog / abs / goto / lamp / stop`），不绕过
  `MotionProfile` 的速度与加减速参数（ADR-0002 单源）。
- `goto` 前用站位表的 x/y 包络做**软限位校验**，越界拒绝下发，而不是依赖控制器报错。
- `home` 与 `goto` 需要操作者二次确认；`stop` 为全局急停，**无需确认且永远可用**（等效
  `Fmc4030.stop_all()`）。
- 权限：先做"内网即可用 + 可选口令"；操作者须持有当前会话（会话过期即视为退出实时模式）。

## 让位时机（第 2 轮补充，2026-09-10）

- 让位发生在**站间空程**：当前站位完成采图并关灯后，在前往下一站位的空程中停到安全位；
  该轮 `PatrolRound` 标记为 `yielded`，退出实时模式后从**下一站位续跑**（已完成站位不重拍）。
- 若此刻正处在某站位的开灯/采图窗口内，等该站位收尾再让位；让位请求设**最长等待 30s**，
  超时则拒绝并回 `409`，界面提示"轮次采图中，请稍候"。
- 实时模式下允许把导轨开到任意坐标（含非站位坐标），但**仅在站位的 x/y 包络内**；退出实时
  模式前必须 `home`（双轴回零），以保证下一次 M1 巡检从已知原点开始——`goto` 的 `from_point`
  与 5mm 接近段都建立在"起点已知"之上。
- 急停（`stop_all`）在界面上**常驻、不随滚动隐藏**，且不受会话与让位流程约束。

## 后果

- 自动状态必须能向界面汇报"已让位 / 让位中 / 拒绝让位"，界面据此渲染状态条。
- 断线即失去会话：控制器 60s 空闲断链与浏览器掉线都必须使状态退回 `SCHEDULED`，避免导轨
  停在无人负责的手动状态。
- 因为"M0 语义"是复用的 `debug.py` 已有动词集，实时模式的实现是"把 CLI 命令映射成端点"，
  不是新造一套控制协议。

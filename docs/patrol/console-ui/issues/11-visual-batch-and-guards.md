## 这一批的原则：先收"能扫出来的缺陷"，不整片重刷

审美判断没法在无头回归里断言，所以我把它拆成两半：

- **纯观感的**：**不装作能自证**——由用户/现场看一眼再提具体诉求，我按诉求改。

**刻意不做**：不整片重刷配色/圆角/间距（现场是每天要用的工作台，大改会把可读性一起改坏）；
不把所有散落的字号/圆角一次性迁到 token（那是另一批，风险独立）。

## 改了什么（每条都带实证）

1. **清掉最后一处暗色主题遗留**：导轨平面图的 Z 锚点标签写死 `#8b98a5`
   （`review-20260918.md` P0-1 名单里的值，浅色界面上最浅、且与同排"层号"的 `#5b6b7d` 不一致）。
   改成同排的 `#5b6b7d`。**这是 P0-1 之后第二次抓到同一个值**，所以配了扫描断言（见下）。
2. **可读性下限**：拼图格小字原来是 **9px**、格内空态是 10px——现场远看/亮光下没意义。
   统一到 `--fs-micro:10.5px`，并让对比卡的小字也用它。配"CSS 里不许出现 <10px"的断言。
3. **键盘焦点环**：加 `:focus-visible`（只在键盘操作时出现，鼠标点完不残留一圈——后者在
   现场会被当成"按钮卡住了"），用 `var(--accent)` 描边 + `--focus-ring` 光晕。
   现场有人全程用键盘走点动/急停，焦点不可见比"不好看"严重。
4. 两个新 token 连同**理由**写进 `:root` 注释（`--fs-micro`、`--focus-ring`）。

## 加了 6 条"可扫描"护栏（全部 PASS）

| 断言 | 防的是 |
| --- | --- |
| 每个 `var(--x)` 要么有定义、要么自带兜底 | `--shadow` 那一类"用了没定义 ⇒ 静默失效"；`--cellw` 是 JS 注入+CSS 兜底，属合法，断言区分得开 |
| 没有暗色主题遗留硬编码（P0-1 名单 4 个值） | 这类补丁曾两次出现；注释里的**历史记载不算**（扫描前先去注释） |
| CSS 里没有 <10px 的 font-size | 可读性下限被悄悄改回去 |
| `button` 仍有 `min-height:44px` | 现场戴手套点不动 |
| `:focus-visible` 焦点环存在且用 accent 色 | 键盘可用性回归 |
| 主题变量只有一处 `:root` 定义 | 历史上"定义了两遍、各自漂" |

## 第二批：结构性改动（2026-10-13，Chief 指的顺序 ②）

**先量化，别拍脑袋**：`border-radius` 当时有 **12 种取值**（2/3/4/5/6/7/8/9/10/14/20/999），
`padding` 首值也有 12 种（1…16px）——确实"没有尺度"，但也说明**一次全改会动到密集布局**。

**做法：只收"与原值完全相等"的台阶 + 上棘轮**（这一批渲染结果不变，风险可控）
1. `:root` 加圆角尺度：`--r-xs:4px / --r-sm:6px / --r-md:8px / --r-lg:10px / --r-pill:999px`。
2. 机械替换**等值**的 23 处：4→`--r-xs`(4)、6→`--r-sm`(8)、8→`--r-md`(5)、10→`--r-lg`(4)、999→`--r-pill`(2)。
   剩下 16 处（2/3/5/7/9/14/20）**登记为欠账**，不在这一批里改。
3. 加三条棘轮断言（防止继续漂，而不是要求一次改完）：
   - **圆角**：新值必须是 `var(--r-*)` 或已登记欠账（谁再写个 11px 就红）；
   - **圆角 token 都得被用上**（不留死 token）；
   - **间距**：新值必须在登记表内（间距 token 化留待下一批，但先挡住新增）。
4. 间距登记表里有两个**别顺手改掉**的，已在注释里写明原因：
   `padding-left:7px`（选中站位的 3px 左边框**位移补偿**，改了文字会跳）、
   `padding-left:42px`（坐标输入框给单位徽标留位）。棘轮第一次就跑出这 4 个"未登记值"，
   逐个看过来源后才登记——**这一步不能省，否则棘轮会逼着人把有理由的值改坏**。

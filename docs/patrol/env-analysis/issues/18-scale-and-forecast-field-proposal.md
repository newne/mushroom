# 18 — 字段提案：菌杆平均长度 / 簇长势 / 菌帽后续长度（预测）+ 尺度基线

**Spec:** ../spec.md §2.2、§2.7、§5；票 11（measurements 契约）、票 16（长势量口径）

**状态：提案，**不动 DDL、不改代码**；等测量师的设计票出来后一起对齐，再由 Chief 裁定 §6。**

**任务来源（用户 2026-10-14）：** 测量侧要新增三个量 —— 菌杆平均长度、簇长势、
菌帽后续长度（预测）；尺度基线是"**用菌包直径做帧内标尺反推 mm/px**"。

## 0. 一句话结论

这三样里，**只有"簇长势"是测量量**；"菌杆平均长度"在平视单档下是**估算**（票 11 §9 说它
明确缺测），"菌帽后续长度"是**预测**。所以本票的核心不是加几列，而是**把"测量 / 估算 /
预测"三种性质在字段层面分开**，让任何下游（区间表、建议层、页面）都不可能把后两者
读成第一种。

## 1. 三个量的字段提案

### 1.1 菌杆平均长度（估算，不是测量）

| 提案 | 值 |
| --- | --- |
| 列名 | **复用 `mean_len_mm`**（不新造 `stem_len_mean_mm` —— 同一事实不许有第二个名字） |
| 单位 | mm |
| 性质 | **估算**：必须同时带 §2 的标记；平视下它**永远**是估算 |
| NULL 语义 | 没算出/没有标尺 ⇒ NULL（**不写 0**） |

⚠️ 这与票 11 §9 不冲突、但需要一条**追加口径**：§9 说"平视下盖径/杆长**明确缺测**、禁止用
平视近似冒充"。**估算不等于冒充的前提是**：① 显式标注来源是标尺反推（§2）；
② 下游**不许**把它当 `verified` 用（§2 的过滤规则）。缺任一条，就是票 11 §9 要禁止的那件事。

### 1.2 簇长势（测量量，定义待裁 —— 见 §3）

已有列就能承载大部分：`mean_cluster_w_mm` / `mean_cluster_h_mm` / `mean_area_mm2` /
`mean_projected_d_mm` / `n`（实例数）。**要补的只有"相对上一轮"**，而它是**派生量**（§3.4）。

### 1.3 菌帽后续长度（预测 —— 建议**不进 measurements**）

见 §4：**建议单独一张 `forecasts` 表**，幂等键含目标时点与模型版本。

## 2. "估算 / 预测"怎么表达（**绝不与 `verified` 混**）

新增四列（都在 `measurements` 上，除预测外）：

| 列名 | 类型/单位 | NULL 语义 | 说明 |
| --- | --- | --- | --- |
| `scale_source` | TEXT 枚举 | NULL = 没记 | 标尺来源：`bag_diameter`（菌包直径做帧内标尺）/ `calibration_target`（已知尺寸靶标）/ `none`（没有标尺） |
| `mm_per_px` | REAL，**mm/px** | NULL = 未知 | **实际用的那个比例**。有了它，任何 mm 值都能被复算/复核；没有它就只能是估算 |
| `scale_ref_mm` / `scale_ref_px` | REAL | NULL = 没记 | 参考物的真实尺寸与帧内像素尺寸（如菌包直径）。`mm_per_px ≈ scale_ref_mm / scale_ref_px`，可交叉验算 |
| `estimated_fields` | TEXT，`+` 分隔的**列名清单** | NULL/空 = 没有估算值 | 例：`mean_len_mm`、`mean_len_mm+mean_cap_mm`。**字段级**标记 |

**过滤规则（写给所有下游，与我票 11 §3 的 `verified` 口径叠加）：**

> 引用 `measurements` 的某个字段 X 时，必须同时满足：
> **`quality` 含 `verified`** **且** **X ∉ `estimated_fields`**。
> 不满足的，值只能用于**展示/探索**，**不得**进区间表、建议层或任何统计。

**再加一个行级 fail-safe flag：`estimated`（进 `quality` 串）。**
规则：只要 `estimated_fields` 非空，`quality` 里**必须**有 `estimated`。
理由：只看 `quality`、不看新列的消费者（现有的、以及将来的）也不会把估算读成测量。
`estimated` 与 `verified` **正交**（像 `no_angle_profile` 一样）：它不否定整行，
只表示"这一行里有估算值"。**`estimated` 单独出现时绝不算可用。**

**为什么不做"整行不可用"**：平视下杆长恒为估算，整行拉黑等于把整张区间表清空 ——
那和"删数据"没区别（票 11 §3 同一条教训）。

## 3. 簇长势的定义候选

| # | 候选 | 需要什么输入 | 缺哪样就出不来 | 我的意见 |
| --- | --- | --- | --- | --- |
| 3.1 | **面积 `mean_area_mm2`**（及其小时/轮次增量） | 检出掩膜 + `mm_per_px` | 无 `mm_per_px` ⇒ 只有 px²；整簇不可分 ⇒ 面积是估的（`low_confidence`） | **v1 主口径**（票 16 已按此实现，只是量纲要随 `unit` 显示） |
| 3.2 | **实例数 `n`**（及其变化） | 实例分割 | 整簇不可分（如 S306 的整帧回退）⇒ `n=0`，**不可信**；`n` 本身已有列 | **v1 一并给**，与面积互为交叉验证 |
| 3.3 | **高度分布**（`cluster_h_p10/p50/p90`） | 每簇顶/底像素 + `mm_per_px` | 缺 `mm_per_px` ⇒ 只能 px；缺逐簇轮廓 ⇒ 算不出 | 等测量侧确认能出再列；**不建议先进 v1** |
| 3.4 | **相对上一轮变化率** | 上一轮同 (room, box) 的**同一种**量 + 两轮都 `verified` | 上一轮缺测、或两次量不同 ⇒ 算不出 | **不进 `measurements`**：这是派生量，放 `growth`/`ranges`（票 16 已定"两点同时有值才比、异量不相减"） |

⇒ **建议 v1 的"簇长势" = {面积增量, 实例数变化} 两个并列指标，各带 `metric`/`unit`**，
不做加权合成为一个"长势分数"（没有现场定标之前，合成权重就是编的）。

## 4. 预测：菌帽后续长度 —— 建议单独一张表

新增 `forecasts`（**不混进 `measurements`**）：

| 列 | 类型/单位 | NULL 语义 | 说明 |
| --- | --- | --- | --- |
| `made_at` | TEXT，ISO8601 | 必填 | **预测时点**：做出这次预测的时刻（= 输入数据截至的时刻） |
| `target_at` | TEXT，ISO8601 | 必填 | **目标时点**：预测指向的未来时刻 |
| `room_id` / `box_id` | TEXT | 必填 | 与 measurements 同口径 |
| `metric` | TEXT | 必填 | 预测的是哪个量（如 `mean_cap_mm`） |
| `value` | REAL | 必填 | 预测值（单位随 `metric`） |
| `model` | TEXT | 必填 | **模型版本**（含版本号/训练批次标识） |
| `inputs_from` | TEXT | 可空 | 输入数据的起止（便于回放） |
| `note` | TEXT | 可空 | 备注 |

- **幂等键 = `(room_id, box_id, metric, target_at, model)`**：同一模型对同一目标时点重复预测
  ⇒ 覆盖；不同模型/不同目标时点 ⇒ 并存（**预测本来就会有多条**）。
- **隔离铁律**：预测值**永远不进** `measurements`、**永远不进** `verified` 统计；
  任何读取 `mean_*_mm` 的路径都不许回退到 `value`。若把预测塞进 measurements 的列，
  "只吃 verified"那层过滤会立刻变得脆弱 —— 这是分表的主要理由。
- 下游展示必须**三个一起显示**：值 + `target_at` + `model`（缺一个都会让人把预测当测量）。

## 5. 幂等与兼容

- `measurements` 主键不变：`(ts, room_id, box_id)`；新增列随行覆盖写。
- 加列仍走 `ADDED_COLUMNS` 就地迁移，老行 NULL = "那时还没记"。
- **顺序照旧：先落列 → 测量师发字段 → 下游启用过滤**（票 11/17 的既有纪律）。

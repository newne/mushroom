# 环境同期对照（env-baseline）设计规格

Status: ready-for-agent
归属：后端（analysis）为主；前端（web/console）承载视图；算法侧只消费
权威依据：本规格由 2026-10-15 grill-with-docs 会话产出，**20 个决定已由用户逐条裁定**（见 `docs/patrol/next-plan-2026-10-15.md §2）
相关：ADR-0020（批次身份）、ADR-0021（参数权威）、ADR-0022（实际参数为主）、ADR-0023（小时聚合）、ADR-0024（标定与四量权威——**本规格对其"区间表只吃已验证"作出修正**）
硬约束：**TDengine 是环境原始序列的权威且只读存储，严禁写入或 DDL**；业务数据落 PostgreSQL，热数据缓存用 Redis；方向永远只有 TDengine →（只读拉取 + 聚合）→ PostgreSQL（ADR-0026）
不做什么：本规格不产长势信号、不做产量归因；不写 TDengine

## Problem Statement

现场看环境数据时，有四件事答不上来：

1. **只有均值曲线，看不出"每天散成什么样"。** 运维真正关心的是"这个阶段温湿度波动大不大、有没有冲出去"，而一根均值线把这些信息全抹平了。
2. **没有"和历史批次同期比"的东西。** 今天第 12 天的 14:00 温度 22.3℃，这算正常吗？库里明明有同库房 3 个历史批次的小时级数据（四房在线 2608 行），但页面上没有一处把它和当前批次对齐着看。
3. **光照这一维口径不对。** 现在按"累计点亮分钟"算，而运维要的是"**不同生长阶段的补光循环是怎么开的**"——开几分钟、关几分钟、哪几路、白光还是蓝光。一个积分值答不了"循环是怎么设的"。
4. **两处观感/对不上号。** 环境模式的明细表在 1366×768 的现场机上有**字体重叠**；批次显示成 `mogu-107`，和现场的"库房 + 入库日期"对不上。

## Solution

在环境模式（以及后端接口层）补齐"**同期可对照**"这件事：

- **按生长天数的分布视图**：当前批次 vs 最近一批，三面板箱线（温度 / 湿度 / CO₂），x 轴是生长天数。
- **同期基线**：同一**生长天数 × 同一日时刻**，历史批次**逐批可见、可切**；样本不足不给带；跨季节显式标注。
- **调控维**：光照从"累计点亮分钟"改为"**补光循环制度**"；并把空调、加湿、冷风机的**运行模式**并进同一维，用来解释"为什么两批的温湿度不一样"。
- **每轮环境快照**：按巡检轮次给出一条房间级环境记录（三维 + 采样点数 + 调控维 + 设定末态），供页面与算法侧共用同一个时间锚。
- **批次显示**改为「**库房 · 入库日期**」为主，业务名作附注。
- **修字体重叠**（只修已确证的那一处）。

## User Stories

1. 作为巡检人员，我想在环境模式看到「当前批次 vs 最近一批」按生长天数的**温度箱线**，这样我能一眼看出这一批每天是偏了还是散了。
2. 作为巡检人员，我想看到同口径的**湿度箱线**，这样我能发现阶段性偏干/偏湿。
3. 作为巡检人员，我想看到同口径的 **CO₂ 箱线**，这样我能发现通风不足的时段。
4. 作为巡检人员，我想在图上**切换"对比哪一批"**，这样我能挑时间上最接近的那批来比。
5. 作为巡检人员，我想看到本批相对历史同期的**偏离**（而不是只给一条带），这样我知道现在是偏高还是偏低。
6. 作为巡检人员，我想让同期基线**逐批可见**而不是只给一条汇总带，这样我能知道这条带是哪些批次凑出来的。
7. 作为巡检人员，我想在样本不足时被**明确告知"样本不足"**，而不是看到一条假的平滑带。
8. 作为巡检人员，我想在看到「**跨季节**」标记时知道基线混了不同季节，这样我不会把它当规律。
9. 作为巡检人员，我想看光照的**循环开关制度**（开几分钟 / 关几分钟 / 哪几路 / 白光还是蓝光），而不是一个累计点亮分钟，这样我能判断这个阶段的补光策略。
10. 作为巡检人员，我想**按生长阶段**看到补光制度改过几次、改成什么，这样我能复盘调控动作。
11. 作为巡检人员，我想看到**空调 / 加湿 / 冷风机**的运行模式，这样我能解释为什么两批的温湿度不同。
12. 作为巡检人员，我想让**设定与实际**（灯的实际占空比）并排显示，这样我能分辨"设了没开"和"压根没设"。
13. 作为巡检人员，我想按**巡检轮次**看到该轮的环境三维（含采样点数），这样我能把生长曲线和环境对到同一个时间锚上。
14. 作为巡检人员，我想在某一轮环境数据缺失时看到「**不可比**」，而不是被补一个邻近小时的值。
15. 作为巡检人员，我想看到批次显示为「**611 · 2026-09-30**」、`mogu-107` 作附注，这样我和现场台账对得上。
16. 作为巡检人员，我想看到**断档**（某小时采样点不足 60），这样我知道那一段不可信。
17. 作为巡检人员，我想在所有卡片都空的时候看到**明确的空态原因**（没有环境 / 没有可对照批次 / 样本不足 / 从未计算），而不是空白图。
18. 作为巡检人员，我想在 **1366×768** 的现场机上不看到字体重叠，这样我能读清明细表。
19. 作为巡检人员，我想在区间表里看到"**这一批落在历史什么位置**"，并且明确知道它是估算档、不能当验证值。
20. 作为研究员，我想让**估算档与已验证数据不混算**，这样我的结论不会被临时数据污染。
21. 作为研究员，我想让**建议层永不消费估算档**，这样调控建议不会建立在未验证的输入上。
22. 作为后端工程师，我想让同期基线在**每天固定时间**重算、且**已结束的批次封版**，这样页面上的历史值不会自己变。
23. 作为后端工程师，我想让**当前批次滚动更新**，这样"今天能看到今天"。
24. 作为后端工程师，我想让同期基线在**批次变更时立即重算一次**，这样换包当天不会还显示旧批次的基线。
25. 作为后端工程师，我想让回填给每个批次标上「**可对照 / 不可对照**」，这样缺段的批次不会被拿去凑数。
26. 作为后端工程师，我想让**数值口径只有一处**（小时聚合行），这样箱线、基线、快照不会各算一套。
27. 作为前端工程师，我想让箱线图只依赖后端给的**五数**（min / q1 / median / q3 / max / n），这样页面不用引图表库。
28. 作为前端工程师，我想让箱线图的几何计算是**纯函数**，这样它能被无头回归测到。
29. 作为算法工程师，我想按巡检轮次取到**环境快照**，这样我的生长曲线能带上环境背景。
30. 作为算法工程师，我想让测量行带上**巡检轮次标识**，这样轮次与环境不再靠时间窗猜。
31. 作为运维，我想让新的环境接口被 **console 反代**、保持单 origin，这样浏览器侧不需要第二个地址。

## Implementation Decisions

**模块**

- **后端（analysis）**：新增三个**只读**接口——同期基线、按生长天数的分布、每轮快照——与既有环境接口**同族**，共用信封约定（状态词 + 空数组，绝不返回伪造的 0）。区间表的"估算档"改造也在这一层。
- **console 反代**：为上面三条新增代理路径，**单 origin 不变**。
- **前端（环境模式）**：手写内联 SVG 画箱线，**页面不引图表库**（沿用环境页既有做法）。

**接口形状**（type shape；字段名以契约为准）

```
GET /environment/distribution?room_id=&metric=temp|rh|co2&by=growth_day
{ state, flags[], points: [ { batch_key, entry_date, growth_day,
                             n, min, q1, median, q3, max } ] }

GET /environment/baseline?room_id=&metric=&batches=N
{ state, flags[], generated_at, baseline_version,
  points: [ { batch_key, growth_day, hour_of_day, n, median, q1, q3 } ] }

GET /environment/rounds?room_id=&limit=
{ state, flags[], points: [ { round_id, ts, hour_ts,
                             temp:{mean,min,max,n}, rh:{...}, co2:{...},
                             light:{...}, controls:[...], setpoints:[...],
                             growth_day, comparable } ] }
```

**状态与标注**

- 状态词**沿用既有信封风格**，**只新增 `insufficient_batches`**（可对照批次 < 2 或每点 n < 3）。
- 「**跨季节混合**」是 `flags` 里的**标注**，**不是状态**——它在当前数据下**永远为真**，做成状态会让接口长期停在非 ok 态。
- **n < 3 不给带**；缺小时的轮次标 `comparable=false`；**不许邻近顶替**。

**重算与封版**

- 挂**每日链**，跟在区间表重算之后（`BASELINE_AT`）；**批次变更时**额外触发一次。
- **已结束批次封版**（值不再变，除非回填）；**当前批次滚动**。

**同期口径**

- 键 = 「**生长天数 × 同日时刻**」。**逐批可见**，不给"把 3 批揉成一条"的汇总带。
- 版本号随口径变化递增；口径变更**写新行不覆盖旧行**。

**调控维**

- 光照主对象 = **补光循环制度**：开 / 关的分钟级设定、秒级设定、分路开关、白 / 蓝选择、模式。
- **实际占空比**由运行状态派生，与设定**并排对照**——用来分辨"设了没开"。
- 空调、加湿、冷风机的**模式与运行状态**并入同一维。
- 原「累计点亮分钟」**降为派生对照**，不再是主口径（**改写既有 lamp-hours 票的交付物**）。

**估算档（区间表）**

- 独立状态（「仅估算」）、**整维标注「未验证」**、**不得与已验证行混算**、**不进建议层**。
- **修正 ADR-0024 的"区间表只吃已验证"**；该修正登记为一条 ADR。

**每轮快照**

- **每轮一条**（房间级），键 = 巡检轮次 ID；含**采样点数 n**；含该小时**设定末态**。
- 环境是房间级的量，48 个站在同一轮里时间差 < 1 小时，逐站重复只是冗余。

**批次显示**

- 主显示「库房 · 入库日期」，业务名作附注。**入库值与历史列一律不动**（历史对账不能断）。

**字体重叠**

- 泳道标签的纵向偏移**从车道高度派生**，不再硬编码（车道高度被压缩后，两个标签的基线只剩 4px 间距 ⇒ 必然叠字）。
- 另两处疑似重叠**需真机截图**，本规格只修已确证的一处。

**前置依赖（本规格之外，但缺了它就跑不起来）**

- analysis 容器**重建**一次（当前线上缺批次台账端点，且台账已陈旧）。
- 一次**只读盘点**：环境数据可回溯的最早时刻、以及环境表是否已有补光列。
- **批次清单对齐**（台账补跑 + 缺映射行核对）——否则同期基线说不清对照的是哪一批。
- 测量行加**巡检轮次标识**（算法侧并行推进）。
- **环境回填**到可回溯的最早，逐批标「可对照 / 不可对照」。

## Testing Decisions

**什么是好测试**：只断言**对外行为**——HTTP 状态、信封状态词、以及五数之间**必须成立的关系**（`min ≤ q1 ≤ median ≤ q3 ≤ max`、`n` 与样本数一致、n<3 时**不出带**）。**不断言**内部函数、不断言某个具体数值来自哪一行、不 mock 数据源内部。

**主 seam（唯一必需的）**：后端 HTTP 接口。三个新端点与区间表的估算态都在这一个 seam 上验，用**临时库 + 测试客户端**，与既有环境接口、区间表状态、批次端点的用例**同一套写法**。

**次 seam**：
- **console 反代**：只验"新端点被代理、响应形状一致"，不重复业务断言。
- **前端纯函数**：「五数 → SVG 几何」按既有**无头回归页**的模式测（同一条五数必须得到同一组坐标；n<3 不画箱体）。

**Prior art**：既有的环境接口用例、区间表状态用例、批次端点用例、以及 console 页的无头回归脚本——本规格不引入新的测试范式。

## Out of Scope

- **产量归因**：产量表 `fresh_weight` 全为 NULL，一个批次都没录过，做出来是一列空。
- **长势信号本身的产出**：属算法线（簇级像素趋势）；本规格只**消费**。
- **严格同期**（每季 ≥ 2 批）：现有 3 个历史批次分属 12 月 / 3 月 / 8 月，做不到分离"季节"与"管理"，故只做**弱同期基线**。
- **另两处疑似字体重叠**：缺真机截图，凭推断改版式会把没坏的地方改坏。
- **毫米 / 绝对尺寸**：实际尺寸映射已由用户裁定延后。
- **建议层消费估算档**：明确禁止。
- **照度**：无数据源，保留列但不显示成 0。

## Further Notes

**已接受的风险（写下来，别让它变成惊讶）**

- 同期基线只有 **3 个可对照批次且跨季节** ⇒ **只作参考**：n<3 不给带、跨季节打标注、**禁止归因**。
- 产量全 NULL ⇒ 同期对照**只对照环境本身**，不带结果列。
- 本批有**停采边界**（入库后第 25 天）⇒ 本批结束后同期基线**只增不减**，界面不应因此显示为异常。
- 环境表是否已有补光列**无任何记录** ⇒ 盘点结果决定调控维是"**加列**"还是"**补值**"；这是后端 DDL 评审的输入。

**与前序文档的关系**

- 本规格是 `docs/patrol/next-plan-2026-10-15.md 中**环境线**（E4–E11）的规格化，不重复算法线的规格。
- 既有环境单页规格（数据口径、小时聚合、断档口径）**继续有效**；本规格只**新增**同期与分布两件事，并**修正光照一维的口径**。
- 区间表的"估算档"修正是对 ADR-0024 的**有意修正**，必须同时立 ADR，否则将来读 ADR-0024 的人会以为代码错了。

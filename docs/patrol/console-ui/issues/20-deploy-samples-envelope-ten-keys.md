# 20. 部署态验收样本升到十键信封（票 26 后遗留的口径漂移）

Status: ready-for-agent
归属：前端（+ 测试配合重导样本）
依据：env-analysis 票 26 交付的 `/ranges` 信封新增 `flags`；console-ui 票 19 的实现记录
依赖：— （但**下次部署态验收之前必须做掉**）

## 0. 问题

票 26 之后 `GET /ranges` 的信封是**十键**（多了 `flags`，用于整维标注「未验证」），
而部署态验收脚本 `docs/patrol/console-ui/verify-deploy-samples.js` 的 `NINE` 常量仍按**九键**校验。
⇒ 用现有样本跑部署态验收，要么误判失败，要么因为样本是旧版本而"看起来通过"——**两种都是假信号**。

票 19 按写域约束没有动它（样本 `.scratch/deploy-acceptance` 不在仓库里，只在主树）。

## 1. 交付物

1. 把 `NINE` 升为**十键**口径，并把 `flags` 纳入断言（含"只有估算行时 `flags` 含 `unverified`"这一条）
2. 重导一份**与当前信封一致**的部署态样本（放回 `.scratch/deploy-acceptance`，或明确改为从生产接口现取）
3. 若样本注定不入库，就把脚本改成**从接口现取**、并写清取数前置（哪一个端点、什么状态）

## 2. 验收

- [ ] 部署态验收在**当前**信封上跑通，且失败项与基线逐条同名
- [ ] 把 `flags` 从断言里去掉会**变红**（防"少校验也算过"）
- [ ] 样本来源写清（入库 or 现取），不含凭据

## 3. 不做什么

- 不改接口信封（十键是票 26 的既定交付）
- 不把样本（可能含生产数据）提交进仓库

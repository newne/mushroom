## 0. 问题定义（Chief 2026-10-14 复核发现，先写清楚再谈做法）

Chief 用真机帧独立跑 `estimate_cluster` 得到 **`cluster_w_mm = 2375.24`（2.4 米）**、
`cluster_h_mm = 880.0`、`scale_note` 交叉差 42%。

**两个问题（都已定位，代码已修但仍需在方案里立住口径）**：

1. **"菌簇"被算成整帧跨度**：旧 `estimate_cluster` 用 `max(x1)-min(x0)` over **全部实例**，
   21 袋 482 实例横跨画面 ⇒ 2.4 m 必然。用户要的是**一袋一簇**。
   → 口径：**簇 = 同一菌包上的实例集合**；行值 = 各可靠簇的**均值**；`n` 是**朵数**，
   簇数/袋数进 `note`（20 列里没有簇数列）。
2. **"交叉校验 42%"是代码造的常数**：旧实现两向都用**袋宽**当分母 ⇒ `mpp_y/mpp_x ≡ 140/240 = 42%`，
   **不含任何信息**。修好后用**袋宽 vs 袋高**实测，得到**真**交叉差：

| 218 帧实测 | 值 |
| --- | --- |
| 袋宽中位 | **334 px** |
| **真**交叉差（240/袋宽 vs 140/袋高） | **中位 38.6%**（p10 29.1% / p90 48.2% / 16.3–69.2%） |
| >30% 的帧 | **191/218** |
| <10% 的帧 | **0/218** |
| 反推袋高（`h = 0.5833·w/(1−Δ)`） | **≈320 px ⇒ 袋高/袋宽 = 0.96** |

⇒ **结论（本方案的核心判断）**：袋宽 334 px 对应 240 mm 时，140 mm 应约 **195 px**；
实测袋高 **320 px** ⇒ L1 的"袋高"被**抬高约 1.6×**（相邻袋/袋肩/粘连被并进同一个连通域）。
**竖直参考物（袋高）当前不可用作独立标尺**；因此**竖直 mm 现在偏小约 1.6 倍**。

## 3. 算法与数据结构（要批的就是这一节）

### 3.1 L1 菌包实例与"一袋一簇"的归属

- L1：`find_bags()`（Otsu → 形态学 → 距离变换拆分）在**全帧 `ds=2`** 上跑；
- **归属规则**（`cluster_by_bag`）：实例 → `nearest_bag_in_same_row(cy, x)`，
  **同排判定用深度带 `row_band_px`（不是 y 容差）**，水平取最近袋；
  **找不到同排袋 ⇒ 该实例不归属**（fail-closed，**不跨袋借**）；
- 数据结构：`list[(BagRegion, list[FruitInstance])]`；**`estimate` 与 `l3` 共用这一份实现**（禁止各写一套）。

### 3.2 L2 ROI

袋肩带 = 画面**下 45%**（`roi_frac`）；L3 只在这个带里跑。理由：菇长在袋肩，整帧跑是浪费且引入货架底面噪声。

### 3.3 L3 菇体实例

`find_fruitbodies()`（top-hat → 自适应阈值 mean+2σ → 连通域 + 峰值 NMS）在 ROI 上、`ds=2`；
再 `filter_above_bag_top()`（实例底端须在所属袋袋顶线 +10 px 以上）——**袋肩门**。

### 3.4 尺度：**一期只用水平标尺定一个各向同性的 mm/px**

| 方向 | 一期做法 | 理由 |
| --- | --- | --- |
| 水平 | **袋特征宽 px ↔ 240 mm** ⇒ `mm_per_px` | 唯一可辩护的参考物（§0 实测袋宽 334 px，逐袋散布 Δw/w 中位 31%） |
| 竖直 | **用同一个 `mm_per_px`**（各向同性像素），只做 **÷cosθ** 投影补偿 | 相机像素是方的；"两个方向各用不同参考物"要求**两个参考物都可信**，而袋高实测被抬高 1.6×（§0）⇒ 用它只会把 1.6× 的偏差灌进竖直列 |
| 袋高 ↔ 140 mm | **降级为旁证/异常检测**（不进 mm 换算） | 它的偏离量正好当"袋检测是否粘连"的探针 |

**"42% 交叉差"的处理（用户/Chief 明确要答案）**：
① 旧 42% 是**代码常数**，已修（不再引用它作证据）；
② 修后的**真**交叉差 **38.6%（中位）**是**袋高不可信**的证据，不是"透视问题"的证据；
③ **一期不在产品里报两方向差**（那会把一个已知坏掉的参考物带进数字），
   只在**离线评估脚本**里继续算它，作为"袋检测质量"的探针。

### 3.5 复杂度 / 分辨率

| 项 | 口径 | 依据 |
| --- | --- | --- |
| 测量输入分辨率 | **2880×1616**（全池一致） | 现场实测 |
| 分割工作分辨率 | **`ds=2`（1440×808）**，坐标乘回原图 | 全帧 `ds=1` ⇒ 分钟级 |
| ROI | 下 45% | L3 只在这里 |
| 三改红线（撤销即回分钟级） | C1 NMS 网格哈希 O(P)；C2 DT 只在袋级 bbox 且"够大才拆"；C3 ROI+`ds=2`、`fill_holes` 关 | 票 15 §8.1 |

### 3.6 每帧数据流

```
帧(2880×1616) → L1 find_bags(全帧,ds=2) → bags[]
              → ROI(下45%) → L3 find_fruitbodies(ds=2) → insts[]
              → filter_above_bag_top → kept[]
              → cluster_by_bag → [(bag, group)]
              → 逐袋：span_w/span_h px + mm_per_px（袋宽↔240mm）
              → 行：mean_cluster_w_mm=mean(span_w*mpp)、
                    mean_cluster_h_mm=mean(span_h*mpp)（θ 缺 ⇒ height_uncorrected）
                    + n=朵数、evidence 五列、quality
```

## 4. 边界与失败模式（各出什么码、写什么值）

| 情形 | `quality` | 值 | 备注 |
| --- | --- | --- | --- |
| 整帧只剩不可信的排（远排） | **`unreliable`** | mm 全 NULL | **不是** `no_detection`；218 帧实测 7 帧 |
| 零候选（真没找到东西） | **`no_detection`** + `no_scale` | 全 NULL | 刻意 fail-closed；实测 13 帧 |
| 低对比/太远但有候选 | `unreliable`（按排判） | NULL | L1 不许静默丢排（`weak_retry` 重试一次） |
| 相邻袋粘连、拆不开 | 该袋 `split_ok=False` ⇒ 该簇**不入统计**（或整排 `unreliable`） | NULL | 待定，见 §8 R4 |
| θ 缺失 | `no_theta`（+ `height_uncorrected`） | **横向照出 mm**；竖直出未补偿跨度 | 两者都**不算不可用** |
| 缺标尺（无袋/袋宽不可用） | `no_scale` | 五列证据 + mm 全 NULL，`scale_source='none'` | 不写 0 |
| 整帧无实例但袋在 | `no_detection`（或全排不可信 ⇒ `unreliable`） | NULL | 两条路必须可区分 |
| 内容可疑帧（跨站重复） | 跳过，不产行（`emit_empty` 时 `n=0` + `no_detection`+`low_confidence`） | NULL | 票 13-round-content-integrity |
| 近黑/过曝/失焦 | 帧质量门先拦（`no_light`/`overexposed`/`blurry`） | 不产行 | 标定默认 45.0 |

| **A 类** | 轮廓、尖端、基部**均可确认** | `height_valid=1`（两端可见）+ `truncated=0` + `occluded_frac=0` |
| **B 类** | **可见杆段**可确认，完整基部不可见 | `height_valid=0` + `reviewer_note`（可见段） |
| **C 类** | **无法可靠区分个体** | **`ignore=1`**（已有：不参与 P/R，但**行必须保留**） |

⇒ 票 21 的 schema **已经能表达这三类**；建议**再加一列 `stem_class ∈ {A,B,C}`**（标注 CSV，不是 DB 列）
让门槛统计可直接算——**属方案项，待批后再改**。
三个必须回答的歧义（用户第 4 点）**写进标注说明**：
① 只标可见部分（**不推测遮挡**）；② 一根杆被遮成两段 ⇒ **分别标 B 类**，不合并；
③ 只露尖端的目标 ⇒ **计数但不测量**（`height_valid=0`）。

### 10.4 路线 A–D（用户建议，本方案按"先验可分性、再上模型"排序）

| 路线 | 做法 | 我的评估（含本项目约束） |
| --- | --- | --- |
| **A 提示式分割（SAM 2.1）** | 前排菌包逐包裁剪 + 人工提示点 → 看是否沿**单杆**边界分割 | **优先级最高**：它区分"图像信息不足"与"自动定位能力不足"；**但需 GPU/torch 运行时**（现场机只有 numpy+Pillow）⇒ 只能在**离线/服务器**跑 |
| **B 专用单杆实例分割（YOLO26-seg）** | 前排 ROI → 单包裁剪 → 实例分割 → 质检 | 需**训练数据**（当前 0）⇒ **必须等 §10.5 阶段 1 门槛**；类别先只做"可见菌杆" |
| **C 实例分割 + 尖端/基部关键点 + 中心线** | 输出掩码 + 尖端 + 可见基部 + "基部是否遮挡" + "测量是否有效" | **这才是"杆长测量"的路线**；弯曲杆不宜用上下端直线距离（用户原话） |
| **D 改善采集/多视角/深度** | 同袋对照采集（现有视角 / 更近 / 侧向 / 补光曝光） | 用户列为"当人工也分不清时"的路线；**但取景/换角那条线此前被冻结** ⇒ **需用户/Chief 明确是否解冻**（见 §10.6 决策 2） |

### 10.5 四阶段门槛（用户建议，采纳为**准入条件**）

| 阶段 | 做什么 | 通过门槛 | 我方投入 |
| --- | --- | --- | --- |
| **1 人工可辨认性基准** | **20–30 张真实局部图**，两名标注者**独立**标注 A/B/C | **A、B 类标注一致性足够**；若大量是 C 类 ⇒ **先改采集，不训练** | 工单可复用票 21 的复核页；需新增 A/B/C 与"两标注者"字段 |
| **2 真实模型基线** | 并行：提示式分割（验证可分性）+ 专用实例分割（验证自动化） | 只用真实原图 + 人工确认标签；**测试集按菌包/批次/采集条件隔离** | **需新运行时（GPU）**；训练规模与归属要定 |
| **3 验证测量（不只验证掩码）** | 指标：**实例召回率 / 合并率 / 拆分率 / 有效测量率 / 长度误差 / 重复拍摄稳定性** | **必须同时报误差与有效测量率**（只挑最清晰杆得低误差 ≠ 整包可靠） | 需 A/B/C 与关键点字段 |
| **4 生长监测** | 每包**可测杆长分布 + 有效样本数**；再做**同一根杆**的跨日关联 | 注意两个偏差：**外围杆不代表整包**；**今天与明天的均值变化不是同一批杆** ⇒ 群体统计与单体曲线**分开呈现** | 复用票 15 §13.5 的"相对趋势"纪律 |

### 10.6 因这条方向而**新增**要裁的决策

1. **交付定义**：是否把一期交付量从"袋级菌簇长度/直径"改为**"前排可辨认单杆的可见段二维投影长度"**？
   （我的建议：**两者并存、名字分开**——簇级保留为"范围粗口径"、单杆为新目标，**都不叫杆长**。）
2. **取景线是否解冻**：路线 D（单包近景/侧向/补光对照采集）需要动采集；此前"取景/换角"被冻结。
   **要用户一句话**：是否允许先做"同一菌包对照采集"这种**最小改动**（不加机械、只改机位/补光）？
3. **运行时与归属**：路线 A/B/C 都需要 **GPU/torch**（现场机只有 numpy+Pillow）。
   在哪跑（服务器离线批？）、谁维护、是否允许引入新依赖？
4. **训练门槛**：是否同意"**阶段 1 一致性不过就不训练**"（用户原话：若大量 C 类，先改采集）？
5. **标注扩展**：是否允许在**标注 CSV**（不是 DB）加 `stem_class ∈ {A,B,C}` 与 `annotator`（两名标注者）两列？
6. **本方案的审批范围**：§10 属于**新目标**，是否与 §1–§9 的"簇级链路"**分批批准**（簇级先跑通、单杆另批）？

### 10.7 我**不做**的（用户方向里明确排除的）

- **不把"每根菌杆完整测量"写进交付承诺**（用户原话：目前不宜）；
- **不补画遮挡部分**、不把推测值混进实测值；
- **不在阶段 1 门槛前训练模型**（不投 300 帧、不做大模型）；
- **不先投入完整三维重建**（用户原话）；
- **不把群体均值变化当单体增长**（阶段 4 的两个偏差）。

# 08. 页面错误态：显示上游 4xx 的原因（别把参数错误说成"不可达"）

Status: implemented（2026-10-16；验收逐条核过，提交 3e4725c）
归属：前端
依据：票 07 §已知边界 3；票 02 交付的页面取数路径
依赖：03（**同一文件 web/console/index.html**）

## 问题

页面取数用 `jget`：**见非 2xx 就抛，不读 body**。于是上游（analysis）回的 400 到了页面上只剩：

> 查不到覆盖轨迹 ⚠ 覆盖轨迹接口**不可达**：… HTTP 400

状态码是如实的，但**把"客户端请求有问题"说成了"连通性错误"**，而且真正的原因（`detail`/`notes`）被丢掉了。
票 07 已经保证**状态码与信封原样透传**（400 就是 400、错误体一字不改）——所以原因就在手里，是页面没读。

## 交付物

1. `jget` 在非 2xx 时**读 body**，把其中的原因（`detail` / `notes` / `error`）显示出来
2. 文案区分两类：**请求有问题（4xx）** vs **连不上 / 服务异常（5xx 与网络故障）**——现在两种都叫"不可达"
3. 无头回归补断言

## 验收（缺一条不算过）

- [x] 上游 **400** 时页面显示**上游给的原因**，不是笼统的"接口不可达"
- [x] **4xx 与 5xx/网络故障的文案分得开**（把 4xx 也说成"不可达" ⇒ 断言变红）
- [x] body 为空或非 JSON 时退化成现有文案，**不抛异常、不显示 `undefined`**
- [x] 零新前端依赖

## 不做什么

- 不改 BFF（票 07 已交付原样透传）
- 不改 `/timeline` 的契约

## 4. 实现与验证（Lead 补记）

提交 `3e4725c`，分支 `feat/tl-08`。两个文件：

| 文件 | 内容 |
| --- | --- |
| `web/console/index.html` | `jget` 非 2xx 时**读 body**：`errorReason(r)` 认 `detail`/`error`/`notes`（字符串/数组/数字都认），挂到 `error.detail`；error 另带 `status`/`url`。`requestErrorText()` 分两类：**4xx** =「请求有问题（HTTP n）：<上游原因>」、**5xx** =「接口不可达（HTTP n）：…」、无状态码的网络故障与超时保持原话术。**12 处 `jget` 的 catch 全部收进这一个口子**，删掉各自硬拼的「…接口不可达」 |
| `docs/patrol/console-ui/verify-page.js` | +5 断言：上游 400 显示原因且**不许出现「不可达」**；上游 502 归到「不可达」且**不许出现「请求有问题」**；两类词互斥；**非 JSON body**（nginx HTML 错误页）退化成状态行、无 `undefined`/`[object Object]`；**空 body** 同上 |

**实测**：前端回归基线 516/525 → **521/530，运行期错误：无**（Lead 在集成分支复跑同数），9 条既有失败逐条同名。
**护栏自证**：把 4xx 说回"不可达" ⇒ 518/530（①③⑤ 红）；把 5xx 也说成"请求有问题" ⇒ 519/530（②③ 红）；**body 读回来但直接拼 ⇒ 518/530（②④⑤ 红，卡上真的出现 `…：undefined`/`…：null`）**——最后这条证明"修好了读 body、却把错误对象直接拼进文案"这个退化会被抓住。
